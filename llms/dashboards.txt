### Install a dashboard template with the shadcn registry

Each template is a registry item, and its sample data is a second item named analytics-demo-<name> that also installs the dashboard. Run the add command with the demo item, for example the SaaS one, and the shadcn CLI copies the dashboard, the dashboard kit, the charts it uses and the sample data into components/sheenui/:

```bash
npx shadcn@latest add https://lokendra-builds.github.io/sheenui/r/analytics-demo-saas.json
```

For production, where load returns your own data, install the component only: analytics-saas instead of analytics-demo-saas. Your app needs React 19.2 and Tailwind CSS v4; the [Tailwind v4 glass UI setup](https://lokendra-builds.github.io/sheenui/docs/tailwind-v4) covers the two CSS imports, and the [installation page](https://lokendra-builds.github.io/sheenui/docs/installation) lists the rest.


### Swap the demo data for your own

A template ships with no data. You pass load, a function that gets the date range, the active filters and an abort signal and returns the object in the table above, synchronously or as a promise. The demos use saasRevenueDemoLoader from @sheenui/theme/demo-data; replace it with a function that calls your API and maps the response to the same fields:

```tsx
import { SaasRevenueDashboard } from "@/components/sheenui/blocks/analytics-saas";

export function Revenue() {
  return (
    <SaasRevenueDashboard
      currency="EUR"
      locale="de-DE"
      load={async ({ range, signal }) => {
        const res = await fetch(`/api/revenue?range=${range}`, { signal });
        return res.json(); // { points, kpis, movement, cohorts, customers, ... }
      }}
    />
  );
}
```

Money and dates go through Intl from the locale and currency props, every string is in a labels object, and the live ticker (liveStep) is optional: leave it out for a static report. The [chart gallery](https://lokendra-builds.github.io/sheenui/charts/) shows what each chart takes if you want to build a screen of your own from the same pieces.


### About dashboards

#### Overview

A glassy dashboard, or glassmorphism dashboard, puts KPI tiles, charts and filters on frosted panels over a soft background, and it only works when contrast, density and speed stay under control. The 5 React dashboard templates below do that work for you: each is a full page you can copy, with animated charts, sparklines, date filters and a table view for every chart.

Pick the one closest to your product. [Web analytics](https://lokendra-builds.github.io/sheenui/dashboards/web-analytics) shows traffic, sources and a live visitor count; [SaaS revenue](https://lokendra-builds.github.io/sheenui/dashboards/saas) follows MRR, churn and plans; [e-commerce](https://lokendra-builds.github.io/sheenui/dashboards/ecommerce) tracks orders and conversion; [product analytics](https://lokendra-builds.github.io/sheenui/dashboards/product) adds funnels and cohorts; and the [crypto dashboard](https://lokendra-builds.github.io/sheenui/dashboards/crypto-dashboard) has candlesticks and a streaming price.

The charts come from the [animated React charts gallery](https://lokendra-builds.github.io/sheenui/charts/), where you can read about each type, and the surrounding parts from the [glass UI components](https://lokendra-builds.github.io/sheenui/components/). For smaller pieces, see the [dashboard stat cards](https://lokendra-builds.github.io/sheenui/blocks/dashboard-stats). Dashboards draw many surfaces at once, so read [backdrop-filter performance](https://lokendra-builds.github.io/sheenui/guides/backdrop-filter-performance) to keep them fast, and [accessible React charts](https://lokendra-builds.github.io/sheenui/guides/accessible-react-charts) for the reading model.

Each template is one component with a required load prop: a function (sync or async) that receives the date range and the active filters and returns the numbers and rows to draw. The templates ship no data of their own; the demo loaders in @sheenui/theme/demo-data are only for trying them out. Header controls (range, Live, Compare) are props too, so you can control them from your router or a store. Every label is in a labels object and every number goes through Intl, so a dashboard in another language or currency needs props, not edits.

Want a whole admin app around a dashboard? The [Glass Admin starter template](https://lokendra-builds.github.io/sheenui/docs/installation#starter-template) (Vite or Next.js) wires the SaaS revenue dashboard into an app shell with a customers table, settings and sign-in.

#### Frequently asked questions

#### Are these dashboard templates really free?

Yes. SheenUI is MIT licensed, so you can use the dashboards in personal and commercial projects.

#### What do the dashboards use for charts?

SheenUI's own animated React charts: line, area, bar, donut, funnel, heatmap and more, each with keyboard reading and a table view.

#### Is the data real?

No. The numbers are deterministic demo data, so the screens look the same every time. Replace the arrays with your own API.

#### How do I connect my own data to a dashboard?

Pass the required load prop, a function that returns the data for the current date range and filters, synchronously or as a promise. The demo loaders in @sheenui/theme/demo-data show the shape, and money and dates are formatted with Intl from the locale and currency props.

### Accessibility

- The dashboard is a labeled region (its title); panels are sections named by their headings; loading sets aria-busy and is announced once (“Loading new data…”, then “Dashboard updated”), never on every live tick.
- The KPI strip is a real tablist that controls the trend panel: “Unique visitors, tab, selected, 1 of 4”. Each delta reads in words (“Up 12.3% vs previous period”), with an arrow and a sign, so color is never the only signal.
- Rolling numbers are visual only: screen readers get the final value once. The online pill doesn't announce every change.
- Every chart has a Table view with the same numbers; charts are focusable and read point by point with the arrow keys (announced politely).
- Live and Compare are toggle buttons (aria-pressed) with descriptions; filter chips show a ✓ and are underlined in forced colors when pressed.
- Reduced motion: no draw-ins, glides, pulses or scans; numbers and charts jump to their values, fades stay short.

### Performance

- Charts below the fold mount when they come within 320px of the viewport; their frame is reserved first, so nothing shifts.
- New data lands in a React transition, one panel per frame: visible panels ripple in order, panels off-screen catch up in idle time or when you scroll to them.
- Controls answer instantly (optimistic state) while the dashboard re-renders in the background, so a click never blocks the next frame.
- Loading dims the panels through a data attribute (CSS only): starting or finishing a load re-renders no chart.
- Glass budget: the header, the KPI strip and at most two panels per row blur what's behind them; controls inside the header don't add their own blur. Phones get a lighter blur.
- Live updates, the realtime stream and every pulse stop while the dashboard is off-screen or the tab is hidden. Only transform and opacity animate.

### When to use the web analytics dashboard

- Use it for the traffic or site-stats screen of a SaaS app, where a strip of KPI tiles (visitors, pageviews, bounce rate, visit duration) sits above the charts that explain them.
- Use it for a client-facing site report where the trend chart shows the previous period dashed, a realtime panel streams the current visitors and active pages, while top pages, referrers, devices and a country map sit below.
- Connect it to your own API through load, which receives the range, the active filters and an abort signal, then set locale and labels to translate every number and string.
- Skip it when you need funnels and retention, or revenue figures: ProductDashboard covers user journeys and cohorts, and SaasRevenueDashboard handles MRR and churn, so pick the block that matches your data.
- Pair it with SegmentedControl for your own filters beside it, Switch for toggles in surrounding settings, and useAnalyticsDashboard if you build a custom dashboard from the same kit.


### Frequently asked questions

#### How do I use this web analytics dashboard template with my own data?

Pass load to WebAnalyticsDashboard. It receives the range, the active filters and an abort signal, and returns a WebAnalyticsData object, synchronously or as a promise: points, totals, pages, referrers, countries, devices, browsers and realtime. There is no fake data fallback; demo loaders live in the demo-data export.

#### What props control the header, filters and live mode?

site sets the title, ranges and filters set the range options and channel chips, and range, defaultRange and onRangeChange control the time range. Live and Compare use live, compare and their defaults and callbacks. liveStep evolves data each tick, and onExport replaces the CSV download.

#### Is the dashboard accessible to keyboard and screen reader users?

It is a labeled region, and a polite live region announces loading and updates, but never live ticks. Charts are single tab stops read with arrow keys, and the main charts have a table view behind a Chart and Table switch. Change badges carry arrows and signed numbers, not color alone.

#### How does it behave while loading, on errors and with reduced motion?

The frame stays while skeletons hold each panel on first load, later loads keep the old data on screen, dimmed under a thin scan line, and empty or failed loads say so in words, with Retry when the loader threw. Reduced motion removes rolling digits, draw-in and panel rise.

- Use it for the finance or growth screen of a subscription product, where MRR, ARR, churn rate and ARPU roll up as headline numbers with deltas and a sparkline beside each.
- Use it for investor updates or an internal finance review, where MRR stacked by plan, the plan mix donut, an MRR movement waterfall and retention cohorts explain why revenue changed.
- Use currency, locale and labels to render a non-US dashboard, for example amounts in euros formatted German style with translated cohort columns.
- Skip it when you need traffic or conversion data: WebAnalyticsDashboard covers visitors and sources, and EcommerceDashboard covers orders and checkout, so use this one only for subscription metrics.
- Pair it with DonutChart and WaterfallChart for custom panels, SegmentedControl for switching views, and AnalyticsShell with AnalyticsPanel when you adapt the layout.


### Frequently asked questions

#### How do I build a SaaS dashboard in React with SheenUI?

Render SaasRevenueDashboard with a load function that returns SaasRevenueData: MRR by plan per point, kpis, trends, movement, cohorts and customers. product sets the title and currency the ISO code. The default ranges are 7d, 30d, 90d and 12m, since MRR is a slow metric.

#### What does the MRR movement waterfall show?

It breaks the change in MRR over the range into a starting amount plus new business, expansion, reactivation, contraction and churn, so you can see which movement drove the change. Churn is passed as a monthly ratio, while MRR, ARR and ARPU are in currency units.

#### How do region filters and the customer table work?

Pass filters as region chips; their values reach load as filters, so your API returns the matching data. defaultFilters starts with one region on. The top-customers table is sortable by MRR, seats, change or tenure, and each chart has a table view.

#### Can I translate it or change the headline numbers?

Yes, through the labels prop, a Partial of SaasRevenueLabels that covers every string including cohort columns. locale formats numbers and dates through Intl, and onExport replaces the default CSV of MRR by plan. headingLevel sets the heading level.

### Performance

- Charts below the fold mount when they come within 320px of the viewport; their frame is reserved first, so nothing shifts.
- New data lands in a React transition, one panel per frame: visible panels ripple in order, panels off-screen catch up in idle time or when you scroll to them.
- Controls answer instantly (optimistic state) while the dashboard re-renders in the background, so a click never blocks the next frame.
- Loading dims the panels through a data attribute (CSS only): starting or finishing a load re-renders no chart.
- Glass budget: the header, the KPI strip and at most two panels per row blur what's behind them; controls inside the header don't add their own blur. Phones get a lighter blur.
- Live updates, the realtime stream and every pulse stop while the dashboard is off-screen or the tab is hidden. Only transform and opacity animate.

### Frequently asked questions

#### How do I build an ecommerce dashboard in React with this block?

Render EcommerceDashboard with load returning EcommerceData: points with revenue and orders, kpis, trends, funnel, categories, an hour-by-weekday heatmap and top products. store sets the title, currency the ISO code, and defaultRange the first range.

#### What does Compare do on the revenue chart?

With Compare on, last period's revenue is drawn as a dashed line on the same axis as the bars, and KPIs show previous values. With it off, the line is a moving average. Points can carry previousRevenue for that comparison.

#### How do I handle live orders and exports?

Pass liveStep to evolve the data on each tick; the Live toggle pauses it, and updates stop off screen and in hidden tabs. Export downloads a CSV of revenue and orders unless you pass onExport. range can be controlled with onRangeChange.

#### Is every chart readable without a mouse or color?

Most panels switch between the chart and a data table. Each chart is one tab stop whose arrow keys read its points, and the treemap has a breadcrumb for zoom levels. Reduced motion removes draw-in and rolling digits, and reduced transparency makes the glass solid.

### Accessibility

- The dashboard is a labeled region; a polite live region says “Loading new data…” and “Dashboard updated” when you change the range or filters, and “CSV downloaded” after an export (never on live ticks).
- Every chart has a table view behind its Chart / Table tabs, so every value can be read without color or a pointer.
- Change badges carry an arrow and a signed number, and a screen-reader sentence (“Up 12.4% vs previous period”); green never stands alone.
- Rolling numbers are visual only: the final value is in the text for assistive tech, and live ticks are not announced (no chatter every two seconds).
- Live updates stop on their own off-screen and in background tabs; the Live toggle is the pause control (WCAG 2.2.2).
- Reduced motion: no rolling, no draw-in, no panel rise; values and data changes appear at once (short fades only).
- Filter chips, Live and Compare are toggle buttons (aria-pressed) with a check mark or dot when on; every control has a 44px hit area on touch screens.

### Performance

- Glass budget: only the header, the KPI strip, the cards and one tooltip blur what is behind them; controls inside them drop their own blur.
- Charts below the fold mount only when they come near the viewport; live updates and loops pause off-screen and in hidden tabs.
- New data reaches the cards one after another, inside React transitions, so no single task re-renders every chart. Live ticks re-render the KPI strip only.

### Frequently asked questions

#### How do I use this product analytics dashboard with my data?

Pass load to ProductDashboard; it is required, and receives range, platforms, now and locale, and returns ProductData: dau, wau, mau, flow, funnel, adoption, cohorts, events and eventsPerMinute. Demo loaders and liveStep helpers come from the demo-data export.

#### How do filters, live mode and keyboard control work?

The range control moves with the arrow keys, and platform chips toggle with Space or Enter, then Live, Compare and Export. Inside a chart, arrow keys read points and Escape clears the reading. Live pauses off screen and in background tabs, and liveInterval defaults to 2000 ms.

The load function can return data or a promise. The first load shows skeletons, later loads keep old data under a veil, and an empty or failed load shows a message, with Retry after a thrown error. The glass prop auto-falls back to solid cards on weak devices.
