URL: https://lokendra-builds.github.io/sheenui/effects/word-rotate

### Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| words | readonly string[] | required | The words to cycle through, in order. |
| interval | number | 2.6 | Seconds each word stays. |
| direction | "up" \| "down" | "up" | Which way words travel: "up" (in from below, default) or "down" (in from above). |
| align | "center" \| "end" \| "start" | "start" | Where a shorter word sits in the slot (the slot is as wide as the longest word). |
| paused | boolean | false | Stop cycling (e.g. from a pause button). |
| pauseOnHover | boolean | true | Pause while a mouse or pen rests on the words. |
| index | number | optional, no default | Controlled index of the word shown. |
| defaultIndex | number | 0 | Sets the index shown first when uncontrolled. |
| onIndexChange | ((index: number) => void) | optional, no default | Called with the index of each new word. |
| label | string | optional, no default | What screen readers hear instead of the list of words. |
| locales | Intl.LocalesArgument | optional, no default | Locale(s) for the default list label (Intl.ListFormat). |
| wordClassName | string | optional, no default | Classes for each word (padding, gradient text). Put a highlight's padding here. |
| highlightClassName | string | optional, no default | Classes for a highlight behind the current word (e.g. "rounded-sheen-md bg-sheen-accent-soft"). It morphs to fit each word. |

### Example 1 of 2: In a headline

highlightClassName draws a pill behind the current word: watch it morph between short and long words (transforms only, corners stay round). Padding goes in wordClassName so the pill and the word line up. Rest the pointer on it, or use the switch, to pause.

```tsx
import { useState } from "react";
import { Switch } from "@/components/sheenui/switch/switch";
import { WordRotate } from "@/components/sheenui/text-effects/word-rotate";
// Package build (after the first npm release, or a packed tarball): import { Switch, WordRotate } from "@sheenui/theme";

export function Example() {
  const [paused, setPaused] = useState(false);

  return (
    <>
      <Switch label="Pause" checked={paused} onCheckedChange={setPaused} />
      <p className="text-center text-4xl leading-tight font-semibold tracking-tight text-balance sm:text-5xl">
        Built for{" "}
        <WordRotate
          words={["designers", "developers", "founders", "everyone"]}
          paused={paused}
          className="text-sheen-accent"
          wordClassName="px-3"
          highlightClassName="rounded-sheen-md bg-sheen-accent-soft"
        />
      </p>
    </>
  );
}
```

### Accessibility

- Screen readers get the words once, as plain text (override it with label); the rotating word is not re-announced every few seconds.
- Under reduced motion it stays on the current word.

### When to use the word rotate effect

- Use it as a word rotate animation for one changing word in a headline, such as Design for designers, developers and everyone, where each word slides in from below as the last slides out the top. Use it as a text loop in React that cycles through a few phrases inside one headline.
- Use it for a feature tagline in a product page that lists audiences or use cases, with highlightClassName adding a pill behind the current word that morphs to fit each one. It is a quiet way to flip words in a headline without moving the layout under the text.
- Use controlled index with onIndexChange when other UI, like tabs or an illustration, should follow the word that is currently shown.
- Skip it when you need whole phrases typed out: Typewriter fits that, and a static sentence fits better when the words are important content, since users may not wait for every one.
- Pair it with BlurIn for the rest of the headline, Button for the action, and a Switch or your own button that sets paused so people can stop the cycling.


### Frequently asked questions

#### How do I make rotating text in React with WordRotate?

Put WordRotate inside your heading and pass words in order. interval is seconds per word (default 2.6), direction is up or down, and align places a shorter word in the slot. Use defaultIndex to choose the first word when uncontrolled.

#### Will the sentence reflow as the words change?

No. The slot is as wide as the longest word from the first paint, so the text around it never reflows or jumps while a word is in flight. The clipped window uses clip-path as well as overflow, so words in flight are clipped too.

#### How do screen readers and keyboard users experience it?

Screen readers hear every word once as a list, such as designers, developers, and everyone, not a stream of changes. Override that with label, and set the list language with locales. It has no keyboard interaction, because it is text.

#### Can visitors pause it, and what about reduced motion?

It pauses while off screen, while the tab is hidden and while a mouse or pen rests on it, with pauseOnHover turning the last one off. paused stops it from outside, for WCAG 2.2.2. With reduced motion it stays on the current word, static.

### Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| containerRef | RefObject<HTMLElement \| null> | required | The positioned element that holds both ends (the beam fills it). Pass the same ref you put on that element. |
| fromRef | RefObject<HTMLElement \| null> | required | Element the beam leaves from. Must be inside containerRef's element. |
| toRef | RefObject<HTMLElement \| null> | required | Element the beam arrives at. Must be inside containerRef's element. |
| curvature | number | 0 | Bend of the path in px, measured sideways from the straight line between the two elements. Positive bends to the left of the direction of travel; 0 draws a straight line. |
| reverse | boolean | false | Run from toRef to fromRef instead. |
| duration | number | 2.4 | Seconds one pass of the beam takes from one end to the other. |
| interval | number | 1.2 | Seconds the path rests, empty, between two passes. |
| delay | number | 0 | Seconds before the first pass (lets several beams in one diagram run out of step). |
| length | number | 96 | Length of the travelling light in px, measured along the path. |
| thickness | number | 2.5 | Thickness of the light and of the track in px. |
| gap | number | 6 | Gap in px kept between the path and the edge of each element. |
| colorFrom | string | "var(--sheen-accent)" | Colour at the tail of the light, any CSS colour. |
| colorTo | string | "var(--sheen-accent-2)" | Colour at the bright head of the light, any CSS colour. |
| track | boolean | true | Draw the faint static track under the light, so the connection reads even between passes. |
| fromOffset | BeamOffset | optional, no default | Nudges where the beam leaves fromRef, in px from its centre. |
| toOffset | BeamOffset | optional, no default | Nudges where the beam arrives at toRef, in px from its centre. |
| paused | boolean | false | Hold the light where it is (it carries on from there when unpaused). |
| className | string | optional, no default | Adds extra classes to the overlay. |
| style | CSSProperties | optional, no default | Applies an inline style to the overlay. |

### Example 1 of 2: Integration diagram

Three sources feed one hub. Each beam is staggered with delay and bent with curvature, so the network reads as alive without any one beam competing. The beam is decorative (aria-hidden), so say what is connected in the labels.

```tsx
import { useRef, useState } from "react";
import { AnimatedBeam } from "@/components/sheenui/animated-beam/animated-beam";
import { GlassCard } from "@/components/sheenui/glass-card/glass-card";
import { Switch } from "@/components/sheenui/switch/switch";
// Package build (after the first npm release, or a packed tarball): import { AnimatedBeam, GlassCard, Switch } from "@sheenui/theme";

export function Example() {
  const [paused, setPaused] = useState(false);
  const container = useRef<HTMLDivElement>(null);
  const a = useRef<HTMLDivElement>(null);
  const b = useRef<HTMLDivElement>(null);
  const c = useRef<HTMLDivElement>(null);
  const hub = useRef<HTMLDivElement>(null);

  return (
    <>
      <Switch label="Pause beams" checked={paused} onCheckedChange={setPaused} />
      <div ref={container} className="relative flex w-full max-w-md items-center justify-between py-6">
        <div className="flex flex-col gap-8">
          <GlassCard ref={a} className="grid size-16 place-items-center text-sm font-semibold">Billing</GlassCard>
          <GlassCard ref={b} className="grid size-16 place-items-center text-sm font-semibold">Chat</GlassCard>
          <GlassCard ref={c} className="grid size-16 place-items-center text-sm font-semibold">Docs</GlassCard>
        </div>
        <GlassCard ref={hub} tint className="grid size-24 place-items-center font-semibold">Your app</GlassCard>
        <AnimatedBeam containerRef={container} fromRef={a} toRef={hub} curvature={-40} paused={paused} />
        <AnimatedBeam containerRef={container} fromRef={b} toRef={hub} delay={0.8} paused={paused} />
        <AnimatedBeam containerRef={container} fromRef={c} toRef={hub} curvature={40} delay={1.6} paused={paused} />
      </div>
    </>
  );
}
```

### Accessibility

- Decorative: the overlay is aria-hidden. The connection must also be in text (a label, a heading or a sentence), because the picture is invisible to assistive technology.
- paused holds the light where it is, so a page can offer a stop control (WCAG 2.2.2). It also rests off-screen and in hidden tabs.
- Under reduced motion there is no light, only the faint still track between the elements.
- The light is one element moved by transform and faded by opacity along positions sampled from the real path; nothing blurs, masks or filters the glass nodes.

### When to use the animated beam effect

- Use it in an integration diagram: a source card, your product in the middle and a destination, with a light running along the connection to show data flowing.
- Use it in a "connected to" section or an architecture map, with several beams staggered by delay so the network feels alive without any of them competing.
- Bend a path with curvature to route around a centre node, or reverse it for a response going back; the beam leaves from the edge of each element, not its centre.
- Skip it when the relationship is the point of the content and nothing else says so; the beam is aria-hidden, so name the connection in text as well.
- Pair it with GlassCard nodes, Badge labels on the nodes, and a Switch wired to the paused prop for a stop control.


### Frequently asked questions

#### How do I draw an animated beam between two elements in React?

Put the elements and the AnimatedBeam in one relative container, then pass containerRef, fromRef and toRef. It measures them, draws a track from edge to edge and sends a comet of light along it; curvature bends the path and reverse flips the direction.

#### Is it expensive to animate?

No. The light is one element moved by transform along positions sampled from the real path, and it fades by opacity, so nothing repaints per frame. It pauses off-screen and in hidden tabs.

#### How is it made accessible?

It is decorative and aria-hidden, and never takes pointer events. Describe the connection in text too. The paused prop holds the light so a page can offer a stop control, and reduced motion leaves only the still track.

#### Does the beam keep running off-screen?

No. It pauses when it scrolls out of view and in hidden tabs, so several beams on a long page cost nothing while unseen. Use delay to stagger the ones in view.

### Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| count | number | 120 | Sets how many pieces each burst draws. |
| maxCount | number | 200 | The most pieces a single burst ever draws, whatever count asks for. Halved on weak devices. |
| spread | number | 75 | Sets the width of the fan in degrees. |
| angle | number | 90 | Direction of the centre of the fan in degrees, counter-clockwise from pointing right. |
| velocity | number | 720 | Sets the launch speed in px per second. |
| colors | string[] | the accent, second accent, success, warning and danger tokens | Sets the colours of the pieces, any CSS colours. |
| badge | ReactNode | optional, no default | Shown instead of a burst when reduced motion is on, in a polite live region, so the moment is still marked (and announced). Without it a reduced-motion fire() does nothing. |
| badgeDuration | number | 2.6 | Seconds the badge stays up. |
| className | string | optional, no default | Adds extra classes to the badge wrapper (a fixed, centred strip near the top). |

### Example: Fire from a button

origin takes an element (the burst starts at its centre) or a point of the viewport. Never let confetti be the only sign of success: the text below changes too. With reduced motion the badge appears at the top of the screen instead.

```tsx
import { useState } from "react";
import { Button } from "@/components/sheenui/button/button";
import { Confetti, useConfetti } from "@/components/sheenui/confetti/confetti";
// Package build (after the first npm release, or a packed tarball): import { Button, Confetti, useConfetti } from "@sheenui/theme";

export function Example() {
  const { ref, fire } = useConfetti();
  const [done, setDone] = useState(0);

  return (
    <>
      <Button
        onClick={(event) => {
          setDone((n) => n + 1);
          fire({ origin: event.currentTarget, count: 140, spread: 100 });
        }}
      >
        Place order
      </Button>
      <p className="text-sm text-sheen-fg-muted">{done === 0 ? "Nothing placed yet." : "Orders placed: " + done}</p>
      <Confetti ref={ref} badge="Order placed" />
    </>
  );
}
```

### Keyboard

| Keys | Action |
| --- | --- |
| Tab | Not focusable: the canvas never takes pointer events, so the page stays usable during a burst. |

### Accessibility

- The canvas is decorative and aria-hidden. Always show text or a toast too; confetti is never the only sign of success.
- Reduced motion: fire() draws nothing. With the badge prop, a still message appears for badgeDuration seconds in a polite live region (role=status), so the moment is marked and announced.
- Nothing runs while idle. The loop exists only while pieces are in flight, then the canvas hides itself; a hidden tab ends the burst. Count is capped at 220 and halved on devices with little memory, few cores or Save-Data.
- The canvas lives in a portal on body, never inside a glass surface, so it cannot flatten any glass.

### When to use the confetti effect

- Use it for success moments: an order placed, a goal reached, an upload finished, fired from the handler that knows it worked.
- Fire from a button with origin set to that element so the burst starts where the user acted, or from a point of the viewport.
- Always show text or a toast as well; confetti is decoration and never the only sign of success.
- Skip it for routine actions, errors and anything repeated often; it should feel like an occasion.
- Pair it with Button, Toast and the badge prop, which shows a still message instead under reduced motion.


### Frequently asked questions

#### How do I fire confetti in React?

Call useConfetti(), render <Confetti ref={confetti.ref} /> once, and call confetti.fire({ origin }) from an event handler. Options set count, spread, angle, velocity and colors.

#### Does it cost anything while idle?

No. Nothing runs until fire() is called; the loop exists only while pieces are in flight, the canvas then hides itself, and a hidden tab ends the burst. The piece count is capped at 220 and halved on weak devices.

#### What happens with reduced motion?

fire() draws nothing. If you pass badge, it appears for badgeDuration seconds in a polite live region so the moment is still marked and announced.

#### Can I change where it starts, how many pieces fall and which colors?

Yes. origin is an element (the burst starts at its centre) or a point of the viewport such as { x: 0.5, y: 0.5 }. count defaults to 120 and is capped by maxCount (200, halved on weak devices), and spread, angle, velocity and colors take any CSS colors. Options passed to fire() override the props for that one burst.

#### How do I stop a burst early?

Call confetti.clear(), for example when the route changes. It removes every piece at once.

```tsx
      <ScrollProgress placement="inline" container={scroller} label="Reading progress" />
      <div ref={scroller} className="h-72 overflow-y-auto p-6">
        <h2 className="text-lg font-semibold">A long read</h2>

}
```

### Accessibility

- Decision: decorative by default and aria-hidden, because browsers already show and announce scroll position and a role that changes on every scroll would be noise.
- Pass label only where the position carries meaning (a course, a long form): the bar becomes a progressbar with that name and a value that updates in 5 % steps, never on every pixel.
- Reduced motion: the bar still tracks the scroll exactly (a direct mapping, not an animation) but without the spring. In forced colors it uses the system highlight colour.
- The fill is a scaleX transform driven by the scroll position: no layout, no paint, no loop, so there is nothing to pause. It grows from the inline start in right-to-left pages.

### When to use the scroll progress effect

- Use it on long articles, docs and guides to show how far through the reader is, fixed to the top edge.
- Pass a container ref to follow a scrollable panel, or placement="inline" to put the bar inside your own header.
- Pass label only where position matters (a course or long form); the bar then becomes a progressbar updating in 5 % steps.
- Skip the label on ordinary pages; browsers already convey scroll position and a changing role would be noise.
- Pair it with TextReveal, a sticky header and Breadcrumb.


### Frequently asked questions

#### How do I add a scroll progress bar in React?

Render ScrollProgress anywhere; it fixes itself to the top and fills with the page scroll through a scaleX transform. Use container for a scrollable panel and placement for bottom or inline.

#### Is a scroll progress bar accessible?

By default it is decorative and aria-hidden. With label it is a named progressbar whose value changes in 5 % steps, so screen readers are not flooded. In forced colors it uses the system highlight.

#### Does it follow reduced motion?

The bar still tracks the scroll exactly, since that is a direct mapping, but without the easing spring.

#### How do I follow a panel instead of the whole page?

Pass the scrollable element as container, a ref such as useRef<HTMLDivElement>(null). placement can be top, bottom or inline: the first two fix the bar to the viewport edge, inline keeps it in the flow, for example in a card header. thickness sets the height in px (default 4).

#### When should the bar have an accessible name?

Only when the position carries meaning, such as a reading-progress bar in a course or a long form. Pass label and it becomes a progressbar whose value updates in 5% steps. Without label the bar is aria-hidden, because browsers already show and announce scroll position.

## Text Reveal on Scroll for React: Word by Word

URL: https://lokendra-builds.github.io/sheenui/effects/text-reveal
Sidebar name: Text reveal

A scroll text reveal for React: words light up one by one with scroll progress. Real text, readable without JS, no layout shift, static for reduced motion.

What it is: TextReveal is a React effect that lights up the words of a statement one by one as you scroll. The text stays real, readable without JavaScript, never shifts layout and is fully visible under reduced motion.

### Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| children | string | required | The text to reveal, as one plain string. Words are split on whitespace. |
| as | TextRevealTag | "p" | The element to render: a paragraph for running text, a heading for a statement. |
| dim | number | 0.28 | How dim a word is before the scroll reaches it, from 0 (invisible) to 1 (no effect). Keep it at 0.25 or above so the unread words stay legible. |
| offset | ScrollOffset | ["start 0.9", "end 0.5"] | Which part of the scroll drives the reveal, in Motion's offset format: ["start 0.9", "end 0.5"] starts when the top of the text reaches 90 % of the viewport height and finishes when its bottom reaches the middle. |
| container | RefObject<HTMLElement \| null> | the page | The scrollable element that drives the reveal. |

### Example 1 of 2: Scroll inside the panel

Pass container to follow a scrollable panel instead of the page. offset sets where the reveal starts and ends; here it begins as the text enters the panel and finishes at the middle. Scroll back and the words dim again.

```tsx
import { useRef } from "react";
import { TextReveal } from "@/components/sheenui/text-reveal/text-reveal";
// Package build (after the first npm release, or a packed tarball): import { TextReveal } from "@sheenui/theme";

export function Example() {
  const scroller = useRef<HTMLDivElement>(null);

  return (
    <div ref={scroller} role="region" aria-label="Manifesto" tabIndex={0} className="h-96 w-full overflow-y-auto p-8 focus-visible:outline-2 focus-visible:outline-sheen-focus">
      <div className="h-40" />
      <TextReveal
        as="h2"
        container={scroller}
        offset={["start 0.9", "end 0.5"]}
        className="text-3xl font-semibold tracking-tight text-balance"
      >
        We build interfaces that feel like light passing through glass: calm, precise and never in the way of the thing you came to do.
      </TextReveal>
      <div className="h-96" />
    </div>
  );
}
```

### Accessibility

- The words are real text with normal spaces, in order: selectable, searchable and read by screen readers whatever their opacity. Before hydration (or without JavaScript) every word is fully visible.
- Dimmed words are lower contrast until revealed: keep dim at 0.25 or above, and avoid the effect on text that must be read at once (instructions, legal copy).
- Use as="h2" only for a heading that belongs in the outline.
- Only opacity changes, driven by the scroll position through MotionValues: no layout shift, no React renders while scrolling, no loop to pause. Reduced motion shows every word at full opacity.

### When to use the text reveal effect

- Use it for a manifesto, mission line or long hero statement where the scroll sets the pace of reading.
- Use as="h2" for a heading statement, or leave it a paragraph; tune offset to start and finish the reveal where you want.
- Keep dim at 0.25 or above so unrevealed words stay legible.
- Skip it for instructions, legal copy or anything that must be read at once.
- Pair it with ScrollProgress for a reading cue and a calm background.


### Frequently asked questions

#### How do I reveal text on scroll in React?

Pass one string to TextReveal. Each word goes from dim to full opacity across its own slice of the scroll range, left to right, driven by the scroll position.

#### Is it readable without JavaScript?

Yes. The words are real text in the HTML and every word is fully visible until the page hydrates. Opacity is the only thing that changes, so the layout never shifts.

#### What does reduced motion do?

Every word is fully visible and nothing is scroll-linked.

#### Which props control how fast the words appear?

dim sets how faint a word is before the scroll reaches it (default 0.28; keep it at 0.25 or above so unread words stay legible). offset says which part of the scroll drives the reveal, in Motion's offset format, and defaults to ["start 0.9", "end 0.5"]: it starts when the top of the text reaches 90% of the viewport and ends when its bottom reaches the middle. container follows a scrollable panel instead of the page.

#### Should I use it for body copy?

No. Dimmed words have lower contrast until the reader reaches them, so keep it for a manifesto, a mission line or a long hero sentence. Avoid it on instructions and legal copy that must be read at once, and use as="h2" only for a heading that belongs in the outline.
