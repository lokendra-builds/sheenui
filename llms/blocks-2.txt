### Example 1 of 2: Four tiers

Switch between monthly and yearly: every digit rolls to its new value. Hover or focus the popular tier to keep its beam circling, then open the comparison table.

```tsx
import { Pricing } from "@/components/sheenui/blocks/pricing";
import { type PricingBilling } from "@/components/sheenui/blocks/pricing/model";
// Package build (after the first npm release, or a packed tarball): import { Pricing, type PricingBilling } from "@sheenui/theme";

// Your call: create a checkout session, then send the person to it
async function startCheckout(tierId: string, billing: PricingBilling) {
  const res = await fetch("/api/checkout", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ tier: tierId, billing }),
  });
  const { url } = (await res.json()) as { url: string };
  window.location.assign(url);
}

export function Example() {
  return (
    <Pricing
      title="Simple pricing, no surprises"
      description="Start free, upgrade when your team grows. Cancel any time."
      footnote="Prices in USD, excluding taxes."
      onSelect={(tier, billing) => startCheckout(tier.id, billing)}
    />
  );
}
```

### When to use the pricing section

- Use Pricing on the plans page of a subscription product to let visitors compare three tiers side by side, switch between monthly and yearly billing and see the popular plan stand out above a full feature table.
- Use it when buyers compare plans, since the Compare all features disclosure opens a feature table with column and row headers that scrolls horizontally on small screens.
- Use it for regional storefronts, setting currency and locale so prices such as euros or rupees are formatted correctly, with onSelect(tier, billing) sending the choice to checkout.
- Skip it when plans are priced per seat or by usage with a calculator; a form with a Slider and a live total communicates that better than fixed tier cards.
- Pair it with PaymentCheckout for the step after a plan is chosen, Badge for plan labels, and AuthSplit if the visitor must create an account first.


### Frequently asked questions

#### How do I make a React pricing table with a billing toggle?

Render Pricing with tiers and optionally features, then handle onSelect(tier, billing). The billing prop is controlled, defaultBilling starts at yearly, and onBillingChange reports the switch. The billing switch announces the saving. Set title, description and footnote for the surrounding copy.

#### Are the animated prices accessible?

Yes in practice: the price is real text with its period, so screen readers read it normally. Visually, prices roll like an odometer when they appear and when billing changes. With reduced motion there is no movement and the numbers switch immediately.

#### Does the highlighted plan's light beam loop forever?

No. The popular plan's light beam circles twice when it scrolls into view and then rests, which respects WCAG 2.2.2 on moving content. It keeps circling only while that card is hovered or has focus. Reduced motion removes the movement altogether.

#### How do I control the compare table and heading levels?

compareOpen, defaultCompareOpen (default false) and onCompareOpenChange control the disclosure. Tier names are headings one level below the title, and headingLevel defaults to 2, so adjust it to fit your page outline. The block renders as a labeled section.

### Example 1 of 2: Account settings

Edit anything: the save bar rises and counts your changes, and the nav shows where they are. Save (or press ⌘S / Ctrl+S), or Discard. The Appearance switches are the real SheenUI preferences and apply at once. Delete account asks you to type the username.

```tsx
import { SettingsPage } from "@/components/sheenui/blocks/settings-page";
import { type SettingsValues } from "@/components/sheenui/blocks/settings-page/model";
// Package build (after the first npm release, or a packed tarball): import { SettingsPage, type SettingsValues } from "@sheenui/theme";

// Your API; each call throws on failure so the page can show the error
async function call(path: string, method: string, body?: unknown) {
  const res = await fetch("/api/" + path, {
    method,
    headers: { "Content-Type": "application/json" },
    body: body === undefined ? undefined : JSON.stringify(body),
  });
  if (!res.ok) throw new Error("Request failed");
}

const api = {
  updateProfile: (values: SettingsValues) => call("profile", "PUT", values),
  exportData: () => call("export", "POST"),
  deleteAccount: () => call("account", "DELETE"),
};

export function Example() {
  return (
    <SettingsPage
      defaultValues={{
        name: "Ada Lovelace",
        username: "ada",
        email: "ada@example.com",
        bio: "Writing the first program, one punch card at a time.",
        notifications: { mentions: true, comments: true, digest: true },
      }}
      onSave={async (values) => {
        // A second argument lists the changed fields: ["name", "notifications.digest", …]
        await api.updateProfile(values);
      }}
      onExportData={() => api.exportData()}
      onDeleteAccount={() => api.deleteAccount()}
      stickyTop="5rem" // below your app bar
    />
  );
}
```

### When to use the settings page

- Use SettingsPage for the account area of a SaaS app, where someone updates a profile photo, flips notification switches, picks a theme and finds the risky actions in a Danger card at the bottom. The side nav follows the scroll and moves focus to the card you jump to, so keyboard users land in the right place. Use it as a settings layout template with grouped preference rows.
- Use it when edits should be explicit, since a save bar with Save and Discard appears only after something changes and Ctrl or Cmd plus S saves from the keyboard.
- Use it for apps that let people export data, upload an avatar up to maxAvatarMb (default 5), or delete their account behind a confirmation dialog.
- Skip it when a single setting should apply the moment it is toggled, such as a theme switch in a header; a lone Switch or SegmentedControl is enough without a save flow.
- Pair it with VerticalNav and ConfirmDialog, which it builds on, and with useTheme and useMotionPreference if your own app needs to read the preferences it exposes.


### Frequently asked questions

#### How do I build a settings page in React with SettingsPage?

Pass defaultValues and an onSave(values, changed) handler; throw inside it to show an error in the save bar. Add onDeleteAccount, onExportData and onAvatarChange(file) to enable those actions. The sections prop picks which sections to show, and the default is all four.

#### What happens if someone leaves with unsaved changes?

With warnOnLeave (default true), the browser asks before the page unloads while changes are pending. Unsaved changes, saving and errors are announced in a polite status region. The save bar offers Save and Discard, and Ctrl or Cmd plus S saves too.

#### How does the sticky section navigation behave for keyboard users?

Tab walks the section links, and Enter glides to the section and focuses its heading. The current link carries aria-current. Position it with stickyTop, which defaults to 1rem, and use headingLevel (default 1) to match your page structure.

#### How does the delete-account confirmation work?

Delete opens a type-to-confirm ConfirmDialog, so focus is trapped inside and Escape cancels it. You supply onDeleteAccount to perform the action, and labels lets you translate the dialog text. The save bar springs up and leaves faster without overshoot, and reduced motion removes the movement.

### Example 2 of 2: With react-hook-form

validate={false} turns the block's own checks off. fieldProps takes register(...) for each field, errors takes formState.errors, and status follows isSubmitting and isSubmitSuccessful. The state light and the success seal work the same.

```tsx
import { useForm } from "react-hook-form";
import { ContactForm, type ContactFormStatus, type ContactFormValues } from "@/components/sheenui/blocks/contact-form";
// Package build (after the first npm release, or a packed tarball): import { ContactForm, type ContactFormStatus, type ContactFormValues } from "@sheenui/theme";

declare function sendMessage(values: ContactFormValues): Promise<void>;

export function Example() {
  const { register, handleSubmit, reset, formState } = useForm<ContactFormValues>();
  const { errors, isSubmitting, isSubmitSuccessful } = formState;
  const status: ContactFormStatus = isSubmitting ? "submitting" : isSubmitSuccessful ? "success" : "idle";

  return (
    <ContactForm
      title="Write to us"
      validate={false}
      status={status}
      errors={{ name: errors.name?.message, email: errors.email?.message, message: errors.message?.message }}
      fieldProps={{
        name: register("name", { required: "Enter your name." }),
        email: register("email", {
          required: "Enter your email.",
          pattern: { value: /^\S+@\S+\.\S+$/, message: "Enter a valid email address." },
        }),
        message: register("message", { required: "Write a message.", minLength: { value: 10, message: "Write at least 10 characters." } }),
      }}
      onSubmit={() => handleSubmit(sendMessage)()}
      onReset={() => reset()}
    />
  );
}
```

## React Announcement Banner: Dismissible Glass Bar

URL: https://lokendra-builds.github.io/sheenui/blocks/announcement-banner
Sidebar name: Announcement banner

A React announcement banner on glass with a tone, a link and a dismiss button that reports the dismissal through a callback. Stores nothing. MIT.

What it is: AnnouncementBanner is a React announcement banner: a dismissible top bar on glass with a tone, an optional link and static copy. It stores nothing and reports the dismissal through onDismiss so you can remember it.

### Example 1 of 2: Remember the dismissal yourself

Controlled with open and onOpenChange; onDismiss fires once when the visitor presses the button, which is where you save it (a cookie, localStorage or an account setting) and pass defaultOpen={false} next time.

```tsx
import { useState } from "react";
import { AnnouncementBanner } from "@/components/sheenui/blocks/announcement-banner";
// Package build (after the first npm release, or a packed tarball): import { AnnouncementBanner } from "@sheenui/theme";

// Your own storage: the banner only reports the dismissal.
const remember = () => window.localStorage.setItem("banner-v2", "dismissed");

export function Example() {
  const [open, setOpen] = useState(true);
  return (
    <AnnouncementBanner
      open={open}
      onOpenChange={setOpen}
      onDismiss={remember}
      link={{ label: "Read the notes", href: "/changelog" }}
    >
      Version 2 is out: new blocks and a faster build.
    </AnnouncementBanner>
  );
}
```

### Accessibility

- A labelled group (labels.region), not a landmark and deliberately not a live region, so it is not read out on every page load. Dismissing moves focus on and announces it politely.
- Tone is never the only signal: the text says it and the icon is aria-hidden. Keep the copy static; a live countdown would be a moving target for assistive tech.
- The dismiss button has an accessible name and a 44 px target. The banner stores nothing, so there is no hidden persistence to explain.
- It slides up by transform and fades on its own surface, faster on the way out. Reduced motion: a short fade.

### All exports on this page

- defaultAnnouncementBannerLabels — The English AnnouncementBannerLabels used when labels is omitted; a partial labels prop is merged over it.


### When to use the announcement banner

- Use AnnouncementBanner above the navbar for a release, a maintenance window or a promotion, with one sentence and a link to the details.
- Use onDismiss to save the choice in your own storage (a cookie, localStorage or an account setting) and pass defaultOpen={false} on the next visit, so the component itself never touches storage.
- Use tone to pick the icon and light the edge: accent, info, success, warning, danger or neutral; the wording always says what it means, so colour is never the only signal.
- Skip live countdowns and rotating text inside it; a moving banner is hard to read with assistive technology, and the component is designed for static copy.
- Pair it with HeroSection and Navbar below it, and use dismissible={false} for a notice that must stay visible, such as a legal change.


### Frequently asked questions

#### How do I build a dismissible announcement banner in React?

Render AnnouncementBanner with your sentence as children, an optional link={{ label, href }}, and onDismiss to remember the choice. Control it with open and onOpenChange if the parent needs to show it again. Pass defaultOpen={false} when you already know the visitor dismissed it.

#### Where does the banner store the dismissal?

Nowhere. It keeps no cookie or localStorage entry. It calls onDismiss once when the visitor presses the button, and you save the choice wherever suits your app. That keeps the block free of hidden persistence and consent questions.

#### Is the banner announced to screen readers?

It is a labelled region landmark, deliberately not a live region, so it is not read out on every page load. The dismiss button has an accessible name and a 44 px target, and the tone icon is aria-hidden because the text carries the meaning.

#### How does it animate?

It slides down by transform and fades in on its own glass surface, then slides up and fades faster on the way out with no overshoot. With reduced motion it only fades for a short time.
