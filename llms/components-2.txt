### Accessibility

- Plain markup with no role, so reading order is the DOM order.
- Glass levels keep text at 4.5:1 over any backdrop; reduced transparency makes the card opaque, and forced colors give it a real border.
- The sheen is a soft highlight that follows a mouse or pen (never on touch). The hover lift is off with reduced motion.

### When to use the glass card

- Use GlassCard as a glassmorphism card for the tiles on a dashboard or pricing page, where grouped content sits on a gradient or photo background and the frosted surface keeps text readable.
- Use the tint prop to mark a featured plan or highlighted stat, so one card among several reads as accent colored without writing custom styles.
- Use interactive for a clickable card in a project grid, adding role, tabIndex and key handlers yourself, so it lifts on hover and shows a solid focus ring.
- Skip it when you need the full refracting lens look, which LiquidGlass provides, or when a page has more than a handful of cards in view, since each is a backdrop-filter surface.
- Pair it with Badge and Button in the footer, Avatar in the header, and Progress or NumberTicker in the content area for stat cards.


### Frequently asked questions

#### How do I create a glassmorphism card in React?

Render GlassCard and compose GlassCardHeader, GlassCardTitle, GlassCardDescription, GlassCardContent and GlassCardFooter inside it. It is a div with backdrop blur, and level 1, 2 or 3 sets how opaque the glass is, from chips and cards to dialogs and bars. Level 2 is the default.

#### Does the card have a performance limit?

Each GlassCard is one backdrop-filter surface, and the source states a budget of at most 8 in view at once. Past that, use fewer glass surfaces or plain containers for inner content. Reduced transparency makes the card opaque, and forced colors give it a solid border and background.

#### What does the sheen prop do?

It adds a soft highlight that follows the pointer, on by default. It only reacts to mouse and pen, never touch, and it stays at rest with reduced motion. Set sheen to false to turn it off. The light moves with a composited translate, so the card is not repainted on each move.

#### Is a GlassCard focusable?

Not on its own. It has no role, so a plain card is just a group of content. For a clickable card, give it role link or button with tabIndex 0 and key handlers; interactive then draws a solid focus ring. Every div prop, including onClick and className, is accepted.

### Accessibility

- label, description and error are linked with aria-labelledby and aria-describedby; an error is announced politely.
- Icons and affixes are decorative (aria-hidden); the input keeps its own name.
- Text is 16 px on touch screens so iOS does not zoom on focus; the border keeps 3:1 contrast.

### When to use Input

- Use Input as a text input with label and error for single-line entry like email, password, search and names in a sign-in or checkout form, where a label and an error message must be tied to the field.
- Use leading and trailing for a search box with a magnifier icon, or a password field with a show button inside the right edge of the field.
- Use the error prop for server-side validation messages, which mark the field invalid with aria-invalid and are announced without moving focus.
- Skip it when the text spans several lines or the value is a stepped number. Use Textarea for multi-line text, NumberField for a stepper, and OtpInput for a fixed-length code.
- Pair it with Button for submit, its label, description and error props for the field text, and Select or Combobox in the same form, since all three share the className wrapper convention.


### Frequently asked questions

#### How do I add a label and error to a glass input in React?

Pass label, description and error. Base UI Field links them to the input through aria-labelledby, aria-describedby and aria-invalid. The description is hidden while an error shows, and the error is announced to screen readers. Without a visible label, set aria-label instead.

#### What does className style on the Input?

className styles the outer wrapper that holds label, field and messages, matching Select and Combobox. Use inputClassName for the native input element. Every other prop, such as type, value, onChange and autoComplete, passes to the input.

#### Will iOS zoom into the field on focus?

The input is 44px tall with 16px text on touch screens, which is what stops iOS Safari from zooming on focus. The control border keeps a 3:1 contrast against its surroundings for WCAG 1.4.11, and forced colors mode keeps a visible border.

#### Does the input work with form libraries?

Yes. It accepts the native input props, so value, onChange, name, ref and onBlur work with controlled state or libraries such as react-hook-form. Typing, selection and browser autofill behave natively, because the field renders a real input element inside the glass wrapper.

### Example 2 of 4: Status feedback

The correct code is 123456. Anything else shakes the field.

```tsx
import { useState } from "react";
import { OtpInput, type OtpStatus } from "@/components/sheenui/otp-input/otp-input";
// Package build (after the first npm release, or a packed tarball): import { OtpInput, type OtpStatus } from "@sheenui/theme";

export function Example() {
  const [value, setValue] = useState("");
  const [status, setStatus] = useState<OtpStatus>("idle");

  return (
    <OtpInput
      grouped
      value={value}
      status={status}
      errorMessage="That code didn't match. Try 123456."
      successMessage="Code verified."
      // Only clear the status once the code is incomplete again: onValueChange also fires for the
      // last digit, and an unconditional reset there would undo onComplete's result.
      onValueChange={(v) => { setValue(v); if (v.length < 6) setStatus("idle"); }}
      onComplete={(v) => setStatus(v === "123456" ? "success" : "error")}
    />
  );
}
```

### When to use the OTP input

- Use OtpInput as a verification code input in React on a two-factor sign-in or phone verification screen, where an SMS or authenticator code of fixed length arrives and people type or paste it. Treat it as an input-otp alternative when you want styled, labeled code slots instead of a headless primitive.
- Use onComplete to verify the code the moment the last digit lands, and set status to error or success to shake the field or play a soft ripple with a message.
- Use grouped for a six digit code shown as 3 + 3, or mask when the code is sensitive and should not be readable over someone's shoulder.
- Skip it when the value is not a fixed-length numeric code. Use Input for an email or a recovery phrase, including a password with a show button in its trailing slot.
- Pair it with Button for a resend action, Alert for a rate-limit message, and the OTP verification block, which already assembles these pieces on one screen.


### SheenUI OtpInput or input-otp?

input-otp is a headless one-time-code library. SheenUI's OtpInput is built on Base UI's OTP field and arrives styled: glass slots, paste and SMS autofill, grouped and mask options, and error and success feedback through the status prop. Use input-otp if you want to draw every slot yourself; use this one if you want a finished, accessible field to copy.


### Frequently asked questions

#### How do I build a React OTP input with SheenUI?

Render OtpInput with a length, 6 by default, and handle value with onValueChange or leave it uncontrolled with defaultValue. onComplete fires once every slot is filled. It is built on Base UI OTPField, and name submits the joined code with a form.

#### Can users paste a code or use SMS autofill?

Yes to both. Pasting a whole code fills every slot at once, and the slots use autoComplete one-time-code, so phones can offer the SMS code. Typing advances to the next slot, Backspace clears and moves back, and the left and right arrow keys move between slots.

#### How are the slots named for screen readers?

The first slot is named by the label or aria-label, which defaults to Verification code. The others are named Digit n of N through digitLabel, which you can translate. Error and success messages sit in a polite live region, and each slot is at least 44px wide and 48px tall.

#### How do I trigger the error shake more than once?

Set status back to idle before setting it to error again. The shake and the success ripple play when the status changes, so repeating the same status does nothing. Both animations use transform and opacity only, and both are skipped when reduced motion is on.

### Frequently asked questions

#### How do I make a React progress bar with SheenUI?

Render Progress with a value from 0 to max, which defaults to 100 so value reads as a percentage. Add a label, which also names the bar for assistive technology. Set showValue to false to hide the percentage, and pass locale for prerendered pages so server and browser text match.

#### What does an indeterminate progress bar look like?

Pass value as null. The bar slides to signal loading with no known end, and Base UI omits aria-valuenow, aria-valuemin and aria-valuemax in that state. Under reduced motion it becomes a static, half-tone full-width bar instead of sliding.

#### How does it animate between values?

The fill is a full-width bar moved with translateX, transform only, so the rounded leading edge never distorts and the track clips it. A light sweeps across the fill a few times after each change. With reduced motion the fill jumps straight to each new value.

#### Is the progress bar focusable?

#### When should I use Progress, Meter or Spinner?

Use Progress for a task with a known length, such as an upload or a setup wizard, and pass value={null} while the length is unknown. Use Meter for a measurement against a range, such as disk used or password strength. A Spinner says that something is busy without saying how far along it is.

#### Can I hide the percentage or translate it?

Yes. showValue turns the percentage text on or off, and the number is formatted in the locale prop. label names the bar for assistive tech: Base UI renders role="progressbar" with aria-valuenow, aria-valuemin and aria-valuemax, and leaves all three out while the value is null.

### Frequently asked questions

#### How do I build a React select dropdown with SheenUI?

Render Select with an items array of value and label objects, then control it with value and onValueChange, or leave it uncontrolled with defaultValue. Add label, description and placeholder, which defaults to "Select…". It wraps Base UI Select, so the listbox behavior comes included.

#### Which keys work on the select?

Enter, Space or the Down arrow opens the list. Up and Down move through options, Home and End jump to the ends, and typing jumps to a matching option. Enter or Space selects, and Escape closes and returns focus to the trigger. Disabled items are shown but cannot be selected.

#### How do I style the trigger and wrapper separately?

#### When should I switch from Select to Combobox?

Switch when people would rather type than scroll, or when they need several values. Select supports typeahead jumping but has no search box, async loading or chips. Combobox adds filtering, loadOptions, onCreate and a multiple mode with removable chips, and takes options with the same value and label fields.

- Pair it with Button, which shows its own spinner through the loading prop, useOffscreenLoops near the app root to pause off-screen loops, and EmptyState for a loading panel.


### Frequently asked questions

#### How do I add a loading spinner in React with SheenUI?

Render Spinner. Choose size from xs at 12px to xl at 48px, with md at 24px as the default, and tone from accent, current or muted. It is a role status live region with a hidden Loading label, so mounting it announces Loading politely. Remove it when the work finishes.

#### How do I translate the spinner label?

Pass labels with a loading string, for example labels={{ loading: "Chargement" }}. That text is what a screen reader says and what showLabel prints. The default is Loading, and the partial object you pass is merged over the English defaults.

#### What happens with reduced motion?

The arc stops turning and shows as a static arc on its track, with the same Loading label for screen readers. Normally it turns once a second using a CSS rotation transform. The track keeps 3:1 contrast and forced colors draw it in CanvasText.

#### Should the spinner go inside a button?

Put it next to the content it replaces, or inside a button that has aria-busy. If you use SheenUI Button, set its loading prop instead, which shows the spinner, ignores clicks and sets aria-busy for you, so you do not need to compose the pieces by hand.

### Frequently asked questions

#### How do I build animated tabs in React with SheenUI?

No, inactive panels are hidden, and the leaving panel is removed at once so quick switching never shows two panels. Add keepMounted to a TabsPanel to keep it rendered. The entering panel rises 6px using a transform only; with reduced motion it simply appears.

```tsx
  const save = () =>

  };

      <button onClick={remove}>Action</button>
      <button onClick={upload}>Update by id</button>
```

### Choosing between SheenUI Toast and Sonner

Sonner is a popular React toast library built around one global toast() call. SheenUI's toast is built on Base UI's Toast: you wrap the app in ToastProvider, render one Toaster and call useToast() for toast.success, toast.info, toast.error and toast.dismiss. Toasts stack, expand on hover or focus, can be swiped away, pause their timer while hovered or focused and fade under reduced motion. Choose Sonner if you want a global function and nothing to provide; choose this one if you want glass styling, Base UI's accessibility model and the source in your own repository.

#### How do I show a toast notification in React with SheenUI?

#### How does keyboard and screen reader support work?

Toasts are announced politely through a live region and never steal focus. F6 moves focus to the viewport in Base UI, Tab reaches each Dismiss button, and Enter, Space or Escape closes the focused toast. The timer pauses while a toast is hovered or focused, giving time to read.

#### Can I swipe a toast away?

Yes. Swipe toward the nearest edge on touch; on phones either side dismisses. The exit speed follows the swipe velocity, clamped to a range of 60 to 400 ms. Under reduced motion toasts fade only and the stack rearranges without sliding, though swiping still tracks your finger.

#### How do I translate the toast Dismiss button?

Pass labels to Toaster with a dismiss string, such as labels={{ dismiss: "Fermer" }}. The default is Dismiss. The region itself is named by the label prop, Toast notifications by default (so it never clashes with a Notifications panel), so give each stack its own name if a page renders more than one.

### Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| content | ReactNode | required | What the tooltip says. |
| children | ReactElement<unknown, string \| JSXElementConstructor<any>> | required | The element that shows the tooltip on hover, keyboard focus or (touch) a long press. Must accept a ref (a native element or a SheenUI component). |
| side | "top" \| "bottom" \| "left" \| "right" | "top" | Which side of the trigger it opens on. It flips when there is no room. |
| align | "center" \| "end" \| "start" | "center" | Alignment along that side: "start", "center" or "end". |
| delay | number | 300 | Sets the delay before showing, in ms. |
| open | boolean | optional, no default | Open state (controlled). Pair with onOpenChange. Leave it out to let hover, focus and touch decide. |
| defaultOpen | boolean | false | Starting open state when uncontrolled. |
| onOpenChange | ((open: boolean) => void) | optional, no default | Called when the tooltip wants to open or close (hover, focus, Escape, touch hold). |
| disabled | boolean | false | Never show the tooltip (the trigger still works). |
| className | string | optional, no default | Adds extra classes to the tooltip bubble. |


### Example 2 of 2: Sides and delay

side picks the edge it opens on. delay is how long the pointer must rest before it opens; 0 shows it at once. A TooltipProvider makes moving between tooltips instant.

```tsx
import { Button } from "@/components/sheenui/button/button";
import { Tooltip, TooltipProvider } from "@/components/sheenui/tooltip/tooltip";
// Package build (after the first npm release, or a packed tarball): import { Button, Tooltip, TooltipProvider } from "@sheenui/theme";

export function Example() {
  return (
    <TooltipProvider>
      <Tooltip content="Opens above (the default)">
        <Button variant="glass">Top</Button>
      </Tooltip>
      <Tooltip content="Opens to the right" side="right">
        <Button variant="glass">Right</Button>
      </Tooltip>
      <Tooltip content="Opens at once" delay={0}>
        <Button variant="glass">No delay</Button>
      </Tooltip>
      <Tooltip content="Waits a full second" delay={1000} side="bottom">
        <Button variant="glass">Slow</Button>
      </Tooltip>
    </TooltipProvider>
  );
}
```

### Keyboard

| Keys | Action |
| --- | --- |
| Tab / Shift + Tab | Focusing the trigger shows the tooltip; leaving it hides it. |
| Escape | Dismiss the tooltip while keeping focus on the trigger. |

### Accessibility

- Tooltip adds no tab stop of its own; the trigger keeps its own. The bubble has role=“tooltip” and, while it is open, the trigger points to it with aria-describedby (added to any description it already has), so the text is announced as its description. It describes, it does not name: an icon-only trigger still needs its own aria-label.
- Keep it to a short label. Anything interactive belongs in a Popover; essential text must not live only in a tooltip.
- The bubble stays open while the pointer moves onto it (so it can be read while magnified) but holds no controls. On touch screens a long press (about half a second) shows it for a couple of seconds, and lifting the finger does not activate the trigger; a plain tap never shows it, so never hide the only label of a control in a tooltip. Under reduced motion it only fades.

### When to use Tooltip

- Use Tooltip to label icon-only buttons in an editor toolbar (Bold, Italic, Export) on hover and on keyboard focus, and put the shortcut, such as Ctrl+B, beside the name.
- Use it for short supplementary hints on a form, like why a field wants a particular format, where the hint is useful but nobody is blocked without it.
- Use TooltipProvider once near the app root so moving between neighboring triggers shows the next tip at once, and use delay to tune the 300ms default.
- Skip it when the content is essential, long or interactive. Use Popover for controls, HoverCard for a rich preview, and plain visible text when a label must always be readable.
- Pair it with Button using size icon, Kbd to show shortcuts inside the tip, and Avatar or Badge when a name or status needs a short explanation.


### Frequently asked questions

#### How do I add a react tooltip with SheenUI?

Wrap a single element that accepts a ref in Tooltip and pass content as the text. Choose side, which defaults to top and flips near the viewport edge, align, and delay in ms, 300 by default. Use open with onOpenChange to control it, or disabled to switch it off.

#### Does the tooltip work with the keyboard and touch?

It shows when the trigger gets focus and hides on blur or Escape, and the trigger keeps its own tab stop. On touch, a long press of about half a second shows it for a couple of seconds, and lifting the finger does not activate the trigger.

#### Is the tooltip text announced by screen readers?

The bubble has role tooltip and, while open, the trigger points to it with aria-describedby, merged with any description the trigger already has. It describes but does not name, so an icon-only button still needs its own aria-label. Never hide a control's only label inside a tooltip.

#### Why use TooltipProvider?

It lets people move from one trigger to the next and see the next tooltip instantly instead of waiting out the delay again. Place it once near the app root. It renders no element and adds no tab stops, and each Tooltip inside keeps its own behavior.
