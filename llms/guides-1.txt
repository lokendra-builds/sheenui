### Frequently asked questions

#### Which guide should I read first?

To install, read the Next.js and Vite install guide. To learn the technique, read the glassmorphism React tutorial. To choose a library, start with the comparison of glassmorphism React libraries.

#### Do the guides say which versions they were checked against?

Where a guide quotes third-party facts (versions, licences, star counts, browser support), it dates them in the text, such as React 19.3, Tailwind CSS 4.3 and Vite 8.3 in the install guide. Several guides also say near the top what they are based on, and every guide shows its published and updated dates; those are when the text was written and revised, not a claim that every fact was re-checked that day.

#### Is the code in the guides tested?

Yes, the TypeScript samples that use SheenUI are compiled against the library by the repo's checks. The Code panel samples on the component pages and the guides' own code blocks are type-checked against the real SheenUI exports by pnpm pagecode:check, and the @example blocks in the library source by pnpm examples:check. A guide sample that shows another library's API, such as the Radix version in the Base UI comparison, is marked external and is not compiled. Compiling is not running: where a guide says it ran or checked something, such as the install guide's end-to-end runs in Next.js and Vite apps, it says what and on which date.

#### Are the comparison guides neutral?

They say up front that SheenUI is the author's own library, give strengths first and mark data they could not verify instead of guessing.

#### Can I read the guides outside the site?

Yes. Each guide is a Markdown file in the docs/guides folder of the repository, and the full text is also in the llms.txt files.

## Install SheenUI Glass UI in Next.js and Vite

Tested install steps for SheenUI in Next.js App Router and Vite (React Router or TanStack Router): the shadcn CLI, the packed package, or copying files.

By Lokendra Singh Rathore. Published November 8, 2026, updated November 16, 2026.

Breadcrumb: [Home](https://lokendra-builds.github.io/sheenui/) > [Guides](https://lokendra-builds.github.io/sheenui/guides/) > Install SheenUI Glass Components in Next.js and Vite

Every step below was first run end to end on 8 Nov 2026 in throwaway apps; on 12 Nov 2026 the versions in the table were re-checked against the packages installed in this repository (Vite 8.3.8, React 19.3.1, Tailwind 4.3.5). A real browser exercised ten components (button, dialog, menu, tabs, toast, data table, line chart, chat widget, backdrop, theme switcher) and reported no console errors or hydration warnings, and every interaction worked.

| Setup | Versions tested | Result |
|---|---|---|
| Next.js App Router, package | Next 16.4.5, React 19.3.1, Tailwind 4.3.5 | `next build` passes with Turbopack and with `--webpack`; dev and production; 0 hydration warnings |

For the short version (one CLI command and two CSS lines) see the [installation page](https://lokendra-builds.github.io/sheenui/docs/installation); this guide has the framework detail and the tested versions.

SheenUI needs React 19.2 or newer (the components use `useEffectEvent`) and Tailwind CSS v4 (the [Tailwind CSS v4 setup](https://lokendra-builds.github.io/sheenui/docs/tailwind-v4) explains how the tokens and layers fit). Two ways to get the code:

- **Package** (`@sheenui/theme`): compiled ES modules plus the stylesheet. `clsx`, `tailwind-merge` and `@tanstack/react-table` install with it; `react`, `react-dom`, `tailwindcss`, `@base-ui/react` and `motion` are peer dependencies that your app adds (see below; the [Base UI docs page](https://lokendra-builds.github.io/sheenui/docs/base-ui) explains what Base UI contributes).
- **Copy the files**: the shadcn CLI or a manual copy puts the source into your project, like shadcn/ui.

Many code samples on the docs pages use icons from `lucide-react`. The components do not need it, but a pasted sample does: `pnpm add lucide-react`.

Basis: the end-to-end runs and the version re-check this guide reports in its opening (8 Nov 2026 and 12 Nov 2026), and the files the registry installs. First published 8 Nov 2026, last revised 16 Nov 2026; the later date marks an edit of the text, and the table lists the versions that were actually tested.

### 0. Get the package (until it is on npm)

`@sheenui/theme` is marked `private` in the repo, so it is not on npm yet. Pack it from a clone, then install the tarball:

```bash
git clone https://github.com/lokendra-builds/sheenui && cd sheenui
pnpm install
pnpm --filter @sheenui/theme pack --pack-destination ..   # builds dist/, writes ../sheenui-theme-0.1.0.tgz (my-app sits next to the clone)
cd ../my-app && pnpm add ../sheenui-theme-0.1.0.tgz motion @base-ui/react
```

Once it is published, this becomes `pnpm add @sheenui/theme`. Publish with `pnpm publish` (not `npm publish`): the repo keeps `exports` pointing at `src/` for development and relies on pnpm's `publishConfig.exports` to point at `dist/` in the tarball.

### 1. Next.js (App Router)

#### Option A: the package

```bash
pnpm create next-app@latest my-app --ts --tailwind --app --src-dir --import-alias "@/*"
cd my-app
pnpm add ../sheenui-theme-0.1.0.tgz motion @base-ui/react
```

`src/app/globals.css`: Tailwind first, then SheenUI. No `@source` line is needed, the stylesheet already scans the package.

```css
@import "tailwindcss";
@import "@sheenui/theme/styles.css";
```

`src/app/layout.tsx` (a Server Component; no `"use client"` needed):

```tsx
import type { ReactNode } from "react";
import { SheenBackdrop, SheenMotionProvider, ToastProvider, Toaster, sheenPreferenceScript } from "@sheenui/theme";
import "./globals.css";

export default function RootLayout({ children }: { children: ReactNode }) {
  return (
    <html lang="en" data-sheen-style="liquid" suppressHydrationWarning>
      <head>
        <script dangerouslySetInnerHTML={{ __html: sheenPreferenceScript }} />
      </head>
      <body>
        <SheenMotionProvider>
          <ToastProvider>
            <SheenBackdrop />
            {children}
            <Toaster />
          </ToastProvider>
        </SheenMotionProvider>
      </body>
    </html>
  );
}
```

`suppressHydrationWarning` on `<html>` and the inline script are what keep a saved theme or style from flashing or mismatching: the script sets `data-theme`, `data-sheen-style` and friends on `<html>` before React hydrates.

Pages can be Server Components that compose SheenUI components directly. Only code that uses a hook or an event handler of your own needs `"use client"`:

```tsx
// src/app/page.tsx (Server Component)
import { Button, Dialog, DialogClose, DialogContent, DialogDescription, DialogHeader, DialogTitle, DialogTrigger, Tabs, TabsList, TabsPanel, TabsTab } from "@sheenui/theme";
import { ThemeSwitcher, ToastButton } from "./islands";

export default function Page() {
  return (
    <main className="mx-auto grid max-w-5xl gap-6 p-6">
      <ToastButton />
      <ThemeSwitcher />
      <Dialog>
        <DialogTrigger render={<Button />}>Open dialog</DialogTrigger>
        <DialogContent>
          <DialogHeader>
            <DialogTitle>Hello</DialogTitle>
            <DialogDescription>Composed in a Server Component.</DialogDescription>
          </DialogHeader>
          <DialogClose render={<Button variant="ghost" />}>Close</DialogClose>
        </DialogContent>
      </Dialog>
      <Tabs defaultValue="a">
        <TabsList><TabsTab value="a">One</TabsTab><TabsTab value="b">Two</TabsTab></TabsList>
        <TabsPanel value="a">Panel one</TabsPanel>
        <TabsPanel value="b">Panel two</TabsPanel>
      </Tabs>
    </main>
  );
}
```

```tsx
// src/app/islands.tsx (hooks live in a Client Component)
"use client";
import { Button, SegmentedControl, useTheme, useToast, type ThemeChoice } from "@sheenui/theme";

export function ToastButton() {
  const toast = useToast();
  return <Button onClick={() => toast.success("Saved", "Your changes are live.")}>Show toast</Button>;
}

export function ThemeSwitcher() {
  const { theme, setTheme } = useTheme();
  return (
    <SegmentedControl
      aria-label="Theme"
      value={theme}
      onValueChange={(v) => setTheme(v as ThemeChoice)}
      items={[{ value: "light", label: "Light" }, { value: "dark", label: "Dark" }, { value: "system", label: "System" }]}
    />
  );
}
```

Notes, all verified:

- Next 16's `create-next-app` sets up Tailwind v4 for Turbopack (`@tailwindcss/turbopack` rule in `next.config.ts`). To build with `next build --webpack`, add the PostCSS plugin instead: `pnpm add -D @tailwindcss/postcss` and a `postcss.config.mjs` with `export default { plugins: { "@tailwindcss/postcss": {} } };`. The CSS lines above stay the same.
- No `transpilePackages` and no `next.config` change: the package ships compiled JavaScript, and every component module starts with `"use client"`. Importing from the `@sheenui/theme` barrel in a Server Component is safe; client modules become client references and nothing client-only runs on the server.
- Values that are not components are only usable on the server when they live in a plain module. Safe in Server Components: `cn`, the motion tokens (`duration`, `ease`, `spring`, `fadeUp`, ...), `defaultChatLabels`, `defaultDataTableLabels`, `toCsv`, `tokenize`, `formatBytes`, `parseColor`, date helpers such as `toISODate`. Helpers and `default…Labels` objects that sit next to a component (`formatCompact`, `formatCurrency`, `getPageItems`, `defaultLineChartLabels`, ...) and every hook belong to a client module: call them in a Client Component. In a Server Component, calling one throws `Attempted to call formatCompact() from the server but formatCompact is on the client`, and spreading a label object gives `{}`.
- `ChatWidget`, `DataTable` and the charts take plain props, so a Server Component can pass them arrays and a `Date` (pass a fixed `now` and `locale` to the chat so server and client text match).
- In `next dev`, Motion logs `You have Reduced Motion enabled on your device` when the OS or the in-app switch asks for reduced motion. It is an informational notice from the Motion library, not an error.
- Smaller CSS: `@sheenui/theme/styles.css` makes Tailwind generate the utilities of every component (about 390 KB, 66 KB gzip). To pay only for the components you use, import the base and scan just those folders (about 110 KB, 30 KB gzip with Button):

  ```css
  @import "tailwindcss";
  @import "@sheenui/theme/styles/base.css";
  @source "../../node_modules/@sheenui/theme/dist/components/button";
  ```

#### Option B: copy the files with the shadcn CLI

```bash
pnpm create next-app@latest my-app --ts --tailwind --app --src-dir --import-alias "@/*"
cd my-app
pnpm dlx shadcn@latest init -d
pnpm dlx shadcn@latest add https://lokendra-builds.github.io/sheenui/r/button.json \
  https://lokendra-builds.github.io/sheenui/r/glass-card.json https://lokendra-builds.github.io/sheenui/r/dialog.json \
  https://lokendra-builds.github.io/sheenui/r/input.json https://lokendra-builds.github.io/sheenui/r/backdrop.json \
  https://lokendra-builds.github.io/sheenui/r/line-chart.json https://lokendra-builds.github.io/sheenui/r/analytics-demo-saas.json
```

Each item installs into `components/sheenui/<item>/` and pulls in `sheenui-theme` (tokens, glass, motion, hooks, styles) and the npm packages it needs. `input` is listed because the Dialog example uses it, and `analytics-demo-saas` is the SaaS dashboard together with its sample data (the plain `analytics-saas` item is the dashboard alone). Then:

1. The CLI appends `@import "@/components/sheenui/styles/index.css";` to your global CSS. **Next.js cannot resolve the `@/` alias inside CSS** (`next build` fails with `Can't resolve '@/components/sheenui/styles/index.css'`). Change it to the relative path:

   ```css
   @import "tailwindcss";
   @import "../components/sheenui/styles/index.css";
   ```

   This is the same text in `src/app/globals.css` and in `app/globals.css` (an app made without `--src-dir`): `components/` sits next to `app/` in both layouts. Vite resolves the alias, so keep the `@/` form there.
2. Import from the installed paths and mount the motion provider and the backdrop once. Use the `RootLayout` from option A (`src/app/layout.tsx`, or `app/layout.tsx` without `--src-dir`) and replace only its package import with these three copied-files imports (`SheenMotionProvider` from `@/components/sheenui/motion/provider`, `SheenBackdrop` from `@/components/sheenui/backdrop/backdrop`, `sheenPreferenceScript` from `@/components/sheenui/hooks/use-preferences`), written as `import { SheenMotionProvider } from "@/components/sheenui/motion/provider";` and so on. Add `toast.json` and wrap the children in `ToastProvider` and `Toaster` (`@/components/sheenui/toast/toast`, `.../toast/toaster`) only if you use toasts.
3. Components that only take plain props can sit in a Server Component. Anything that takes a function (a chart's `format`, `legend={seriesLegend(...)}`, a dashboard's `load`) must live in a file that starts with `"use client"`; see "Function props" below. This page is a Server Component (`src/app/page.tsx`):

##### Function props: charts and dashboards in Next.js

Every chart and dashboard module already starts with `"use client"`, so you can render them from a Server Component. What cannot cross the server/client boundary is a function: a chart's `format`, the `seriesLegend(...)` and `formatCompact(...)` helpers (they live in client modules, so calling one on the server throws `Attempted to call seriesLegend() from the server but seriesLegend is on the client`), and a dashboard's `load` and `liveStep`. The docs samples for charts and dashboards pass functions, so paste them into a file that starts with `"use client"` and import that file from your page. They work there exactly as written; only the import lines change to the copied paths. For example `src/app/sheen-islands.tsx`:

```tsx
// src/app/sheen-islands.tsx
"use client";
import { LineChart } from "@/components/sheenui/charts/line-chart";
import { ChartCard } from "@/components/sheenui/charts/chart-parts/chart-card";
import { ChartTable } from "@/components/sheenui/charts/chart-parts/empty-table";
import { seriesLegend } from "@/components/sheenui/charts/chart-parts/legend-tooltip";
import { formatCompact, type ChartSeries } from "@/components/sheenui/charts/chart-utils";
import { SaasRevenueDashboard } from "@/components/sheenui/blocks/analytics-saas";
import { saasRevenueDemoLoader, saasLiveStep } from "@/components/sheenui/blocks/analytics/demo-saas";

const usd = (n: number) => "$" + formatCompact(n);

const data = [
  { month: "Jan", organic: 4200, paid: 2100 },
  { month: "Feb", organic: 4800, paid: 2300 },
  { month: "Mar", organic: 5600, paid: 2200 },
];

const series: ChartSeries[] = [
  { key: "organic", label: "Organic", color: 1 },
  { key: "paid", label: "Paid", color: 2 },
];

export function Revenue() {
  return (
    <ChartCard
      title="Monthly revenue by channel"
      legend={seriesLegend(series, "line")}
      table={<ChartTable data={data} index="month" series={series} format={usd} />}
    >
      <LineChart data={data} index="month" series={series} format={usd} aria-label="Monthly revenue by channel" />
    </ChartCard>
  );
}

export function SaasDashboard() {
  return <SaasRevenueDashboard load={saasRevenueDemoLoader} liveStep={saasLiveStep} product="Acme Cloud" />;
}
```

### 2. Vite + React Router or TanStack Router (SPA, no SSR)

Start from any Vite React TypeScript app (`pnpm create vite@latest my-app --template react-ts`), then:

```bash
pnpm add ../sheenui-theme-0.1.0.tgz motion @base-ui/react react-router        # or @tanstack/react-router
pnpm add -D tailwindcss @tailwindcss/vite
```

`vite.config.ts`:

```ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({ plugins: [react(), tailwindcss()] });
```

`src/index.css`:

```css
@import "tailwindcss";
@import "@sheenui/theme/styles.css";
```

`index.html`: inline the preference script in `<head>` (it is the text of `sheenPreferenceScript`) and set the default style on `<html>`:

```html
<html lang="en" data-sheen-style="liquid">
  <head>
    <script>
      (function(){try{var r=document.documentElement;["theme","motion","transparency","glass"].forEach(function(k){var v=localStorage.getItem("sheen:"+k);if(v)r.setAttribute("data-"+k,v);});var s=localStorage.getItem("sheen:style");r.setAttribute("data-sheen-style",s==="aurora"||s==="liquid"?s:"liquid");}catch(e){document.documentElement.setAttribute("data-sheen-style","liquid");}})();
    </script>
  </head>
```

`src/main.tsx` with React Router: the providers wrap the router, so the backdrop and toasts survive navigation. `Home` is any page component of yours; this one is enough to try it:

```tsx
// src/home.tsx
import { Button } from "@sheenui/theme";

export function Home() {
  return <Button>Hello</Button>;
}
```

```tsx
// src/main.tsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { BrowserRouter, Route, Routes } from "react-router";
import { SheenBackdrop, SheenMotionProvider, ToastProvider, Toaster } from "@sheenui/theme";
import "./index.css";
import { Home } from "./home";

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <SheenMotionProvider>
      <ToastProvider>
        <SheenBackdrop />
        <BrowserRouter>
          <Routes>
```

### Package hygiene (what `pnpm pack` ships)

Checked against the tarball of `@sheenui/theme`:

- `exports`: `.` (barrel, ESM + `.d.ts`), `./components/*`, `./blocks/*`, `./motion/*`, `./hooks/*` (one file per module, for importing a single component), `./styles.css`, `./styles/*`, `./package.json`.
- `sideEffects: ["**/*.css"]`: bundlers drop every unused module and keep CSS imports. A bundle that imports only `Button` contains no charts, chat or Motion engine: 276 KB (88 KB gzip) in total against 220 KB (69 KB gzip) for a bare `react-dom` app, so Button adds about 57 KB (19 KB gzip) of JavaScript, including Base UI, `clsx` and `tailwind-merge` (measured on 16 Nov 2026 with Vite 8.3.8 and React 19.3.1). Importing `@sheenui/theme/components/button/button` directly gives the same size. The stylesheet is separate and carries every token and both style presets: 473 KB, 76 KB gzip.
- Types resolve with `moduleResolution` `bundler`, `node16` and `nodenext` (`skipLibCheck: false`), and Node can `import("@sheenui/theme")` directly.
- Peer dependencies: `react`, `react-dom` (19.2 or newer), `tailwindcss` (4.1 or newer), `@base-ui/react` (1.9 or newer), `motion` (14.10 or newer), optional `@types/react`. Two copies of Motion would break `MotionConfig`, so the app owns the one copy.
- The tarball holds `dist/`, `LICENSE`, `README.md` and `package.json` only: no tests, source maps, local paths or secrets.

### Frequently asked questions

#### Is SheenUI on npm?

Not yet. `@sheenui/theme` is marked `private` in the repository, so you either pack it from a clone and install the tarball, or let the shadcn CLI or a manual copy put the source into your project. Once it is published, the install becomes `pnpm add @sheenui/theme`.

#### Which versions of React and Tailwind CSS does it need?

React 19.2 or newer (the components use `useEffectEvent`) and Tailwind CSS 4.1 or newer. The other peer dependencies are `@base-ui/react` 1.9 or newer and `motion` 14.10 or newer, and your app owns the single copy of Motion.

#### Does it work with the Next.js App Router and server components?

Yes. It was built and run on Next 16 with Turbopack and with `--webpack`, in dev and production, with no hydration warnings. Every component module starts with `"use client"`, so a Server Component can import and render them (they become client references). Helpers and hooks that live in those modules must be called from a Client Component.

#### Why does the theme flash or React warn about hydration on the html element?

The saved theme and style are applied by a script that has to run before first paint. Inline `sheenPreferenceScript` in `<head>` and keep `suppressHydrationWarning` on `<html>`.

#### How much JavaScript does one component add?

Importing only `Button` adds about 57 KB (19 KB gzip) over a bare `react-dom` app, including Base UI, `clsx` and `tailwind-merge`. Unused components, charts and the Motion engine are dropped because the package declares `sideEffects: ["**/*.css"]`.

Glassmorphism in React is a UI style where a component looks like frosted glass: a translucent tint, a `backdrop-filter` blur and a thin light border over a colorful background. This tutorial builds it from four layers in plain CSS, then Tailwind CSS v4, then a typed React component, with contrast checks and fallbacks for people who turn transparency off.

Each step is a short glassmorphism React example you can paste into a project and see working before you read on. To see the finished surface live, open the [Glass card page](https://lokendra-builds.github.io/sheenui/components/glass-card).

Quick answer, the smallest glassmorphism in React or any page (a colorful background behind it makes it visible):

```css
.glass {
  background: rgb(255 255 255 / 0.12);
  backdrop-filter: blur(16px) saturate(160%);
  border: 1px solid rgb(255 255 255 / 0.25);
  border-radius: 16px;
}
```

Basis: written for React 19.2+ and Tailwind CSS v4; the Tailwind statement about variants refers to Tailwind CSS 4.3.5, and browser support is quoted from MDN browser-compat-data. First published 8 Nov 2026, last revised 26 Nov 2026.

### What glassmorphism is

Glassmorphism is a surface that looks like frosted glass: you see a blurred version of whatever sits behind it. It is not a color or a shadow. It only works when there is something colorful behind the glass, which is why flat white pages make it look like a gray box.

Nielsen Norman Group describes the style and its risk in one line: if overused, it can [pose significant accessibility and usability challenges](https://www.nngroup.com/articles/glassmorphism/). Keep that in mind; sections 4 and 5 are about it.

### The four layers

Build the effect in this order. Each layer fixes a specific problem of the one before.

1. **A vivid background.** Without color variation there is nothing to blur. A gradient or a few soft blobs is enough.
2. **A tint.** A semi-transparent fill (white in light mode, a dark smoke in dark mode) lowers the contrast of whatever shows through, so text on top stays readable.
3. **A backdrop blur.** `backdrop-filter: blur()` blurs what is behind the element, not the element itself. A small `saturate()` brings back the color the blur washes out.
4. **A lit border.** A 1px light border and a thin inner highlight on the top edge make the pane read as a physical sheet.

In plain CSS:

```css
.glass {
  background: rgb(255 255 255 / 0.55);
  -webkit-backdrop-filter: blur(20px) saturate(160%);
  backdrop-filter: blur(20px) saturate(160%);
  border: 1px solid rgb(255 255 255 / 0.6);
  border-radius: 20px;
  box-shadow:
    inset 0 1px 0 rgb(255 255 255 / 0.8),
    0 12px 32px -12px rgb(30 20 80 / 0.35);
}
```

`backdrop-filter` is supported unprefixed in Chrome 76, Edge 79, Firefox 103 and Safari 18, with a `-webkit-` prefix back to Safari 9 ([MDN browser-compat-data 8.1.8, 2 Nov 2026](https://developer.mozilla.org/en-US/docs/Web/CSS/backdrop-filter)). Keep the prefixed line for older Safari.

The same four layers as Tailwind CSS v4 utilities (SheenUI's [Tailwind CSS v4 setup](https://lokendra-builds.github.io/sheenui/docs/tailwind-v4) shows the imports it needs). In v4, `backdrop-blur-xl` is a 24px blur:

```html
<div class="relative min-h-screen bg-linear-to-br from-violet-500 via-fuchsia-400 to-amber-300">
  <div
    class="rounded-2xl border border-white/60 bg-white/55 p-6 backdrop-blur-xl backdrop-saturate-150 shadow-[inset_0_1px_0_rgb(255_255_255/0.8)]"
  >
    Frosted glass
  </div>
</div>
```

### A reusable GlassCard in TypeScript

Three levels cover most interfaces: level 1 for small chips, level 2 for cards, level 3 for dialogs and bars. Higher levels use more tint and more blur. This component has no dependencies except React:

```tsx
import type { ComponentProps } from "react";

type GlassLevel = 1 | 2 | 3;

const levels: Record<GlassLevel, string> = {
  1: "bg-white/40 backdrop-blur-md dark:bg-slate-900/40",
  2: "bg-white/55 backdrop-blur-xl dark:bg-slate-900/50",
  3: "bg-white/75 backdrop-blur-2xl dark:bg-slate-900/70",
};

export type GlassCardProps = ComponentProps<"div"> & { level?: GlassLevel };

export function GlassCard({ level = 2, className = "", ...props }: GlassCardProps) {
  return (
    <div
      className={`rounded-2xl border border-white/60 shadow-[inset_0_1px_0_rgb(255_255_255/0.8)] backdrop-saturate-150 dark:border-white/10 ${levels[level]} ${className}`}
      {...props}
    />
  );
}
```

Because it spreads `ComponentProps<"div">`, it accepts `onClick`, `aria-*` and `ref` like a normal `div`.

One rule saves hours of debugging: never fade or filter a *wrapper* of a glass element. An ancestor with `opacity` below 1, a `filter`, a `mask`, a `clip-path` or a `mix-blend-mode` becomes a "backdrop root", and the blur then only sees content inside that ancestor, not the page behind it ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/backdrop-filter)). Animate the glass element itself.

### Keeping text readable

The tint is not decoration; it is what keeps text legible. WCAG 2 asks for [4.5:1 contrast for normal text and 3:1 for large text](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), and on glass the background behind the text is different at every point.

So test the worst case, not the average. Composite your tint over the brightest and darkest parts of your backdrop and keep the minimum:

```tsx
export type RGB = readonly [number, number, number];

const channel = (value: number) => {
  const s = value / 255;
  return s <= 0.04045 ? s / 12.92 : ((s + 0.055) / 1.055) ** 2.4;
};

export const luminance = ([r, g, b]: RGB) => 0.2126 * channel(r) + 0.7152 * channel(g) + 0.0722 * channel(b);

export function contrast(a: RGB, b: RGB) {
  const [light, dark] = [luminance(a), luminance(b)].sort((p, q) => q - p) as [number, number];
  return (light + 0.05) / (dark + 0.05);
}

/** The tint (rgb + alpha) laid over one backdrop sample. */
export const over = (tint: RGB, alpha: number, back: RGB): RGB => [
  Math.round(tint[0] * alpha + back[0] * (1 - alpha)),
  Math.round(tint[1] * alpha + back[1] * (1 - alpha)),
  Math.round(tint[2] * alpha + back[2] * (1 - alpha)),
];

export function worstContrast(text: RGB, tint: RGB, alpha: number, backdrop: readonly RGB[]) {
  return Math.min(...backdrop.map((sample) => contrast(text, over(tint, alpha, sample))));
}
```

Run it with text `#1b1b2f` and a white tint at 55% opacity. In our run (computed with the code above), that text scored 7.98:1 over a pure `#e11d48` red, 13.29:1 over `#fbbf24` amber and 5.02:1 over pure black. The darkest sample is the limit here. Without the tint the same red gives only 3.59:1 and black 1.24:1, which is why the tint matters. If your worst sample falls under 4.5, raise the tint opacity, change the text color, or move the text off that part of the background.

SheenUI's own tokens file records the same kind of measurement. On its brightest backdrop blob, muted text measured 5.2:1 (light theme) bare and 6.7:1 on level-2 glass, because the tint lifts it. Numbers like these come from sampling rendered pixels, not from guessing; [the accessibility guide](https://lokendra-builds.github.io/sheenui/guides/accessible-glassmorphism) shows how.

### Fallbacks for people who turn transparency off

Some people cannot read through translucency. Operating systems expose that as media queries, and glass should answer each of them by becoming a solid surface:

```css
:root {
  color-scheme: light dark;
}

@supports not ((backdrop-filter: blur(1px)) or (-webkit-backdrop-filter: blur(1px))) {
  .glass {
    background: rgb(255 255 255 / 0.92);
  }
}

@media (prefers-reduced-transparency: reduce) {
  .glass {
    background: Canvas;
    -webkit-backdrop-filter: none;
    backdrop-filter: none;
  }
}

@media (prefers-contrast: more) {
  .glass {
    background: Canvas;
    border-color: CanvasText;
  }
}

@media (forced-colors: active) {
  .glass {
    background: Canvas;
    border: 1px solid CanvasText;
    box-shadow: none;
    backdrop-filter: none;
  }
}
```

Browser support differs. `prefers-reduced-transparency` is in Chrome and Edge 118, behind a flag in Firefox 113 and absent from Safari, and MDN still marks it experimental. `prefers-contrast` is supported from Chrome 96, Firefox 101 and Safari 14.1, and `forced-colors` from Chrome 89, Firefox 89 and Safari 16 ([MDN browser-compat-data](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-transparency)). Because Safari has no transparency query, also offer an in-app toggle that sets a `data-transparency="reduced"` attribute and mirror the same rules under it.

In Tailwind, `contrast-more:` and `forced-colors:` are built-in variants, but Tailwind 4.3.5 has none for reduced transparency, so define one once:

```css
@import "tailwindcss";
@custom-variant reduced-transparency (@media (prefers-reduced-transparency: reduce));
```

```html
<div class="bg-white/55 backdrop-blur-xl reduced-transparency:bg-white reduced-transparency:backdrop-blur-none contrast-more:border-black">
  Falls back to a solid white card
</div>
```

### Performance in one paragraph

Each blurred surface costs a render pass, and the cost grows with its area and blur radius. SheenUI's budget is at most 8 blurred surfaces in view, a 20px blur on level-2 glass and 32px on level 3, and no blur at all on tiny level-1 chips, which only use tint. For the reasons and how to measure on your own pages, read [the backdrop-filter performance guide](https://lokendra-builds.github.io/sheenui/guides/backdrop-filter-performance).

### Adding Motion: a pointer sheen, springs and reduced motion

A soft highlight that follows the pointer sells the glass. With `motion`, the pointer position lives in motion values, so moving the mouse never re-renders React:

```tsx
import { motion, useMotionTemplate, useMotionValue, useReducedMotion } from "motion/react";
import type { PointerEvent, ReactNode } from "react";

export function SheenCard({ children }: { children: ReactNode }) {
  const reduce = useReducedMotion();
  const x = useMotionValue(120);
  const y = useMotionValue(-40);
  const sheen = useMotionTemplate`radial-gradient(260px circle at ${x}px ${y}px, rgb(255 255 255 / 0.55), transparent 65%)`;

  function onPointerMove(event: PointerEvent<HTMLDivElement>) {
    if (reduce || event.pointerType === "touch") return;
    const box = event.currentTarget.getBoundingClientRect();
    x.set(event.clientX - box.left);
    y.set(event.clientY - box.top);
  }

  return (
    <motion.div
      onPointerMove={onPointerMove}
      whileHover={reduce ? undefined : { y: -2 }}
      transition={{ type: "spring", visualDuration: 0.22, bounce: 0.12 }}
      className="relative overflow-hidden rounded-2xl border border-white/60 bg-white/55 p-6 backdrop-blur-xl"
    >
      <motion.div aria-hidden style={{ background: sheen }} className="pointer-events-none absolute inset-0" />
      <div className="relative">{children}</div>
    </motion.div>
  );
}
```

`useReducedMotion` reports the operating system setting, so the lift and the sheen turn off for people who asked for less motion. Touch is skipped because a finger dragging across the card is scrolling, not hovering.

### When not to use glassmorphism

- **Dense data and long reading.** Tables, forms with many fields and body text are better on solid surfaces. Use glass for the frame around them.
- **Flat or white backgrounds.** There is nothing to blur, so you get a pale gray box with a cost.
- **Low-end devices and many panels.** A page full of blurred cards drops frames on weak GPUs. Use fewer, larger panels.
- **Text on small, busy areas.** If you cannot guarantee 4.5:1 over the worst backdrop point, use a solid surface.
- **Brand or product rules that need exact color.** Translucency changes color depending on what is behind it.

### Frequently asked questions

#### What is glassmorphism in React?

Glassmorphism in React is a UI style where a component looks like frosted glass: a translucent background, a `backdrop-filter: blur()` and a thin light border over a colorful backdrop. In React you apply it with a class or a styled component, and it only shows when something colorful sits behind it. This tutorial builds it in plain CSS, in Tailwind CSS v4 and as a typed `GlassCard`; the `.glass` rule near the top is the shortest version.

#### How do you make glassmorphism in React?

Give an element a semi-transparent background, a `backdrop-filter: blur()`, a light border and a vivid page behind it. In React that is a small component with a `className` and a level prop, as above. No library is required.

#### Does glassmorphism work with Tailwind CSS v4?

Yes. `bg-white/55`, `backdrop-blur-xl`, `backdrop-saturate-150` and `border-white/60` are core utilities. Tailwind 4.3.5 has no built-in variant for `prefers-reduced-transparency`, so define one with `@custom-variant`, as shown above.

#### Why is my backdrop-filter not blurring anything?

Most often an ancestor is a backdrop root (it has `opacity` below 1, a `filter`, a `mask` or `will-change` on one of those). The blur then ends at that ancestor. Remove the property from the wrapper and apply it to the glass element instead.

#### Is glassmorphism accessible?

It can be, if text keeps its contrast over the worst backdrop point and the surface turns solid for reduced transparency, more contrast and forced colors. Read the [accessible glassmorphism guide](https://lokendra-builds.github.io/sheenui/guides/accessible-glassmorphism). For the lens-like variant, see [Liquid Glass in CSS and React](https://lokendra-builds.github.io/sheenui/guides/liquid-glass-css-react).

## Liquid Glass CSS & React with Safari Fallback

Sidebar name: Liquid Glass in CSS and React

Liquid Glass CSS for React: Apple's iOS 26 look with an SVG displacement map, plus a frosted fallback for Safari and Firefox. Working code.

By Lokendra Singh Rathore. Published November 8, 2026, updated November 12, 2026.

Breadcrumb: [Home](https://lokendra-builds.github.io/sheenui/) > [Guides](https://lokendra-builds.github.io/sheenui/guides/) > Apple Liquid Glass in CSS and React

Liquid Glass CSS is possible on the web, with one big limit: the refraction part works in Chromium only. This guide builds the effect step by step with an SVG displacement map inside `backdrop-filter`, wraps it in a React component, and shows the frosted-glass fallback that Safari and Firefox get.

SheenUI is our library, so we also show its `LiquidGlass` component at the end. The live version is on the [Liquid glass effect page](https://lokendra-builds.github.io/sheenui/effects/liquid-glass).

### What Liquid Glass is, and how it differs from frosted glass

Apple announced Liquid Glass on 9 June 2025 for iOS 26, iPadOS 26 and macOS Tahoe 26. Apple describes the material as one that [reflects and refracts its surroundings](https://www.apple.com/newsroom/2025/06/apple-introduces-a-delightful-and-elegant-new-software-design/), with specular highlights that react to movement.

The practical difference from the older frosted style (see [our glassmorphism tutorial](https://lokendra-builds.github.io/sheenui/guides/glassmorphism-react-tutorial)) is this. Frosted glass only blurs what is behind it. Liquid Glass bends it, like a thick lens: the backdrop is shifted and magnified near the edges, and stays sharp in the middle. On the web we approximate that with a static map, not Apple's real-time rendering, so treat the result as a convincing imitation.

### How refraction works on the web

CSS has no "refract" function. The trick is `backdrop-filter` accepting a reference to an SVG filter, and one SVG primitive, [`feDisplacementMap`](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/feDisplacementMap), which moves pixels according to a second image.

For every output pixel P, the filter reads the input at `P + scale × (R − 0.5, G − 0.5)`, where R and G come from the map image at P. A mid-gray map pixel (128, 128) means no shift. So you draw a map that is gray in the middle of the lens and pushes pixels along the surface normal near the rim. The rim width is called the bezel.

### Quick answer

Liquid Glass in CSS is a `backdrop-filter` that points at an SVG displacement filter. The smallest version:

```css
.lens {
  border-radius: 28px;
  backdrop-filter: blur(14px) saturate(160%); /* frosted fallback: Safari, Firefox */
}

/* Only where refraction works: a script sets data-refraction on <html> in Chromium. */
[data-refraction] .lens {
  backdrop-filter: url(#liquid) saturate(150%);
}
```

The `#liquid` filter is an `feGaussianBlur` followed by an `feDisplacementMap` that reads a map image (step 2). It refracts in Chromium only. Safari and Firefox keep the frosted rule, and `@supports` cannot choose between them, because those engines report `url()` as supported, so engine detection sets `data-refraction` (see Browser support). The steps below build the map, the filter, the rim and the React component.

Basis: the refraction was confirmed in Chromium 156; we could not confirm the Safari and Firefox rendering ourselves, and the support data is from MDN browser-compat-data 8.1.8 (2 Nov 2026). First published 8 Nov 2026, last revised 12 Nov 2026.

### Step by step

#### 1. The displacement map

This function draws the map on a canvas for a rounded rectangle. It computes each pixel's distance in from the edge and the direction out of the shape, and pushes hardest at the edge, fading to nothing at the inner end of the bezel:

```tsx
// file: displacement-map.ts
export function createDisplacementMap(width: number, height: number, radius: number, bezel: number): string {
  const canvas = document.createElement("canvas");
  canvas.width = width;
  canvas.height = height;
  const ctx = canvas.getContext("2d");
  if (!ctx) return "";
  const image = ctx.createImageData(width, height);
  const hx = width / 2;
  const hy = height / 2;
  const r = Math.min(radius, hx, hy);
  for (let y = 0; y < height; y++) {
    for (let x = 0; x < width; x++) {
      const px = x + 0.5 - hx;
      const py = y + 0.5 - hy;
      // Signed distance to a rounded rectangle, and the direction pointing out of it.
      const qx = Math.abs(px) - (hx - r);
      const qy = Math.abs(py) - (hy - r);
      const outside = Math.hypot(Math.max(qx, 0), Math.max(qy, 0));
      const depth = r - outside - Math.min(Math.max(qx, qy), 0); // pixels in from the edge
      let nx = 0;
      let ny = 0;
      if (qx > 0 && qy > 0) {
        nx = (qx / outside) * Math.sign(px);
        ny = (qy / outside) * Math.sign(py);
      } else if (qx > qy) nx = Math.sign(px);
      else ny = Math.sign(py);
      const t = Math.min(Math.max(depth / bezel, 0), 1); // 0 at the edge, 1 where the flat top begins
      const strength = depth < 0 ? 0 : (1 - t) ** 3; // steep at the edge, fading to nothing
      const i = (y * width + x) * 4;
      image.data[i] = 128 + nx * strength * 127;
      image.data[i + 1] = 128 + ny * strength * 127;
      image.data[i + 2] = 128;
      image.data[i + 3] = 255;
    }
  }
  ctx.putImageData(image, 0, 0);
  return canvas.toDataURL();
}
```

The curve `(1 - t) ** 3` is a simple stand-in. SheenUI's own map derives the shift from a squircle profile and Snell's law for glass with an index of 1.5, which looks thicker.

#### 2. The SVG filter and the element

Save the map as an image (or set it from the function above) and reference it from `feImage`. A light blur first gives the frosted look, then the displacement bends it:


### Browser support and feature detection

| Engine | `backdrop-filter: blur()` | `backdrop-filter: url(#svg)` | What to ship |
|---|---|---|---|
| Chrome and Edge (Chromium) | Chrome 76, Edge 79 | Refracts (confirmed in Chrome 156) | The lens |
| Safari | 18 unprefixed, `-webkit-` since 9 | Accepted but, as reported, draws nothing | Frosted glass |
| Firefox | 103 | Accepted but, as reported, draws nothing | Frosted glass |

Blur support comes from [MDN browser-compat-data 8.1.8](https://developer.mozilla.org/en-US/docs/Web/CSS/backdrop-filter) (2 Nov 2026). For the last column, one developer reports that Safari parses `backdrop-filter: url(#f)` and [renders nothing, so the feature query lies](https://dev.to/devyatov/liquid-glass-on-the-web-6-ways-to-build-it-with-css-and-svg-3m07). We checked the part that matters for code: `CSS.supports("backdrop-filter", "url(#f)")` returned `true` in Playwright's Chromium 156, WebKit 27.2 and Firefox 159. So `@supports` cannot gate this. We could not confirm the blank rendering ourselves, because those WebKit and Firefox builds did not paint even a plain `blur()` backdrop in our automated screenshots on a Mac.

That leaves engine detection. Prefer `navigator.userAgentData` where it exists (Chromium only, per [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/userAgentData)) and fall back to the user agent string, excluding iOS browsers, which use WebKit:

```ts
// file: supports-refraction.ts
type BrandsNavigator = Navigator & { userAgentData?: { brands: { brand: string }[] } };

export function supportsRefraction(): boolean {
  if (typeof navigator === "undefined") return false;
  const brands = (navigator as BrandsNavigator).userAgentData?.brands;
  if (brands?.length) return brands.some((entry) => entry.brand === "Chromium");
  const ua = navigator.userAgent;
  return /\bChrom(e|ium)\/\d/.test(ua) && !/\b(CriOS|FxiOS|EdgiOS)\b/.test(ua);
}
```

In plain HTML and CSS, call it once at startup and let the stylesheet do the rest:

```ts
import { supportsRefraction } from "./supports-refraction";

if (supportsRefraction()) document.documentElement.dataset.refraction = "";
```

### The React component with its fallback

The component measures itself, draws a map at its own size, and applies the filter only when the engine supports it and the map exists. Otherwise it renders ordinary frosted glass:

```tsx
import { useEffect, useId, useState, useSyncExternalStore, type ComponentProps } from "react";
import { createDisplacementMap } from "./displacement-map";
import { supportsRefraction } from "./supports-refraction";

const subscribe = () => () => {};

type LensMap = { href: string; width: number; height: number };

export function RefractiveGlass({
  radius = 40,
  bezel = 32,
  scale = 44,
  style,
  children,
  ...props
}: ComponentProps<"div"> & { radius?: number; bezel?: number; scale?: number }) {
  const id = `lens-${useId().replace(/:/g, "")}`;
  const canRefract = useSyncExternalStore(subscribe, supportsRefraction, () => false);
  const [el, setEl] = useState<HTMLDivElement | null>(null);
  const [map, setMap] = useState<LensMap | null>(null);

  useEffect(() => {
    if (!canRefract || !el) return;
    const observer = new ResizeObserver(([entry]) => {
      const box = entry?.borderBoxSize[0];
      if (!box) return;
      const width = Math.round(box.inlineSize);
      const height = Math.round(box.blockSize);
      if (width > 1 && height > 1) setMap({ href: createDisplacementMap(width, height, radius, bezel), width, height });
    });
    observer.observe(el);
    return () => observer.disconnect();
  }, [canRefract, el, radius, bezel]);

  const filter = map ? `url(#${id}) saturate(150%)` : "blur(14px) saturate(160%)";

  return (
    <div
      ref={setEl}
      style={{ borderRadius: radius, WebkitBackdropFilter: "blur(14px) saturate(160%)", backdropFilter: filter, ...style }}
      {...props}
    >
      {map && (
        <svg aria-hidden="true" width="0" height="0" style={{ position: "absolute" }}>
          <filter id={id} colorInterpolationFilters="sRGB">
            <feGaussianBlur in="SourceGraphic" stdDeviation={2} edgeMode="duplicate" result="frost" />
            <feImage href={map.href} x={0} y={0} width={map.width} height={map.height} preserveAspectRatio="none" result="map" />
            <feDisplacementMap in="frost" in2="map" scale={scale} xChannelSelector="R" yChannelSelector="G" />
          </filter>
        </svg>
      )}
      {children}
    </div>
  );
}
```

This is a starting point, not production code. Drawing a map is per-pixel work, so a real component should cap the map size and throttle redraws while the element resizes. SheenUI caps maps at 240,000 pixels and redraws at most every 120 ms.

### Rules that keep it usable

- **One hero element, never body text.** Refraction distorts what is behind the glass. Use it on a button, a nav pill or a floating control, not on paragraphs.
- **Solid when transparency is off.** Reduced transparency, more contrast and forced colors should drop the lens for a solid surface. SheenUI's `LiquidGlass` does this by listening to all three media queries.
- **Budget the lenses.** Each lens runs an SVG filter per frame. SheenUI refracts at most 3 lenses at once; extra ones in view fall back to frosted glass until a slot frees.
- **Never animate size.** A new size means a new map. SheenUI only animates `scale` on hover and press.

### When not to use Liquid Glass

- **Safari, Firefox and iOS browsers.** They get frosted glass, not refraction. If the effect is the point of your design, you can't deliver it there.
- **Reading surfaces.** Refraction and body text fight each other. Use solid or frosted glass.
- **Many lenses on one page.** The cost is per lens, per frame. Use one or two.
- **Backgrounds with no detail.** A flat color shows nothing to bend.
- **Native apps.** This is DOM and SVG. In React Native, the native iOS 26 material is wrapped by libraries such as [`@callstack/liquid-glass`](https://github.com/callstack/liquid-glass) (version 0.8.2 on npm on 8 Nov 2026); check their platform limits yourself.

### Frequently asked questions

#### What is Liquid Glass in CSS and React?

Liquid Glass is Apple's glass material, announced on 9 June 2025 for iOS 26, iPadOS 26 and macOS Tahoe 26, which reflects and refracts what is behind it. On the web you build it with an SVG displacement map applied through `backdrop-filter` and wrap it in a React component. The refraction works in Chromium only; Safari and Firefox get frosted glass instead. SheenUI's `LiquidGlass` component packages this, with the fallback built in.

#### Why doesn't Liquid Glass work in Safari?

Safari supports `backdrop-filter` with `blur()` and similar functions (unprefixed since version 18), but, as reported, it does not render SVG filters referenced from `backdrop-filter`. The declaration parses, so `@supports` says yes. Detect the engine and serve frosted glass.

#### Does this work in React Native?

No. It relies on the DOM, CSS and SVG filters. React Native needs the native platform material, for example through a library like the one linked above.

#### Can I use Liquid Glass for a whole page layout?

You can, but you should not. Use it for one or two controls, and keep content on solid or frosted surfaces.

#### Does SheenUI support Firefox and Safari?

Yes, as frosted glass. `LiquidGlass` renders the same component there, with the refraction switched off.

## Glassmorphism Accessibility: Contrast & Fallbacks

Glassmorphism accessibility in React: WCAG contrast on glass, prefers-reduced-transparency, prefers-contrast, forced colors and reduced motion, with code.

By Lokendra Singh Rathore. Published November 8, 2026, updated November 12, 2026.

Breadcrumb: [Home](https://lokendra-builds.github.io/sheenui/) > [Guides](https://lokendra-builds.github.io/sheenui/guides/) > Accessible Glassmorphism

Glassmorphism accessibility comes down to two things: text keeps its contrast over the worst point of the backdrop, and the glass turns solid for people who ask for less transparency, more contrast or forced colors. Both are testable, and neither needs you to give up the look. This guide shows how we measure and how we respond, with code we ran against SheenUI's own docs pages.

SheenUI is our library, and where we cite numbers about it they come from its source or from scripts we ran on 8 Nov 2026. See the [Glass card page](https://lokendra-builds.github.io/sheenui/components/glass-card) for the surfaces we tested.

Basis: WCAG 2.2 and the Nielsen Norman Group review as linked, plus the measurement scripts shown in this guide, which the text says were run against SheenUI's own docs pages on 8 Nov 2026. First published 8 Nov 2026, last revised 12 Nov 2026; a revision date marks an edit of the text, not a new measurement run.

### Why glass UI fails real users

Nielsen Norman Group's review of the style says that if overused, [glassmorphism can pose significant accessibility and usability challenges](https://www.nngroup.com/articles/glassmorphism/). Its recommendations are to meet contrast requirements across every background area, to use more blur over intricate backgrounds, and to let users control contrast or transparency where feasible. It gives no contrast numbers, so we use WCAG's.

Three things go wrong in practice:

- **The background moves under the text.** Contrast is a property of a text and background pair. On glass the background is different at every pixel and can change while an animation plays.
- **Edges disappear.** WCAG 1.4.11 asks for [3:1 contrast for UI component boundaries](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html). A white 1px border on a light backdrop does not make it.
- **Some people cannot read through translucency at all.** That is a setting at the OS level, and your CSS can listen to it.

### Measuring contrast on glass

WCAG 2's [text contrast minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) is 4.5:1 for normal text and 3:1 for large text. To check it on glass, measure the worst pixel behind the text, not an average and not the CSS color.

First, do not rely on an automated checker alone. We ran axe-core 4.14.0 on the Glass card docs page. It reported 0 violations, but marked `color-contrast` as "needs review" on 208 nodes, because it cannot compute a ratio over gradients and backdrops:

```ts
// file: axe-run.ts

import axe from "axe-core";

const browser = await chromium.launch();
const page = await browser.newPage();
await page.goto("http://localhost:5180/sheenui/components/glass-card");
await page.addScriptTag({ content: axe.source });

const results = await page.evaluate(() => (globalThis as unknown as { axe: typeof import("axe-core") }).axe.run());
console.log("violations:", results.violations.length);
for (const item of results.incomplete) console.log("needs review:", item.id, item.nodes.length);
await browser.close();
```

So sample the pixels instead. This script hides an element's text, screenshots what is left (backdrop, tint and blur) and returns the lowest contrast ratio between the text color and any pixel:

```ts
// file: measure.ts
import { chromium, type Page } from "playwright";

type RGB = [number, number, number];

const channel = (v: number) => {
  const s = v / 255;
  return s <= 0.04045 ? s / 12.92 : ((s + 0.055) / 1.055) ** 2.4;
};
const luminance = ([r, g, b]: RGB) => 0.2126 * channel(r) + 0.7152 * channel(g) + 0.0722 * channel(b);
const ratio = (a: RGB, b: RGB) => {
  const [hi, lo] = [luminance(a), luminance(b)].sort((x, y) => y - x) as [number, number];
  return (hi + 0.05) / (lo + 0.05);
};

/** Worst-case contrast of an element's text over the pixels actually painted behind it. */
export async function worstContrast(page: Page, selector: string) {
  const target = page.locator(selector).first();
  // 1. The text color, converted to sRGB by a canvas (computed colors may be oklch()).
  const text = await target.evaluate((el): RGB => {
    const ctx = document.createElement("canvas").getContext("2d")!;
    ctx.fillStyle = getComputedStyle(el).color;
    ctx.fillRect(0, 0, 1, 1);
    const [r = 0, g = 0, b = 0] = ctx.getImageData(0, 0, 1, 1).data;
    return [r, g, b];
  });
  // 2. Hide the glyphs, so the screenshot shows only the backdrop, the tint and the blur.
  await target.evaluate((el) => el.setAttribute("style", `${el.getAttribute("style") ?? ""};color:transparent;text-shadow:none`));
  const png = (await target.screenshot()).toString("base64");
  await target.evaluate((el) => el.setAttribute("style", (el.getAttribute("style") ?? "").replace(";color:transparent;text-shadow:none", "")));
  // 3. Read every pixel and keep the lowest ratio.
  const pixels = await page.evaluate(async (data) => {
    const bitmap = await createImageBitmap(await (await fetch(`data:image/png;base64,${data}`)).blob());
    const canvas = new OffscreenCanvas(bitmap.width, bitmap.height);
    const ctx = canvas.getContext("2d")!;
    ctx.drawImage(bitmap, 0, 0);
    return Array.from(ctx.getImageData(0, 0, bitmap.width, bitmap.height).data);
  }, png);
  let worst = Infinity;
  for (let i = 0; i < pixels.length; i += 4) worst = Math.min(worst, ratio(text, [pixels[i] ?? 0, pixels[i + 1] ?? 0, pixels[i + 2] ?? 0]));
  return worst;
}

const browser = await chromium.launch();
for (const colorScheme of ["light", "dark"] as const) {
  const page = await browser.newPage({ colorScheme, viewport: { width: 1280, height: 900 } });
  await page.goto("http://localhost:5180/sheenui/components/glass-card");
  await page.waitForSelector('[data-slot="glass-card-description"]');
  console.log(colorScheme, (await worstContrast(page, '[data-slot="glass-card-description"]')).toFixed(2));
}
await browser.close();
```

On the Glass card docs page this printed 8.85:1 in light and 11.62:1 in dark for the muted description text. That is one element on one page at 1280 px, not a guarantee for every position of an animated backdrop. Take samples at several scroll positions and over the brightest and darkest part of your background.

SheenUI's token file documents the stricter version of this. Measured over its brightest backdrop blob, muted text reached 5.2:1 (light) bare and 6.7:1 on level-2 glass, and a control's 1px edge reached 3.1:1 in light and 3.6:1 in dark. The same notes record that its plain light-theme red and green status colors reach only about 2.1 and 1.5 against that backdrop as a control edge, so they are not used for borders. A measurement caught what looking would not.

Dark mode needs its own tint, not an inverted one. SheenUI's glass stylesheet records why: over the brightest part of a dark backdrop, a white frost lifted the background so far that status, accent and caption text on small glass dropped to about 3.3:1. The fix was a smoked tint, a dark translucent fill that darkens bright spots instead of lightening dark ones. If your dark theme uses white at low opacity, run the sampling script above in dark mode before you ship. SheenUI's [dark mode docs](https://lokendra-builds.github.io/sheenui/docs/dark-mode) show how the theme switch works, and the [Tailwind CSS v4 setup](https://lokendra-builds.github.io/sheenui/docs/tailwind-v4) shows how the glass tokens reach your classes.

### prefers-reduced-transparency, and an in-app toggle

`prefers-reduced-transparency: reduce` is the direct signal. It is experimental: Chrome and Edge 118 support it, Firefox only behind a flag from version 113, and Safari does not ([MDN browser-compat-data 8.1.8](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-transparency), 2 Nov 2026). Users enable the OS setting under Settings > Personalization > Colors > Transparency effects on Windows, System Settings > Accessibility > Display > Reduce transparency on macOS, and Accessibility > Display & Text Size > Reduce Transparency on iOS.

Because Safari cannot read it, add your own switch and mirror the rule under an attribute. In SheenUI, `useReducedTransparency` sets `data-transparency="reduced"` on `<html>` and stores it:

```tsx
import { useReducedTransparency } from "@/components/sheenui/hooks/use-preferences";
import { Switch } from "@/components/sheenui/switch/switch";
// Package build (after the first npm release, or a packed tarball): import { Switch, useReducedTransparency } from "@sheenui/theme";

export function TransparencySetting() {
  const [reduced, setReduced] = useReducedTransparency();
  return <Switch label="Reduce transparency" description="Show solid surfaces instead of glass." checked={reduced} onCheckedChange={setReduced} />;
}
```

The CSS for all the preferences in one place, in plain CSS you can adapt:

```css
:root {
  color-scheme: light dark;
  --glass-bg: light-dark(rgb(255 255 255 / 0.6), rgb(30 28 45 / 0.5));
  --glass-edge: light-dark(rgb(255 255 255 / 0.7), rgb(255 255 255 / 0.12));
  --solid: light-dark(white, rgb(34 32 50));
}

.glass {
  background: var(--glass-bg);
  border: 1px solid var(--glass-edge);
  -webkit-backdrop-filter: blur(20px) saturate(160%);
  backdrop-filter: blur(20px) saturate(160%);
}

.glass :focus-visible {
  outline: 2px solid;
  outline-offset: 2px;
}

@media (prefers-reduced-transparency: reduce) {
  .glass {
    background: var(--solid);
    -webkit-backdrop-filter: none;
    backdrop-filter: none;
  }
}

[data-transparency="reduced"] .glass {
  background: var(--solid);
  -webkit-backdrop-filter: none;
  backdrop-filter: none;
}

@media (prefers-contrast: more) {
  .glass {
    background: var(--solid);
    border-color: CanvasText;
  }
}

@media (forced-colors: active) {
  .glass {
    background: Canvas;
    border: 1px solid CanvasText;
    box-shadow: none;
    -webkit-backdrop-filter: none;
    backdrop-filter: none;
  }
}
```

### prefers-contrast: more

`prefers-contrast` is widely supported: Chrome 96, Firefox 101, Safari 14.1 ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-contrast)). `more` means the person wants stronger contrast, so replace the tint with a solid surface and give edges a full-contrast border, as above.

### forced-colors (Windows High Contrast)

In forced colors mode the browser replaces your colors with a system palette and, per [MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/forced-colors), forces `box-shadow` and `text-shadow` to none and removes non-URL `background-image`. Glass built from shadows and gradients loses its edge. The fix is a real border in system colors (`Canvas`, `CanvasText`), as in the last rule above. Support: Chrome 89, Firefox 89, Safari 16.

### Reduced motion for glass effects

Glass is often paired with moving backdrops, shimmer sweeps and pointer highlights. `prefers-reduced-motion` has been supported since Chrome 74, Firefox 63 and Safari 10.1. Stop ambient loops, drop parallax, and keep short fades. With Motion, `MotionConfig reducedMotion="user"` disables transform animations; see [Framer Motion examples](https://lokendra-builds.github.io/sheenui/guides/framer-motion-examples) for the pattern, and offer an in-app toggle as well.

### Focus rings and touch targets on glass

Focus indicators must survive translucency and forced colors. Use `outline`, not a `box-shadow` ring: shadows vanish in forced colors mode. Check the ring against the glass and the backdrop, not just the page (WCAG asks 3:1 for non-text contrast). Targets should be at least 24 by 24 CSS px under WCAG 2.2's [target size minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html); SheenUI grows controls to 44 px on touch screens.

### Checklist, and testing with axe and Playwright

- Text is 4.5:1 (3:1 if large) over the worst backdrop sample, measured from pixels.
- Control edges and focus rings reach 3:1.
- Glass becomes solid under reduced transparency, more contrast and forced colors, and in your in-app toggle.
- Motion stops under `prefers-reduced-motion`.
- Nothing depends on a shadow to be visible.

Automate the preference checks. Chromium can emulate the media features through the DevTools protocol. We ran this against the real SheenUI CSS and it printed what the comments say:

In Chrome 156 the three lines were a `blur(20px) saturate(1.9) brightness(1.05)` backdrop filter, then `none`, then `none`. Under `prefers-contrast: more` the same surface kept its blur declared but gained an opaque background and a dark border, which has the same effect.

### When not to use glass

If your audience includes many low-vision users, or the screen is dense with text, use solid surfaces by default and glass only as a decorative frame. Glass also needs a vivid, controlled background; over user-uploaded images you cannot guarantee any contrast. See [Liquid Glass in CSS and React](https://lokendra-builds.github.io/sheenui/guides/liquid-glass-css-react) for the most contrast-hostile variant, and [the tutorial](https://lokendra-builds.github.io/sheenui/guides/glassmorphism-react-tutorial) for the base recipe.

### Frequently asked questions

#### Is glassmorphism WCAG compliant?

It can be. WCAG does not forbid translucency; it asks for contrast ratios, which you can meet by using enough tint and by testing the worst backdrop sample. See the checklist above.

#### Does `prefers-reduced-transparency` work in Safari?

No. Safari does not support the media query. Provide an in-app toggle that sets an attribute your CSS also listens to.

#### How much blur is enough?

NN/g says more blur is better over intricate backgrounds. Blur alone does not guarantee contrast: tint does the work, and blur costs performance, so check [the performance guide](https://lokendra-builds.github.io/sheenui/guides/backdrop-filter-performance).

#### Can automated tools check glass contrast?

Not reliably. On our docs page axe-core flagged 208 contrast checks as needing review. Sample the rendered pixels as shown above.

## Glassmorphism vs Liquid Glass vs Neumorphism

URL: https://lokendra-builds.github.io/sheenui/guides/glassmorphism-vs-liquid-glass
Sidebar name: Glassmorphism vs Liquid Glass

Glassmorphism vs Liquid Glass vs Neumorphism: how each works in CSS, browser support, accessibility and cost, when to use which, with React code.

By Lokendra Singh Rathore. Published November 8, 2026, updated November 12, 2026.

Breadcrumb: [Home](https://lokendra-builds.github.io/sheenui/) > [Guides](https://lokendra-builds.github.io/sheenui/guides/) > Glassmorphism vs Liquid Glass vs Neumorphism

The short version of glassmorphism vs Liquid Glass: glassmorphism blurs what is behind a surface, Liquid Glass bends it like a lens, and neumorphism has no transparency at all, it extrudes shapes from a flat background with two shadows. They look related but they are different techniques, with different browser support, accessibility problems and costs.

Basis: browser support quoted from MDN browser-compat-data 8.1.8 (2 Nov 2026) and Apple's 9 June 2025 Liquid Glass announcement, as read while writing; first published 8 Nov 2026, last revised 12 Nov 2026.

This guide defines each, compares them in a table, and ends with a recommendation for product UI. We make a glass component library, SheenUI, so we have a bias toward glass; we say where it is the wrong tool.

### The three styles side by side

Here is each style in CSS. The glass and Liquid Glass rules need something colorful behind them; the neumorphic card needs the same flat color as its surroundings:

```css
/* Glassmorphism: blur what is behind */
.glassmorphic {
  background: rgb(255 255 255 / 0.55);
  -webkit-backdrop-filter: blur(20px) saturate(160%);
  backdrop-filter: blur(20px) saturate(160%);
  border: 1px solid rgb(255 255 255 / 0.6);
  border-radius: 20px;
}

/* Liquid Glass: bend what is behind (Chromium only; see the Liquid Glass guide) */
[data-refraction] .liquid {
  backdrop-filter: url(#liquid) saturate(150%);
}

/* Neumorphism: raise a shape out of a flat background */
.neumorphic {
  background: #e0e5ec;
  border-radius: 20px;
  box-shadow:
    8px 8px 16px #a3b1c6,
    -8px -8px 16px #ffffff;
}
```

And as React, using SheenUI for the first two. SheenUI is copy-the-source (the `@sheenui/theme` package is not on npm yet; the [install guide](https://lokendra-builds.github.io/sheenui/guides/install-frameworks) and the [installation page](https://lokendra-builds.github.io/sheenui/docs/installation) show the registry and copy routes, and the [Tailwind CSS v4 setup](https://lokendra-builds.github.io/sheenui/docs/tailwind-v4) the CSS it needs), and the [Glass card](https://lokendra-builds.github.io/sheenui/components/glass-card) and [Liquid glass](https://lokendra-builds.github.io/sheenui/effects/liquid-glass) pages show both live:

```tsx
import { GlassCard, GlassCardContent } from "@/components/sheenui/glass-card/glass-card";
import { LiquidGlass } from "@/components/sheenui/liquid-glass/liquid-glass";
// Package build (after the first npm release, or a packed tarball): import { GlassCard, GlassCardContent, LiquidGlass } from "@sheenui/theme";

export function ThreeStyles() {
  return (
    <div className="grid gap-6 bg-linear-to-br from-violet-500 via-fuchsia-400 to-amber-300 p-8 md:grid-cols-3">
      <GlassCard level={2}>
        <GlassCardContent>Glassmorphism: blurred backdrop</GlassCardContent>
      </GlassCard>
      <LiquidGlass className="p-6">Liquid Glass: refracted backdrop</LiquidGlass>
      <div className="rounded-2xl bg-[#e0e5ec] p-6 text-[#44476a] shadow-[8px_8px_16px_#a3b1c6,-8px_-8px_16px_#ffffff]">
        Neumorphism: extruded shape
      </div>
    </div>
  );
}
```

### Comparison table

| | Glassmorphism | Liquid Glass (web) | Neumorphism |
|---|---|---|---|
| Look | Frosted, translucent pane | A lens: refracted edges, specular rim | Soft shapes pushed out of a flat surface |
| CSS technique | `backdrop-filter: blur()` plus a tint and a lit border | SVG `feDisplacementMap` inside `backdrop-filter`, plus a rim | Two opposite `box-shadow`s on a matching background |
| Browser support | Chrome 76, Edge 79, Firefox 103, Safari 18 (`-webkit-` since 9) | Refraction in Chromium only; frosted fallback elsewhere | Everywhere `box-shadow` works |
| Accessibility risk | Contrast varies with the backdrop | Same, plus distortion at the edges | Edges are low contrast by design |
| Performance cost | A blur pass per surface (SheenUI budgets 8 in view) | An SVG filter pass per lens (SheenUI budgets 3 in view) | Static paint, no backdrop sampling |
| Best use | Cards, panels, nav bars, overlays | One or two hero controls | Decorative tiles; rarely interactive controls |

Support data is from [MDN browser-compat-data 8.1.8](https://developer.mozilla.org/en-US/docs/Web/CSS/backdrop-filter) (2 Nov 2026). The Liquid Glass row is explained in [Liquid Glass in CSS and React](https://lokendra-builds.github.io/sheenui/guides/liquid-glass-css-react).

### Glassmorphism (2020 onwards)

Glassmorphism is a translucent surface with a background blur. Nielsen Norman Group says it has been [gaining popularity since 2020](https://www.nngroup.com/articles/glassmorphism/) and notes that it is prominent in Apple's and Microsoft's design systems; Microsoft's Fluent "Acrylic" material is one example.

Four layers make it: a colorful backdrop, a tint, a blur and a lit border. The recipe, with working code, is in the [glassmorphism React tutorial](https://lokendra-builds.github.io/sheenui/guides/glassmorphism-react-tutorial). Its weak point is legibility: the background behind text changes with the page. NN/g's advice is to meet contrast everywhere the text sits, use more blur over busy backgrounds, and let users reduce transparency. The [accessibility guide](https://lokendra-builds.github.io/sheenui/guides/accessible-glassmorphism) shows how to measure and respond.

### Liquid Glass (Apple, 2025 onwards)

Apple introduced Liquid Glass on 9 June 2025 with iOS 26, iPadOS 26 and macOS Tahoe 26. Its press release calls it a translucent material that [reflects and refracts its surroundings](https://www.apple.com/newsroom/2025/06/apple-introduces-a-delightful-and-elegant-new-software-design/) and reacts to movement with specular highlights.

The key difference from glassmorphism is that the backdrop is displaced, not only blurred. On the web that means an SVG displacement map, which only Chromium honors inside `backdrop-filter`. Elsewhere you ship frosted glass. It is a hero effect: SheenUI limits itself to three refracting lenses in view at once. Apple's own version is rendered in real time across its operating systems; a web version is a static imitation of it.

### Neumorphism, claymorphism and Frutiger Aero

Neumorphism (soft UI) makes elements look extruded from the page. It appeared around 2019 and 2020; sources disagree on who named it, so we do not attribute it. It has no transparency, so none of the glass fallbacks apply. Its problem is contrast. In the palette above, the page color `#e0e5ec` against the dark shadow `#a3b1c6` is 1.72:1 and against the white highlight 1.27:1 (computed with the WCAG formula). WCAG 1.4.11 asks [3:1 for the boundaries of UI components](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html), so a neumorphic button's edge cannot pass unless you add an outline, which defeats the look.

Claymorphism is the inflated cousin: puffy, rounded shapes built from stacked inner and outer shadows, usually filled with saturated colors. Those fills sit against a contrasting page, so the boundary problem is smaller than with same-color neumorphism, but you still have to check it. Frutiger Aero refers to the glossy, aqua-gradient look of roughly the mid-2000s. We include it only because people compare it with Liquid Glass; it is a visual reference, not a technique.

### What each style needs from the rest of the page

Each style makes demands on its surroundings, and breaking them is the usual reason a demo looks good and a real page does not.

- **Glassmorphism** needs a varied backdrop behind the pane: a gradient, soft color blobs or an image. It also needs wrappers that leave the blur alone: an ancestor with `opacity` below 1, a `filter` or a `mask` becomes a backdrop root and the blur stops seeing the page ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/backdrop-filter)).
- **Liquid Glass** needs detail behind the lens (text, edges, photos), because refraction of a flat color shows nothing. It needs an engine check, a frosted fallback and a displacement map that matches the lens size.
- **Neumorphism** needs the element's fill to match its parent's exactly, because the two shadows imitate light on one continuous surface. Put it on a different background and the effect collapses into two odd shadows.

Light direction matters for all three. A rim highlight on the top left and a shadow on the bottom right read as one consistent light source; mixing directions between components makes a page feel broken even when each piece is fine.

### Which to choose for a product UI

- **Default: glassmorphism at small scale.** Use it for the frame around content (nav bars, dialogs, toasts, side panels), with solid surfaces for dense data. It works in every current browser.
- **Add Liquid Glass sparingly.** One or two controls, built with a frosted fallback, where the effect is the brand. Not for text blocks.
- **Use neumorphism for decoration only.** Avoid it on buttons, inputs and toggles unless you add visible, high-contrast boundaries.
- **Combine by role.** For instance a frosted card containing a solid table, with one refractive CTA pill.
- **Always provide the solid fallback.** Reduced transparency, more contrast and forced colors should turn any of them into plain surfaces.

### When not to use any of them

If your product is mostly forms, tables or long text, a flat design system with a single glass overlay will serve users better. If your audience skews toward low-end devices, avoid blur and refraction altogether, or ship a lite mode; see [the performance guide](https://lokendra-builds.github.io/sheenui/guides/backdrop-filter-performance). If brand consistency matters more than novelty, a trend-driven look will date.

### Frequently asked questions

#### What is Liquid Glass?

Apple's design material for iOS 26, iPadOS 26 and macOS Tahoe 26: translucent, with refraction and highlights that react to movement. On the web it is imitated with SVG filters.

#### Is Liquid Glass just glassmorphism?

No. Glassmorphism blurs the backdrop. Liquid Glass also distorts it near the edges, like a lens, and adds a specular rim.

#### Glassmorphism vs neumorphism: which is more accessible?

Neither is automatically accessible. Glass can pass WCAG with enough tint and measurement; neumorphism's boundaries usually fail the 3:1 rule for components, as computed above.

#### Can I use more than one style in the same interface?

Yes, by role: glass for chrome, solid for content, Liquid Glass for one hero control. Mixing neumorphism with glass is hard to make coherent, because glass needs a varied backdrop and neumorphism needs a flat one.

#### Does glassmorphism work in Safari and Firefox?

Yes. Safari supports unprefixed `backdrop-filter` from version 18 and Firefox from 103. Only the SVG-refraction variant of Liquid Glass does not carry over; see [the best libraries comparison](https://lokendra-builds.github.io/sheenui/guides/best-glassmorphism-react-libraries) for tools that handle the fallback.

## backdrop-filter Performance: Fast Glassmorphism

URL: https://lokendra-builds.github.io/sheenui/guides/backdrop-filter-performance
Sidebar name: backdrop-filter performance

backdrop-filter performance, measured: what blur costs, why a moving backdrop is the real problem, rules for fast glass, and a lite mode for weak devices.

By Lokendra Singh Rathore. Published November 8, 2026, updated November 14, 2026.

Breadcrumb: [Home](https://lokendra-builds.github.io/sheenui/) > [Guides](https://lokendra-builds.github.io/sheenui/guides/) > backdrop-filter Performance: Fast Glassmorphism

Backdrop-filter performance depends on one thing more than any other: how much of the screen is blurred while what is behind it changes. We measured this on a real machine instead of repeating folklore. On an Apple M1, with a static backdrop, 32 full-screen blurred layers held 60 fps. With a moving backdrop, 8 of them did not. If you are chasing backdrop-filter blur lag on scroll or drag, those numbers show where it starts. To try the rules in your own app, start from the [installation page](https://lokendra-builds.github.io/sheenui/docs/installation); the [Tailwind CSS v4 setup](https://lokendra-builds.github.io/sheenui/docs/tailwind-v4) shows how the glass tokens reach your Tailwind classes.

Basis: one set of measurements on an Apple M1 in headed Chrome 156, as reported in this guide (first published 8 Nov 2026, last revised 14 Nov 2026; the date of the measurement run itself is not recorded). Browser-support facts are quoted from MDN browser-compat-data 8.1.8 (2 Nov 2026).

This guide gives those numbers with their limits, the rules SheenUI follows because of them, and the code for a "lite glass" mode. The glass surfaces mentioned are on the [Glass card page](https://lokendra-builds.github.io/sheenui/components/glass-card) and the [Foundations page](https://lokendra-builds.github.io/sheenui/foundations).

### What backdrop-filter costs

A surface with `backdrop-filter` makes the browser take what is painted behind it, filter it, and draw the result under the element's own content. If anything behind it changes (an animated background, a scroll, a video), the filtered copy must be redone. So the work grows with the area filtered, the number of surfaces, and how often the backdrop changes.

Two related facts from [MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/backdrop-filter) shape the rules below. An ancestor with `opacity` below 1, a `filter`, a `mask`, a `clip-path` or a `mix-blend-mode` becomes a backdrop root, and the blur stops at it. And the property is baseline across browsers since September 2024.

#### What we measured

Setup: Apple M1, headed Chrome 156, a 1440 by 900 viewport at 2x device pixel ratio, a backdrop of six drifting gradient blobs animated on the compositor, and N glass panels (`blur(20px) saturate(160%)` over a faint white tint). Each configuration ran twice for 3 seconds after a 1.2 second warm-up; the table gives the range across the two runs. The Mac was shared with other jobs (load average 12 to 15), so read the shape, not the exact values.

| Configuration | fps |
|---|---|
| 1 or 4 full-viewport blurred layers, moving backdrop | 60 |
| 8 full-viewport layers | 44 to 50 |
| 16 full-viewport layers | 22 to 26 |
| 32 full-viewport layers | 12 to 13 |
| 8, 16 or 32 full-viewport layers, **static** backdrop | 60 |
| 24 panels of 400 by 300, moving backdrop | 60 |
| 1 full-viewport SVG lens (refraction) | 60 |
| 4 full-viewport SVG lenses | 32 to 38 |
| 8 full-viewport SVG lenses | 15 to 19 |
| 8 SVG lenses of 400 by 300 | 60 |

What this shows, for this machine:

- **Area and a changing backdrop drive the cost.** Sixteen full-screen layers were free when nothing behind them moved and cost more than half the frame rate when something did.
- **The number of small panels barely mattered.** 24 panels of 400 by 300 (about two screens of area) held 60 fps.
- **Refraction costs more per area.** Four full-viewport lenses fell to 32 to 38 fps, where four plain blurs held 60.
- **Blur radius made no measurable difference.** Eight full-viewport layers ran at 44 to 50 fps with a 20 px blur and the same with 80 px.
- **Animating the blur radius** from 8 to 40 px on eight 400 by 300 panels still held 60 fps on this GPU, so we cannot show a cost for it here.

What it does not show: any phone, any low-end GPU, Safari or Firefox. Our automated WebKit and Firefox builds did not paint `backdrop-filter` in screenshots at all, so we have no numbers for them. Treat our figures as a ranking of what hurts, and measure on your own target devices.

### Measuring on your own page

In Chrome, open DevTools and show the Rendering tab (Command Menu, then "Show Rendering", [per the DevTools docs](https://developer.chrome.com/docs/devtools/rendering)). Turn on Frame Rendering Stats for a live FPS meter, Paint flashing to see what repaints, and Layer borders to see compositing layers. Then record a Performance trace while scrolling and look at the frames lane.

To log numbers from code, this function records frame gaps over a window. We ran it in the benchmark page above:

```ts
export function measureFrames(ms = 3000): Promise<{ fps: number; p95: number; slowFrames: number }> {
  return new Promise((resolve) => {
    const stamps: number[] = [];
    const tick = (t: number) => {
      stamps.push(t);
      if (t - (stamps[0] ?? t) < ms) {
        requestAnimationFrame(tick);
        return;
      }
      const gaps = stamps.slice(1).map((stamp, i) => stamp - (stamps[i] ?? stamp));
      const sorted = [...gaps].sort((a, b) => a - b);
      resolve({
        fps: Math.round((gaps.length / ms) * 10000) / 10,
        p95: sorted[Math.floor(sorted.length * 0.95)] ?? 0,
        slowFrames: gaps.filter((gap) => gap > 20).length,
      });
    };
    requestAnimationFrame(tick);
  });
}
```

Call it while the interaction you care about runs (a scroll, a hover). Frames over 20 ms are the ones people notice.

### Rules that follow

1. **Pause animated backdrops.** This was the largest lever in our test. A moving wallpaper forces every glass surface above it to re-filter each frame. Pause ambient loops when they leave the screen, when the tab is hidden, and on reduced motion. SheenUI's loops do all three.
2. **Count area, not elements.** A few large panels cost more than many small ones. SheenUI's budget is at most 8 blurred surfaces in view and at most 3 refracting lenses, and it drops the blur on the smallest level (its chips use a tint and a rim, no blur at all).
3. **Never blur inside a blur.** The outer surface already is a backdrop root, so a nested blur can only blur the outer surface's own tint. SheenUI turns off `backdrop-filter` for glass nested in glass.
4. **Keep the radius moderate for look and for weak GPUs.** We could not measure a radius effect on an M1, but strong blurs wash out color and we only tested one GPU. SheenUI uses 20 px for cards, 32 px for dialogs and bars, and 8 px in lite mode.
5. **Do not animate the blur radius.** We did not see a cost on this GPU, but there is no reason to pay for it: animate the opacity or transform of the glass element and keep the blur constant.
6. **Avoid fading wrappers.** Besides being a performance habit, it breaks the blur (backdrop root). Animate the glass element itself.
7. **Budget refraction separately.** Our four-lens result fits SheenUI's cap of 3 lenses at once, where a lens that scrolls away hands its slot to the next. Read [Liquid Glass in CSS and React](https://lokendra-builds.github.io/sheenui/guides/liquid-glass-css-react).
8. **Contain what you can.** `contain: paint` tells the browser an element's contents never paint outside its box, so it can skip them when the box is offscreen. We did not benchmark it, so use it where it is safe and measure the result.

### A lite-glass mode for weak devices

Give weak devices a cheaper surface, and let people choose it. In CSS it is an attribute on the root:

```css
[data-glass="lite"] .glass {
  -webkit-backdrop-filter: blur(8px);
  backdrop-filter: blur(8px) saturate(160%);
}
```

SheenUI decides automatically on three signals: 4 GB of device memory or less, 4 or fewer CPU cores, or the Save-Data hint, plus a measured fallback: under 45 fps over a 2-second window once the entrance has settled. A saved choice by the visitor always wins. A minimal version of the same idea:

```ts
type Hints = Navigator & { deviceMemory?: number; connection?: { saveData?: boolean } };

export function isWeakDevice(): boolean {
  const nav = navigator as Hints;
  return (
    (nav.deviceMemory !== undefined && nav.deviceMemory <= 4) ||
    (nav.hardwareConcurrency > 0 && nav.hardwareConcurrency <= 4) ||
    nav.connection?.saveData === true
  );
}

if (isWeakDevice()) document.documentElement.dataset.glass = "lite";
```

`deviceMemory` and the Save-Data hint exist in Chromium only (Chrome and Edge, not Firefox or Safari, per MDN browser-compat-data), so Safari and Firefox rely on the core count and your own toggle. With SheenUI the whole thing, including the visitor's switch, is two hooks:

```tsx
import { useAutoLiteGlass } from "@/components/sheenui/backdrop/auto-lite";
import { useGlassMode } from "@/components/sheenui/hooks/use-preferences";
import { Switch } from "@/components/sheenui/switch/switch";
// Package build (after the first npm release, or a packed tarball): import { Switch, useAutoLiteGlass, useGlassMode } from "@sheenui/theme";

export function GlassQuality() {
  useAutoLiteGlass();
  const [lite, setLite] = useGlassMode();
  return <Switch label="Lite glass" description="A cheaper blur for slower devices." checked={lite} onCheckedChange={setLite} />;
}
```

### Safari specifics

Safari supports unprefixed `backdrop-filter` from version 18 and the `-webkit-` prefix since version 9 ([MDN browser-compat-data 8.1.8](https://developer.mozilla.org/en-US/docs/Web/CSS/backdrop-filter), 2 Nov 2026), so ship both lines. SheenUI writes literal values in the prefixed line, because its source notes that older Safari ignored `var()` there. We did not measure real Safari hardware: test on an actual iPhone and Mac before you rely on any frame budget.

### Effect on INP

INP measures an interaction up to the moment the next frame is presented; web.dev lists [presentation delay](https://web.dev/articles/inp) as one of its three parts, and a good INP is 200 ms or less at the 75th percentile. A page that spends 40 ms per frame on blur can therefore make every interaction feel slower, even if your JavaScript is quick. Check INP on your own pages with real users or a field tool.

### Checklist

- Fewer than about 8 blurred surfaces in view, and no more than 3 lenses.
- Nothing behind the glass animates unless it has to, and it pauses off-screen.
- No `opacity`, `filter` or `mask` on ancestors of glass.
- A lite mode, automatic or manual, and a solid fallback for reduced transparency.
- Measured on a low-end phone, not only your laptop.

### When not to optimize, and the limits of these numbers

If your glass sits over a static background, our test suggests cost is small even at large sizes; you may never need lite mode. If your audience is on recent phones and your page has two or three panels, stop optimizing. The advice here matters for dashboards, hero sections with animated backdrops, and long pages full of cards. For an example of a page with many panels, see the [web analytics dashboard](https://lokendra-builds.github.io/sheenui/dashboards/web-analytics).

### Frequently asked questions

#### Why is my backdrop-filter laggy?

Usually because a large blurred area sits over something that changes every frame, such as an animated background, video or a scrolling list. Pause the movement, shrink the area, or reduce the number of layers.

#### Does a bigger blur radius make it slower?

Not measurably on our M1: 20 px and 80 px ran the same. It may on weaker GPUs, which we did not test.

#### Is backdrop-filter bad for mobile?

We did not measure phones. Use fewer and smaller surfaces, a lite mode and a real-device test. See [the accessibility guide](https://lokendra-builds.github.io/sheenui/guides/accessible-glassmorphism) for the solid fallbacks, which are also the cheapest surfaces.

#### Can I use `will-change: backdrop-filter`?

We did not benchmark it. It can create extra layers and memory use, so apply it only to a surface you have measured.

## Accessible React Charts with a Table Fallback

URL: https://lokendra-builds.github.io/sheenui/guides/accessible-react-charts
Sidebar name: Accessible React charts

Accessible React charts with a table fallback: color-blind-safe palettes, keyboard reading, screen-reader summaries, never relying on color. Tested code.

By Lokendra Singh Rathore. Published November 8, 2026, updated November 15, 2026.

Breadcrumb: [Home](https://lokendra-builds.github.io/sheenui/) > [Guides](https://lokendra-builds.github.io/sheenui/guides/) > Accessible React Charts

Accessible React charts need four things: colors that stay distinct for color-blind readers, a way to read values from the keyboard, a text summary for screen readers, and a table of the same data. Everything else, such as animation and tooltips, is decoration on top of those four. Every SheenUI chart ships a table fallback: the Chart / Table tabs switch to a real HTML table with the same values, so no number depends on color, hover or sight.

The table view is one prop on the card (the full example is in the table fallback section below):

```tsx fragment
// data and series as in the full example below
declare const data: ChartRow[];
declare const series: CompareSeries[];

<ChartCard title="Revenue by channel" table={<ChartTable data={data} index="month" series={series} />}>
  <LineChart data={data} index="month" series={series} aria-label="Monthly revenue by channel" />
</ChartCard>
```

This guide shows each rule with code, including a palette check we wrote and ran, and a keyboard test we ran against SheenUI's chart gallery on 8 Nov 2026. Read it as a chart accessibility checklist you can run against any library. SheenUI is our library; we say so wherever its behavior is the example. See the [charts gallery](https://lokendra-builds.github.io/sheenui/charts/) for the live versions.

Basis: the WCAG 2.2 criteria as linked, the palette check and the keyboard test described below (the text says the keyboard test was run against SheenUI's chart gallery on 8 Nov 2026) and SheenUI's own source. First published 8 Nov 2026, last revised 15 Nov 2026; a revision date marks an edit of the text, not a new test run.

### The four rules

1. **Color is never the only carrier.** WCAG's [Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) criterion says information cannot rest on color alone. Every series needs a second cue: a label, a legend key shape, a dash style.
2. **Keyboard reading.** Someone who cannot use a pointer must be able to move through the data points and hear or see each value.
3. **A summary and an accessible name.** A screen reader should hear what the chart is and what it shows before it reads any point.
4. **A table view.** A real `<table>` with the same values is the most reliable accessible view of any chart.

### Color-blind-safe palettes

Colorblind safe chart colors have to hold up in three ways: the colors must stand apart from each other for normal vision and for the common kinds of color-blindness, and each must have enough contrast against the chart surface.

SheenUI's token file defines eight categorical slots, assigned in a fixed order and never cycled; a ninth series is drawn in neutral gray, so you fold extra series into "Other". Its comments say the palette was validated with a lightness band, a chroma floor, color-blind separation of adjacent slots and a normal-vision floor, against its light (`#f6f6fa`) and dark (`#1d1e29`) surfaces. We did not reproduce those checks. Instead we wrote an independent one that you can run on any palette: contrast against the surface, and the distance between colors after simulating color-blindness with the matrices from [Machado, Oliveira and Fernandes (2009)](https://www.inf.ufrgs.br/~oliveira/pubs_files/CVD_Simulation/CVD_Simulation.html) at severity 1.0, measured in [OKLab](https://bottosson.github.io/posts/oklab/) and scaled by 100. The authors' page does not state the color space; we apply the matrices to linear sRGB, which is the usual convention, and another choice would shift the numbers slightly.

```ts
// file: palette-check.ts
type RGB = [number, number, number];

const palette = {
  light: ["#4a3aa7", "#eb6834", "#1baf7a", "#eda100", "#e87ba4", "#008300", "#2a78d6", "#e34948"],
  dark: ["#9085e9", "#d95926", "#199e70", "#c98500", "#d55181", "#008300", "#3987e5", "#e66767"],
};
const surface = { light: "#f6f6fa", dark: "#1d1e29" };

const cvd = {
  protan: [[0.152286, 1.052583, -0.204868], [0.114503, 0.786281, 0.099216], [-0.003882, -0.048116, 1.051998]],
  deutan: [[0.367322, 0.860646, -0.227968], [0.280085, 0.672501, 0.047413], [-0.01182, 0.04294, 0.968881]],
  tritan: [[1.255528, -0.076749, -0.178779], [-0.078411, 0.930809, 0.147602], [0.004733, 0.691367, 0.3039]],
} as const;

const toRgb = (hex: string): RGB => [1, 3, 5].map((i) => parseInt(hex.slice(i, i + 2), 16)) as RGB;
const toLinear = (v: number) => ((v /= 255) <= 0.04045 ? v / 12.92 : ((v + 0.055) / 1.055) ** 2.4);
const luminance = (c: RGB) => 0.2126 * toLinear(c[0]) + 0.7152 * toLinear(c[1]) + 0.0722 * toLinear(c[2]);
const contrast = (a: RGB, b: RGB) => {
  const [hi, lo] = [luminance(a), luminance(b)].sort((x, y) => y - x) as [number, number];
  return (hi + 0.05) / (lo + 0.05);
};

function oklab([r, g, b]: RGB): RGB {
  const [lr, lg, lb] = [toLinear(r), toLinear(g), toLinear(b)];
  const l = Math.cbrt(0.4122214708 * lr + 0.5363325363 * lg + 0.0514459929 * lb);
  const m = Math.cbrt(0.2119034982 * lr + 0.6806995451 * lg + 0.1073969566 * lb);
  const s = Math.cbrt(0.0883024619 * lr + 0.2817188376 * lg + 0.6299787005 * lb);
  return [
    0.2104542553 * l + 0.793617785 * m - 0.0040720468 * s,
    1.9779984951 * l - 2.428592205 * m + 0.4505937099 * s,
    0.0259040371 * l + 0.7827717662 * m - 0.808675766 * s,
  ];
}

function simulate(color: RGB, kind: keyof typeof cvd | "normal"): RGB {
  if (kind === "normal") return color;
  const linear = color.map(toLinear);
  return cvd[kind].map((row) => {
    const v = Math.min(1, Math.max(0, row[0] * linear[0]! + row[1] * linear[1]! + row[2] * linear[2]!));
    return Math.round((v <= 0.0031308 ? v * 12.92 : 1.055 * v ** (1 / 2.4) - 0.055) * 255);
  }) as RGB;
}

const distance = (a: RGB, b: RGB) => 100 * Math.hypot(...(oklab(a).map((v, i) => v - oklab(b)[i]!) as RGB));

for (const theme of ["light", "dark"] as const) {
  const colors = palette[theme].map(toRgb);
  console.log(`${theme}: contrast against ${surface[theme]}`, colors.map((c) => contrast(c, toRgb(surface[theme])).toFixed(1)).join(" "));
  for (const kind of ["normal", "protan", "deutan", "tritan"] as const) {
    const seen = colors.map((c) => simulate(c, kind));
    let worst = { pair: "", d: Infinity };
    for (let i = 0; i < seen.length; i++) {
      for (let j = i + 1; j < seen.length; j++) {
        const d = distance(seen[i]!, seen[j]!);
        if (d < worst.d) worst = { pair: `${i + 1}-${j + 1}`, d };
      }
    }
    const adjacent = Math.min(...seen.slice(1).map((c, i) => distance(seen[i]!, c)));
    console.log(`  ${kind}: closest pair ${worst.pair} at ${worst.d.toFixed(1)}, closest adjacent slots ${adjacent.toFixed(1)}`);
  }
}
```

Here is what it printed for SheenUI's eight slots (the "adjacent" column is the closest two neighboring slots; "any pair" is the closest of all 28):

| Theme and vision | Closest adjacent slots | Closest pair of any two slots |
|---|---|---|
| Light, normal | 19.6 | 7.1 (slots 2 and 8) |
| Light, protanopia | 9.1 | 3.3 (slots 2 and 6) |
| Light, deuteranopia | 9.2 | 5.7 (slots 2 and 8) |
| Light, tritanopia | 6.0 | 5.1 (slots 2 and 8) |
| Dark, normal | 19.3 | 7.1 (slots 2 and 8) |
| Dark, protanopia | 8.3 | 1.8 (slots 1 and 7) |
| Dark, deuteranopia | 9.3 | 1.5 (slots 3 and 5) |
| Dark, tritanopia | 8.6 | 2.9 (slots 2 and 5) |

Contrast against the surface, slots 1 to 8, was 7.9, 3.0, 2.6, 2.0, 2.5, 4.6, 4.1 and 3.7 in light and 5.3, 4.3, 4.9, 5.4, 4.2, 3.3, 4.5 and 5.1 in dark.

Read these honestly. Neighboring slots stay apart in every simulation, which is what a fixed-order palette can promise. But non-neighbors can nearly collide: in dark mode, slots 3 and 5 are 1.5 apart under deuteranopia, a very small distance. And on the light surface slots 2 to 5 fall under the 3:1 that [WCAG 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) asks for graphics, which SheenUI's own comments also note. So no categorical palette alone makes a chart accessible. That is the case for the next three rules, and for assigning each series a fixed slot so that filtering never recolors it.

### Never color alone: labels, patterns and icons

Give every series a second cue the reader can use without color:

- **Direct labels.** `LineChart` can label the end of each line (`endLabels`) when they do not collide, and `BarChart` can print values (`showValues`).
- **Shape and dash.** A previous-period line is dashed and muted, and legend keys are drawn as SVG, not CSS backgrounds, so they survive forced colors, where they also gain a `CanvasText` outline.
- **A legend that works.** Legend items name each series, and in SheenUI they are toggle buttons, so a reader can isolate one series.

SheenUI's bar, line and area charts do not use pattern fills (its heatmap and map hatch cells with missing data); where color cannot be enough it relies on the legend, direct labels and the table. If your chart has more than a few series, add patterns yourself.

### Keyboard reading and tooltips

React chart keyboard navigation should be one focus stop, with arrow keys moving through points. We checked how SheenUI's charts behave, against the live gallery:

```ts
// file: keyboard-check.ts
import { chromium } from "playwright";

const browser = await chromium.launch();
const page = await browser.newPage();
await page.goto("http://localhost:5180/sheenui/charts");
await page.waitForSelector('svg[aria-roledescription="chart"]');

const announced = () =>
  page.evaluate(() => [...document.querySelectorAll('[aria-live="polite"]')].map((el) => el.textContent?.trim()).filter(Boolean));

await page.locator('svg[role="figure"][tabindex="0"]').first().focus();
for (const key of ["ArrowRight", "ArrowRight", "End", "Escape"]) {
  await page.keyboard.press(key);
  await page.waitForTimeout(300);
  console.log(key, await announced());
}
await browser.close();
```

Each interactive chart is an `svg` with `role="figure"`, `aria-roledescription="chart"` and `tabindex="0"`. The accessible name is the chart title; the instructions ("Use left and right arrow keys to read values.") are its description (`aria-describedby`, a `<desc>` inside the svg). Inside a `ChartCard` with a `table`, `aria-details` points at the table view, the full text alternative. A chart that is not interactive is not a tab stop. ArrowRight announced "Aug 21: Organic $6,882, Organic (previous) $5,678, Paid $3,672, Paid (previous) $3,172" through a polite live region; End jumped to the last point and Escape cleared the selection. The tooltip showed the same values for sighted keyboard users, and the focus outline is a real `outline` that holds up in forced colors.

### Table fallback: a data table for every chart

The name should say what the chart is and give the headline facts. SheenUI's `Sparkline` generates a summary and appends it to your label; on the gallery page we read "Orders trend: 42 points, min 186, max 381, latest 267". A function that produces the same kind of label:

```ts
export function summarize(label: string, values: number[], format: (n: number) => string = String) {
  if (values.length === 0) return `${label}: no data`;
  const latest = values[values.length - 1] as number;
  return `${label}: ${values.length} points, min ${format(Math.min(...values))}, max ${format(Math.max(...values))}, latest ${format(latest)}`;
}
```

Then provide the table. In SheenUI, `ChartCard` takes a `table` prop and shows Chart and Table tabs; the table is a real `<table>` with a caption and header cells, and it scrolls inside a focusable region if it is wider than the card. SheenUI's chart docs say every chart has a table view:

```tsx
import { ChartCard } from "@/components/sheenui/charts/chart-parts/chart-card";
import { ChartTable } from "@/components/sheenui/charts/chart-parts/empty-table";
import { seriesLegend } from "@/components/sheenui/charts/chart-parts/legend-tooltip";
import { type ChartRow, type CompareSeries } from "@/components/sheenui/charts/chart-utils";
import { LineChart } from "@/components/sheenui/charts/line-chart";
// Package build (after the first npm release, or a packed tarball): import { ChartCard, ChartTable, LineChart, seriesLegend, type ChartRow, type CompareSeries } from "@sheenui/theme";

const data: ChartRow[] = [
  { month: "Jan", organic: 4200, paid: 1800 },
  { month: "Feb", organic: 4900, paid: 2100 },
  { month: "Mar", organic: 5600, paid: 2600 },
];
const series: CompareSeries[] = [
  { key: "organic", label: "Organic", color: 1 },
  { key: "paid", label: "Paid", color: 2 },
];
const usd = (n: number) => `$${n.toLocaleString("en")}`;

export function Revenue() {
  return (
    <ChartCard
      title="Revenue by channel"
      description="Monthly, US dollars"
      legend={seriesLegend(series, "line")}
      table={<ChartTable data={data} index="month" indexLabel="Month" series={series} format={usd} caption="Monthly revenue by channel" />}
    >
      <LineChart data={data} index="month" series={series} format={usd} aria-label="Monthly revenue by channel, organic and paid" endLabels />
    </ChartCard>
  );
}
```

The `aria-label` is required on the charts and names what is plotted. Use a descriptive one, not "Chart".

### Reduced motion for animated charts

Chart animation is fine until it plays on every update. Respect the OS setting, and keep the end state identical. In your own SVG charts, drop the entrance when motion is reduced:

```tsx
import { motion, useReducedMotion } from "motion/react";

export function Bars({ values }: { values: number[] }) {
  const reduce = useReducedMotion();
  const max = Math.max(...values, 1);
  return (
    <svg role="img" aria-label={`Bar chart, ${values.length} values, highest ${max}`} viewBox="0 0 100 40" className="h-40 w-full">
      {values.map((value, i) => {
        const height = (value / max) * 36;
        return (
          <motion.rect
            key={i}
            x={i * 10 + 1}
            y={40 - height}
            width={8}
            height={height}
            rx={1.5}
            fill="currentColor"
            initial={reduce ? false : { scaleY: 0 }}
            animate={{ scaleY: 1 }}
            style={{ originY: 1, transformBox: "fill-box" }}
            transition={reduce ? { duration: 0 } : { type: "spring", visualDuration: 0.4, bounce: 0.1, delay: i * 0.03 }}
          />
        );
      })}
    </svg>
  );
}
```

SheenUI's charts read both the OS setting and an in-app toggle through `useSheenReducedMotion`. More patterns are in [Framer Motion examples](https://lokendra-builds.github.io/sheenui/guides/framer-motion-examples).

### Testing

- **Color-blindness.** Chromium can emulate vision deficiencies through the DevTools Protocol ([`Emulation.setEmulatedVisionDeficiency`](https://chromedevtools.github.io/devtools-protocol/tot/Emulation/)). Screenshot your chart under `deuteranopia`, `protanopia` and `tritanopia`, and check that every series is still tellable from its neighbors and its legend.
- **Keyboard.** The script above is the model: focus, arrow through, read the announcement.
- **axe-core.** It catches missing names and roles, but cannot judge contrast over gradients; see [the accessible glassmorphism guide](https://lokendra-builds.github.io/sheenui/guides/accessible-glassmorphism) for pixel sampling.
- **Forced colors and zoom.** Emulate `forced-colors: active` and zoom to 400% at a 320 px width.

### When not to rely on these charts

A table view is not practical for thousands of points; offer a downloadable CSV and a summary of the key values instead (SheenUI's `ChartCard` has an `exportable` option for PNG, SVG and CSV). Eight colors is a hard ceiling for identification by color; past that, use labels. Complex chart types, such as Sankey or chord diagrams, need an extra written description of what the shape means. And a chart is the wrong tool for a single number: use text, or the [meter](https://lokendra-builds.github.io/sheenui/components/meter) for a level in a known range.

### Frequently asked questions

#### How do I add a table fallback to an accessible React chart?

Render a real HTML table with the same values and offer it beside the chart, so no number depends on color, hover or sight. In SheenUI, pass `table={<ChartTable ... />}` to `ChartCard`: it shows Chart and Table tabs, the table has a caption and header cells, and it scrolls inside a focusable region when it is wider than the card. With your own chart, add a `<table>` of the data and point the chart's `aria-details` at it.

#### How many colors can an accessible chart use?

As few as you can. Our check shows that even a carefully ordered eight-color palette can have close pairs for color-blind viewers, so beyond three or four series, rely on labels, direct values and the table.

#### Do I need a table for every chart?

Provide some text alternative for every chart. A table is the most complete one, and it also serves people who simply prefer numbers. SheenUI's docs say each of its charts has one.

#### Are red and green always a problem?

Red and green are the classic confusion pair, but our results show other combinations can collapse too, for example slots 3 and 5 in dark mode under deuteranopia. Test the actual pairs. How the theme switches between light and dark is in the [dark mode docs](https://lokendra-builds.github.io/sheenui/docs/dark-mode); the charts install as shown on the [installation page](https://lokendra-builds.github.io/sheenui/docs/installation).

#### Does axe-core check charts?

It checks names, roles and some contrast, but it cannot verify that a chart's data is understandable. Test with the keyboard and a screen reader. See the [charts gallery](https://lokendra-builds.github.io/sheenui/charts/) and the [heatmap](https://lokendra-builds.github.io/sheenui/charts/heatmap) and [pie chart](https://lokendra-builds.github.io/sheenui/charts/pie-chart) pages for how SheenUI handles their tables.
