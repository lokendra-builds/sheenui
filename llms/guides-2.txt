## Framer Motion Examples for React: 12 Patterns

12 Framer Motion examples for React in Motion (motion/react): springs, shared layouts, scroll reveals, drag, tilt, reduced motion. Copy-paste code.

By Lokendra Singh Rathore. Published November 8, 2026, updated November 15, 2026.

Breadcrumb: [Home](https://lokendra-builds.github.io/sheenui/) > [Guides](https://lokendra-builds.github.io/sheenui/guides/) > Framer Motion Examples: 12 Animated React Patterns

These 12 Framer Motion examples use the library under its current name, Motion, imported from `motion/react`. Each one is a complete component you can paste into a React 19 project: press and hover springs, a sliding tab pill, a morphing dialog, a toast stack, a number ticker, blur-in text, scroll reveal, drag to dismiss, 3D tilt, a magnetic button, dock magnification and staggered menus. The TypeScript samples in this guide are compiled by the repo's checks: against the installed `motion` package, and against SheenUI where they use it.

They come from the animation layer of SheenUI, our glass component library, which uses Motion 14.14.0. Where SheenUI ships the polished version, we link to its docs page.

Basis: patterns from the animation layer of SheenUI, Motion's upgrade guide, and package facts dated in the text (8 Nov 2026). First published 8 Nov 2026, last revised 15 Nov 2026; a revision date marks an edit of the text, not a new test run of every example.

### Motion vs Framer Motion

It is the same library under a new name. The npm package is now `motion`, React code imports from `motion/react`, and the old `framer-motion` package is still published: on 8 Nov 2026 both were at version 14.10.1, and `motion` depends on `framer-motion` at that exact version (checked with `npm view`). The [upgrade guide](https://motion.dev/docs/react-upgrade-guide) says to uninstall `framer-motion`, install `motion` and change imports to `motion/react`. For the full migration, see [Framer Motion to Motion](https://lokendra-builds.github.io/sheenui/guides/framer-motion-to-motion).

### Setup with React 19 and Tailwind CSS v4

```bash
npm install motion
```

Motion 14.14.0 (the version these examples run on) declares peer dependencies on React 18 or 19. Tailwind CSS v4 needs no extra setup (SheenUI's [Tailwind CSS v4 setup](https://lokendra-builds.github.io/sheenui/docs/tailwind-v4) covers the CSS if you use its components): the examples use ordinary utility classes, and Motion writes inline styles for transforms. To add the SheenUI versions of these effects to your app, follow the [installation page](https://lokendra-builds.github.io/sheenui/docs/installation).

### 12 patterns

Patterns 5, 9, 10 and 11 are driven by motion values: the counter or pointer position is written straight to the element's style, so React does not re-render on every frame. That is a SheenUI rule for all JavaScript-driven motion (see the performance numbers in the README): motion values, not React state per frame. Patterns 1 to 4, 7 and 12 are declarative and need no extra care. Each example is a separate file, so you can take one without the others.

#### 1. Press and hover springs

Springs tuned by `visualDuration` and `bounce` line up with how long the motion looks like it takes. A short, low-bounce spring suits controls:

```tsx
import { motion } from "motion/react";

export function PressButton() {
  return (
    <motion.button
      whileHover={{ y: -2 }}
      whileTap={{ scale: 0.97 }}
      transition={{ type: "spring", visualDuration: 0.22, bounce: 0.12 }}
      className="rounded-full border border-white/60 bg-white/55 px-5 py-2 backdrop-blur-xl"
    >
      Save
    </motion.button>
  );
}
```

SheenUI's [glass button](https://lokendra-builds.github.io/sheenui/components/button) is built on the same idea; its motion tokens also define a stiff press spring so the release rebounds a little.

#### 2. The shared-layout tab pill

Give the active tab a child with the same `layoutId` and Motion animates it from tab to tab:

```tsx
import { motion } from "motion/react";
import { useState } from "react";

const tabs = ["Overview", "Usage", "Billing"];

export function PillTabs() {
  const [active, setActive] = useState(tabs[0]);
  return (
    <div role="tablist" className="inline-flex gap-1 rounded-full bg-white/40 p-1 backdrop-blur-xl">
      {tabs.map((tab) => (
        <button key={tab} role="tab" aria-selected={tab === active} onClick={() => setActive(tab)} className="relative rounded-full px-4 py-1.5 text-sm">
          {tab === active && (
            <motion.span layoutId="pill" className="absolute inset-0 rounded-full bg-white/80" transition={{ type: "spring", visualDuration: 0.22, bounce: 0.12 }} />
          )}
          <span className="relative">{tab}</span>
        </button>
      ))}
    </div>
  );
}
```

This has no arrow-key navigation. The [Tabs component](https://lokendra-builds.github.io/sheenui/components/tabs) builds on Base UI Tabs for that.

#### 3. The morphing dialog

A card and a dialog that share a `layoutId` look like one element growing. Wrap the dialog in `AnimatePresence` so it can animate out:

```tsx
import { AnimatePresence, motion } from "motion/react";
import { useState } from "react";

export function MorphingCard() {
  const [open, setOpen] = useState(false);
  return (
    <>
      <motion.button layoutId="card" onClick={() => setOpen(true)} style={{ borderRadius: 16 }} className="bg-white/60 p-4 text-left">
        <motion.h3 layoutId="title">Release notes</motion.h3>
      </motion.button>
      <AnimatePresence>
        {open && (
          <motion.div layoutId="card" role="dialog" aria-modal="true" aria-labelledby="notes-title" style={{ borderRadius: 24 }} className="fixed inset-x-6 top-24 bg-white/90 p-6">
            <motion.h3 layoutId="title" id="notes-title">Release notes</motion.h3>
            <button onClick={() => setOpen(false)}>Close</button>
          </motion.div>
        )}
      </AnimatePresence>
    </>
  );
}
```

Motion's docs warn that layout animations use `transform: scale()` and can [distort children](https://motion.dev/docs/react-layout-animations); that is why the radius is set in `style`, where Motion corrects it. This sketch lacks a focus trap and Escape; the [Morphing dialog](https://lokendra-builds.github.io/sheenui/effects/morphing-dialog) adds both.

#### 4. The toast stack

`mode="popLayout"` lets the remaining toasts slide into the gap while one leaves:

```tsx
import { AnimatePresence, motion } from "motion/react";
import { useState } from "react";

export function Toasts() {
  const [ids, setIds] = useState<number[]>([]);
  return (
    <>
      <button onClick={() => setIds((list) => [...list, Date.now()])}>Notify</button>
      <ul aria-live="polite" className="fixed right-4 bottom-4 grid gap-2">
        <AnimatePresence mode="popLayout">
          {ids.map((id) => (
            <motion.li
              key={id}
              layout
              initial={{ opacity: 0, y: 16, scale: 0.96 }}
              animate={{ opacity: 1, y: 0, scale: 1 }}
              exit={{ opacity: 0, scale: 0.96, transition: { duration: 0.15 } }}
              className="rounded-xl bg-white/70 px-4 py-3 backdrop-blur-xl"
            >
              Saved <button onClick={() => setIds((list) => list.filter((x) => x !== id))}>Dismiss</button>
            </motion.li>
          ))}
        </AnimatePresence>
      </ul>
    </>
  );
}
```

Note the exit: shorter than the entrance and no overshoot. See the [Toast component](https://lokendra-builds.github.io/sheenui/components/toast) for swipe and hover-to-fan.

#### 5. The number ticker

Animate a motion value and render it directly. React never re-renders per frame:

```tsx
import { animate, motion, useInView, useMotionValue, useTransform } from "motion/react";
import { useEffect, useRef } from "react";

export function Ticker({ to }: { to: number }) {
  const ref = useRef<HTMLSpanElement>(null);
  const inView = useInView(ref, { once: true });
  const value = useMotionValue(0);
  const text = useTransform(value, (v) => Math.round(v).toLocaleString("en"));

  useEffect(() => {
    if (!inView) return;
    const controls = animate(value, to, { duration: 1.2, ease: [0.22, 1, 0.36, 1] });
    return () => controls.stop();
  }, [inView, to, value]);

  return <motion.span ref={ref} className="tabular-nums">{text}</motion.span>;
}
```

#### 6. Blur-in text

```tsx
import { motion } from "motion/react";

export function BlurIn({ children }: { children: string }) {
  return (
    <motion.h2
      initial={{ opacity: 0.2, filter: "blur(8px)" }}
      animate={{ opacity: 1, filter: "blur(0px)" }}
      transition={{ duration: 0.5, ease: [0.22, 1, 0.36, 1] }}
    >
      {children}
    </motion.h2>
  );
}
```

It starts at 0.2, not 0, on purpose; see the performance section. The [Blur in effect](https://lokendra-builds.github.io/sheenui/effects/blur-in) splits text by word.

#### 7. Scroll reveal

```tsx
import { motion } from "motion/react";
import type { ReactNode } from "react";

export function Reveal({ children }: { children: ReactNode }) {
  return (
    <motion.section
      initial={{ opacity: 0, y: 16 }}
      whileInView={{ opacity: 1, y: 0 }}
      viewport={{ once: true, margin: "0px 0px -10% 0px" }}
      transition={{ type: "spring", visualDuration: 0.55, bounce: 0.18 }}
    >
      {children}
    </motion.section>
  );
}
```

`once: true` stops it replaying and lets Motion release the observer.

#### 8. Drag to dismiss

```tsx
import { motion } from "motion/react";
import type { ReactNode } from "react";

export function SwipeCard({ onDismiss, children }: { onDismiss: () => void; children: ReactNode }) {
  return (
    <motion.div
      drag="x"
      dragConstraints={{ left: 0, right: 0 }}
      dragElastic={0.6}
      whileDrag={{ scale: 1.02 }}
      onDragEnd={(_, info) => {
        if (Math.abs(info.offset.x) > 120 || Math.abs(info.velocity.x) > 600) onDismiss();
      }}
      className="touch-pan-y rounded-xl bg-white/70 p-4"
    >
      {children}
    </motion.div>
  );
}
```

Dismissing on distance or velocity makes a quick flick count. Always offer a button too: dragging is not available to everyone.

#### 9. 3D tilt

```tsx
import { motion, useMotionValue, useSpring, useTransform } from "motion/react";
import type { PointerEvent, ReactNode } from "react";

const spring = { stiffness: 320, damping: 32, mass: 0.6 };

export function Tilt({ children }: { children: ReactNode }) {
  const px = useMotionValue(0.5);
  const py = useMotionValue(0.5);
  const rotateY = useSpring(useTransform(px, [0, 1], [-8, 8]), spring);
  const rotateX = useSpring(useTransform(py, [0, 1], [8, -8]), spring);

  function move(event: PointerEvent<HTMLDivElement>) {
    const box = event.currentTarget.getBoundingClientRect();
    px.set((event.clientX - box.left) / box.width);
    py.set((event.clientY - box.top) / box.height);
  }

  return (
    <motion.div onPointerMove={move} onPointerLeave={() => { px.set(0.5); py.set(0.5); }} style={{ rotateX, rotateY, transformPerspective: 800 }}>
      {children}
    </motion.div>
  );
}
```

SheenUI skips the 3D lean on phones: its source notes that a perspective transform on a blurred surface re-rasterizes the backdrop every frame. See the [Tilt card](https://lokendra-builds.github.io/sheenui/effects/3d-tilt-card).

#### 10. The magnetic button

```tsx
import { motion, useSpring } from "motion/react";
import type { PointerEvent, ReactNode } from "react";

const spring = { stiffness: 220, damping: 18, mass: 0.5 };
const pull = (offset: number) => Math.max(-6, Math.min(6, offset * 0.3));

export function Magnetic({ children }: { children: ReactNode }) {
  const x = useSpring(0, spring);
  const y = useSpring(0, spring);

  function move(event: PointerEvent<HTMLButtonElement>) {
    const box = event.currentTarget.getBoundingClientRect();
    x.set(pull(event.clientX - (box.left + box.width / 2)));
    y.set(pull(event.clientY - (box.top + box.height / 2)));
  }

  return (
    <motion.button onPointerMove={move} onPointerLeave={() => { x.set(0); y.set(0); }} style={{ x, y }} className="rounded-full bg-violet-600 px-6 py-3 text-white">
      {children}
    </motion.button>
  );
}
```

Cap the pull (6 px here). A larger pull makes the target hard to hit.

#### 11. Dock magnification

Scale icons by their distance from the pointer. `scale` is a transform, so it stays cheap, unlike animating `width`:

```tsx
import { motion, useMotionValue, useSpring, useTransform, type MotionValue } from "motion/react";
import { useRef } from "react";

function DockIcon({ mouseX, label }: { mouseX: MotionValue<number>; label: string }) {
  const ref = useRef<HTMLButtonElement>(null);
  const distance = useTransform(mouseX, (x) => {
    const box = ref.current?.getBoundingClientRect();
    return box ? x - (box.left + box.width / 2) : Infinity;
  });
  const scale = useSpring(useTransform(distance, [-120, 0, 120], [1, 1.6, 1]), { stiffness: 320, damping: 32, mass: 0.6 });
  return <motion.button ref={ref} aria-label={label} style={{ scale, originY: 1 }} className="size-12 rounded-xl bg-white/60" />;
}

export function Dock() {
  const mouseX = useMotionValue(Infinity);
  return (
    <div onPointerMove={(event) => mouseX.set(event.clientX)} onPointerLeave={() => mouseX.set(Infinity)} className="flex items-end gap-2">
      {["Mail", "Files", "Music"].map((label) => <DockIcon key={label} mouseX={mouseX} label={label} />)}
    </div>
  );
}
```

The [Dock](https://lokendra-builds.github.io/sheenui/effects/macos-dock) adds keyboard support and reduced-motion handling.

#### 12. Staggered menus

`delayChildren: stagger()` offsets each child's entrance, as shown in the [stagger docs](https://motion.dev/docs/stagger):

```tsx
import { motion, stagger } from "motion/react";

const list = { hidden: {}, visible: { transition: { delayChildren: stagger(0.05) } } };
const item = { hidden: { opacity: 0, y: 8 }, visible: { opacity: 1, y: 0 } };

export function Menu({ items }: { items: string[] }) {
  return (
    <motion.ul variants={list} initial="hidden" animate="visible">
      {items.map((label) => (
        <motion.li key={label} variants={item}>{label}</motion.li>
      ))}
    </motion.ul>
  );
}
```

Cap the total: SheenUI never spreads a group over more than 0.4 s, however many children there are.

### Choosing springs

Pick a spring by what is moving, not by feel on one screen. These are the four SheenUI uses, all defined by `visualDuration` (when the bulk of the motion is done) and `bounce`:

| Token | `visualDuration` | `bounce` | Use it for |
|---|---|---|---|
| `snappy` | 0.22 s | 0.12 | Controls: pills, toggles, indicators |
| `smooth` | 0.30 s | 0 | Overlays and layout reflow, no overshoot |
| `gentle` | 0.55 s | 0.18 | Large surfaces and reveals |
| `bouncy` | 0.40 s | 0.38 | Delight only: success, a badge count |

Two rules go with them. Exits are shorter than entrances and never overshoot (SheenUI uses 0.15 s with an ease-in curve). And a fade never springs: SheenUI's presets spring the transform and give the opacity its own short tween inside the same entrance.

If you would rather not copy numbers, the tokens and presets are exported, and they compile against `motion/react`:

```tsx
import { motion } from "motion/react";
import { useSheenReducedMotion } from "@/components/sheenui/hooks/use-preferences";
import { fadeUp, hoverLift, stagger } from "@/components/sheenui/motion/presets";
// Package build (after the first npm release, or a packed tarball): import { fadeUp, hoverLift, stagger, useSheenReducedMotion } from "@sheenui/theme";

export function Cards({ items }: { items: string[] }) {
  const reduced = useSheenReducedMotion();
  const variants = reduced ? fadeUp.reduced : fadeUp.full;
  return (
    <motion.ul variants={stagger()} initial="hidden" animate="visible">
      {items.map((label) => (
        <motion.li key={label} variants={variants} {...(reduced ? {} : hoverLift)}>
          {label}
        </motion.li>
      ))}
    </motion.ul>
  );
}
```

`fadeUp.reduced` keeps the opacity change and drops the movement, which is the reduced-motion rule from the next section in one line.

### Reduced motion done right

Motion has two tools. `MotionConfig reducedMotion="user"` follows the operating system setting and, per the [Motion docs](https://motion.dev/docs/react-accessibility), disables transform and layout animations while still animating values like opacity. `useReducedMotion()` returns a boolean for custom branches. Add an in-app toggle for people whose OS setting is not the whole story:

```tsx
import { MotionConfig } from "motion/react";
import { useMotionPreference } from "@/components/sheenui/hooks/use-preferences";
// Package build (after the first npm release, or a packed tarball): import { useMotionPreference } from "@sheenui/theme";
import type { ReactNode } from "react";

export function Providers({ children }: { children: ReactNode }) {
  const [appReduced] = useMotionPreference();
  return <MotionConfig reducedMotion={appReduced ? "always" : "user"}>{children}</MotionConfig>;
}
```

SheenUI's `SheenMotionProvider` wraps this and follows both settings live. Replace movement with a short fade, not with nothing.

### Performance: transform and opacity first

Motion's [performance docs](https://motion.dev/docs/performance) say that `transform` and `opacity` are cheapest to render in all browsers, and that animating layout is discouraged because it can take upwards of 100 ms. SheenUI's gate is stricter: only `transform` and `opacity` animate, apart from a short list of listed exceptions.

The `opacity: 0` trap matters on prerendered pages. Chromium [excludes elements with an opacity of 0](https://web.dev/articles/lcp) from Largest Contentful Paint, so a hero heading that fades in from 0 is not counted until it becomes visible. SheenUI's own SEO plan therefore says the H1 and subline must never start at `opacity: 0`.

### When not to animate

- Content people must read right away: skip entrance animations on the first headline.
- Long lists: animate the first screen, not all rows.
- Anything that repeats forever near text: it competes for attention and costs battery. Loops should pause when they leave the screen and when the tab is hidden.
- Layout animations on blurred surfaces: scaling a `backdrop-filter` element every frame is expensive.

### Frequently asked questions

#### Is it Framer Motion or Motion?

Motion, with `motion/react` as the React import. Many tutorials still say Framer Motion and import from `framer-motion`, which still works because that package is still published.

#### Do I need LazyMotion for these examples?

No. `LazyMotion` with the `m` component reduces bundle size; the [bundle size docs](https://motion.dev/docs/react-reduce-bundle-size) give about 5 kB initial instead of 43 kB for the `motion` component. See the migration guide above.

#### Why does my stagger or exit animation not run?

Exit animations need the element's parent to be an `AnimatePresence` and the element to have a stable `key`. Variants need the same variant names on parent and children.

#### Can I animate `height: auto`?

Yes, with the `layout` prop or by animating a wrapper, but measure the cost on blurred glass first.

## Framer Motion to Motion: Migrating to motion/react

URL: https://lokendra-builds.github.io/sheenui/guides/framer-motion-to-motion
Sidebar name: Framer Motion to Motion

Framer Motion to Motion migration: switch from framer-motion to the motion package and motion/react imports, with a codemod, Next.js notes and bundle size.

By Lokendra Singh Rathore. Published November 8, 2026, updated November 15, 2026.

Breadcrumb: [Home](https://lokendra-builds.github.io/sheenui/) > [Guides](https://lokendra-builds.github.io/sheenui/guides/) > Framer Motion Is Now Motion

Framer Motion renamed itself Motion, and moving over takes one package swap and one import change. The animation library for React is now called Motion, it is published on npm as `motion`, and React code imports from `motion/react` instead of `framer-motion`. The `motion` component API you already know stays the same. The TypeScript samples in this guide are compiled by the repo's checks: against the installed `motion` package, and against SheenUI where they use it.

This guide covers what changed, a small script that rewrites your imports, what to check for React 19 and Next.js, and how to cut bundle size with `LazyMotion`. We verified the package facts with `npm view` on 8 Nov 2026; the version SheenUI's components use is Motion 14.14.0. For examples after you migrate, see [12 Framer Motion examples](https://lokendra-builds.github.io/sheenui/guides/framer-motion-examples).

Basis: Motion's upgrade guide, package facts from npm dated in the text (8 Nov 2026, and the re-check of Motion 14.14.0 dated 15 Nov 2026), and the Motion version SheenUI's components use. First published 8 Nov 2026, last revised 15 Nov 2026; a revision date does not mean every fact was re-checked that day.

### What changed: the name, the package and the import path

| Before | Now |
|---|---|
| `npm install framer-motion` | `npm install motion` |
| `import { motion } from "framer-motion"` | `import { motion } from "motion/react"` |
| `framer-motion/m` | `motion/react-m` |
| `framer-motion/client` | `motion/react-client` |

Motion's [upgrade guide](https://motion.dev/docs/react-upgrade-guide) says to uninstall `framer-motion`, install `motion` and import from `motion/react`. The two packages are not separate code bases. We re-checked the installed `motion` 14.14.0 on 15 Nov 2026: `motion/react` is the single line `export * from 'framer-motion'`, `motion/react-client` re-exports `framer-motion/client` and `motion/react-m` re-exports `framer-motion/m`. `motion` also depends on `framer-motion` at exactly the same version (14.14.0). SheenUI's peer range starts at `^14.10.1`; 14.14.0 is the version this guide was checked against.

The `motion` package has more entry points than React alone. Its `exports` include `motion/react`, `motion/react-client`, `motion/react-m`, `motion/react-mini`, `motion/react-animate-view`, `motion/mini` and the vanilla JavaScript entry `motion`.

One naming trap: versions of `motion` up to 10.18.0 were a different library. npm shows 10.18.0 depending on `@motionone/*` packages, and the next published version is 11.11.12. If an old tutorial tells you to install `motion@10`, it means the vanilla Motion One library, not this one.

### Install, then search and replace the imports

```bash
npm uninstall framer-motion
npm install motion
```

In a monorepo, change every package in one pull request so the workspace resolves a single copy, and commit the updated lockfile so CI installs the same versions you tested. Then rewrite the imports. A search and replace for `"framer-motion"` to `"motion/react"` is enough for most projects. This script does it across a folder, including dynamic `import()` and `require()` calls, and leaves everything else alone:

```js
// codemod.mjs, run with: node codemod.mjs src
import { readdirSync, readFileSync, statSync, writeFileSync } from "node:fs";
import { join } from "node:path";

const root = process.argv[2] ?? "src";
/** @type {string[]} */
const files = [];

/** @param {string} dir */
function walk(dir) {
  for (const name of readdirSync(dir)) {
    const path = join(dir, name);
    if (statSync(path).isDirectory()) {
      if (name !== "node_modules") walk(path);
    } else if (/\.(tsx?|jsx?|mdx?)$/.test(name)) {
      files.push(path);
    }
  }
}

walk(root);

let changed = 0;
for (const file of files) {
  const source = readFileSync(file, "utf8");
  const output = source
    .replace(/(from\s+|import\s*\(\s*|require\(\s*)(["'])framer-motion\/m\2/g, "$1$2motion/react-m$2")
    .replace(/(from\s+|import\s*\(\s*|require\(\s*)(["'])framer-motion\/client\2/g, "$1$2motion/react-client$2")
    .replace(/(from\s+|import\s*\(\s*|require\(\s*)(["'])framer-motion\2/g, "$1$2motion/react$2");
  if (output !== source) {
    writeFileSync(file, output);
    changed++;
  }
}
console.log(`updated ${changed} of ${files.length} files`);
```

We ran it on a sample folder with static, dynamic and `require` imports and it rewrote all of them. Commit before you run it, then check the diff. Other entry points, such as `framer-motion/dom`, have no one-to-one rename: look them up in the upgrade guide.

Afterwards, run `npm ls framer-motion`. Libraries in your tree that depend on `framer-motion` themselves may pull in a second copy at a different version. That usually does not break anything, but it adds weight to your bundle.

### Verify the migration

A short checklist after the swap:

1. `npm ls framer-motion` should list one version, the one `motion` depends on. Extra copies from third-party libraries are fine, but note them.
2. Search your source for the old name (`grep -rn "framer-motion" src`). Only intentional leftovers, such as `framer-motion-3d` or `framer-motion/dom`, should remain.
3. Run `tsc --noEmit`. In our check, `motion/react` resolved under TypeScript 6.0.3 with `moduleResolution` set to `node10`, `bundler` and `nodenext`, so you do not need to change your tsconfig.
4. Open the pages with the most animation and check exits, shared layouts and gestures by hand. Automated tests rarely catch a changed spring.
5. Test reduced motion: turn on the OS setting and confirm that transforms stop (see [the examples guide](https://lokendra-builds.github.io/sheenui/guides/framer-motion-examples)).
6. Compare your bundle before and after with your bundler's analyzer. If the `motion` component is a large share, consider `LazyMotion` below.

### What stays the same

The component API: `motion.div`, `animate`, `initial`, `exit`, `variants`, `layout`, `layoutId`, `AnimatePresence`, `useMotionValue`, `useScroll` and the rest. According to the upgrade guide, versions 12.0 and 14.0 had no breaking changes for Motion for React; 14.0 deprecated some internal APIs and made versioning between internal dependencies stricter.

If you are jumping from an older Framer Motion, these are the changes that can bite. They are from the guide, listed by the release that introduced them:

| Version | Change |
|---|---|
| 7.0 | Requires React 18 or later |
| 9.0 | Tap-enabled elements get `tabindex="0"`; `whileFocus` follows `:focus-visible` |
| 10.0 | The `IntersectionObserver` fallback for `whileInView` is removed; `exitBeforeEnter` on `AnimatePresence` now throws, use `mode="wait"` |
| 11.0 | `MotionValue` velocity calculation changed; the initial render moves to a microtask, so Jest tests may need to await an animation frame |
| 13.0 | `@emotion/is-prop-valid` is no longer an optional dependency; Styled Components and Emotion users may need `MotionConfig`'s `isValidProp` |

Current peer dependencies are React `^18.0.0 || ^19.0.0` (read from the installed package).

### React 19 and Next.js

In the Next.js App Router, anything that uses hooks or event handlers must be a client component. Put `"use client"` at the top of files that import from `motion/react`. For a Server Component that only needs static initial and animate props, import from `motion/react-client`:

```tsx
import * as motion from "motion/react-client";

export default function Page() {
  return (
    <motion.h1 initial={{ opacity: 0.2, y: 12 }} animate={{ opacity: 1, y: 0 }}>
      Hello
    </motion.h1>
  );
}
```

Motion's upgrade page does not discuss Next.js; the `react-client` entry above is documented only by the package's own exports. Check Motion's current Next.js notes before relying on it in production. Hooks such as `useReducedMotion`, `useScroll` and `AnimatePresence` still need a client component. Every SheenUI component that uses Motion begins with `"use client"` for this reason.

### Bundle size: LazyMotion and m

The `motion` component cannot be tree-shaken below roughly 43 kB, according to Motion's [bundle size docs](https://motion.dev/docs/react-reduce-bundle-size). Using the lighter `m` component with `LazyMotion` brings the initial render to just over 5 kB, and you add features as needed: `domAnimation` (about +24 kB) covers animations, variants, exit animations and tap, hover and focus gestures; `domMax` (about +38 kB) adds drag and layout animations. The figures come from Rollup builds; Webpack output is slightly larger.

```tsx
import { LazyMotion, domAnimation } from "motion/react";
import * as m from "motion/react-m";
import type { ReactNode } from "react";

export function Fade({ children }: { children: ReactNode }) {
  return (
    <LazyMotion features={domAnimation} strict>
      <m.div initial={{ opacity: 0 }} animate={{ opacity: 1 }}>
        {children}
      </m.div>
    </LazyMotion>
  );
}
```

With `strict`, a plain `motion` component inside the provider throws, which keeps you from accidentally pulling in the full bundle. To load the features after the first render, pass an async function:

```ts
// file: features.ts
import { domMax } from "motion/react";

export default domMax;
```

```tsx
import { LazyMotion } from "motion/react";
import * as m from "motion/react-m";
import type { ReactNode } from "react";

const loadFeatures = () => import("./features").then((module) => module.default);

export function Card({ children }: { children: ReactNode }) {
  return (
    <LazyMotion features={loadFeatures}>
      <m.div layout drag="x">
        {children}
      </m.div>
    </LazyMotion>
  );
}
```

Remember that layout animations and drag need `domMax`, not `domAnimation`.

### When not to migrate (yet)

- **You are pinned to an old major.** If you are on React 16 or 17 and framer-motion below 7, jumping straight to Motion 14 means upgrading React first.
- **Your dependencies still use `framer-motion`.** Migrating your own code is fine, but you will carry two import names until they update. They resolve to the same library at the same version when the versions match.
- **You have no reason to touch it.** The old package is still published, so a working project does not have to change the import line this week.

### Frequently asked questions

#### How do I migrate from Framer Motion to Motion?

Uninstall `framer-motion`, install `motion`, and change each import from `framer-motion` to `motion/react` (`framer-motion/m` becomes `motion/react-m`, `framer-motion/client` becomes `motion/react-client`). The `motion` component API stays the same, and Motion's upgrade guide lists no breaking changes for React in 12.0 and 14.0. The script above rewrites the imports for you; then run your build and tests.

#### Is framer-motion still published?

Yes, as of 8 Nov 2026. The npm registry's [`framer-motion` record](https://registry.npmjs.org/framer-motion/latest) and [`motion` record](https://registry.npmjs.org/motion/latest) both showed 14.10.1 as the latest version with no deprecation message, and `npm view` lists both packages as last modified on 6 Nov 2026. Check again on the day you migrate.

#### Do I have to change anything besides the imports?

Not if you are already on a recent version. The upgrade guide lists no breaking changes for React in 12.0 and 14.0. If you are coming from an older release, check the table above.

#### Does Motion work with React 19 and Tailwind CSS v4?

Yes. Its peer dependencies allow React 18 or 19, and SheenUI ships React 19.2+ components animated with Motion 14.14.0 and styled with Tailwind CSS v4 (see the [Tailwind CSS v4 setup](https://lokendra-builds.github.io/sheenui/docs/tailwind-v4) and the [installation page](https://lokendra-builds.github.io/sheenui/docs/installation)). #### Is Motion for vanilla JavaScript the same package?

The `motion` package exposes both: the React API under `motion/react` and the vanilla `animate()` function from `motion`.

### API differences: `render` vs `asChild`

Both libraries let you replace the element a part renders. Radix uses the `asChild` boolean and clones the single child; Base UI uses a `render` prop that takes an element or a function. In both cases your component must spread the received props onto its DOM node and forward the ref.

The Base UI example compiles against `@base-ui/react` 1.9.0 and React 19 (where `ref` is a normal prop):

```tsx
import type { ComponentProps } from "react";
import { Dialog } from "@base-ui/react/dialog";

// Base UI passes props and ref through `render`; the element only has to spread them.
function GlassButton(props: ComponentProps<"button">) {
  return <button className="glass-button" {...props} />;
}

export function BaseUiExample() {
  return (
    <Dialog.Root>
      <Dialog.Trigger render={<GlassButton />}>Open</Dialog.Trigger>
      <Dialog.Portal>
        <Dialog.Backdrop className="scrim" />
        <Dialog.Popup className="glass-dialog">
          <Dialog.Title>Edit profile</Dialog.Title>
          <Dialog.Description>Changes are saved when you press Save.</Dialog.Description>
          <Dialog.Close render={<GlassButton />}>Close</Dialog.Close>
        </Dialog.Popup>
      </Dialog.Portal>
    </Dialog.Root>
  );
}
```

The Radix version, verified separately with `radix-ui@1.8.1`, React 19 and `tsc`:

```tsx external
import { forwardRef, type ComponentPropsWithoutRef } from "react";
import { Dialog } from "radix-ui";

// asChild only works when the child spreads its props and forwards its ref.
const GlassButton = forwardRef<HTMLButtonElement, ComponentPropsWithoutRef<"button">>(
  function GlassButton(props, ref) {
    return <button ref={ref} className="glass-button" {...props} />;
  },
);

export function RadixExample() {
  return (
    <Dialog.Root>
      <Dialog.Trigger asChild>
        <GlassButton>Open</GlassButton>
      </Dialog.Trigger>
      <Dialog.Portal>
        <Dialog.Overlay className="scrim" />
        <Dialog.Content className="glass-dialog">
          <Dialog.Title>Edit profile</Dialog.Title>
          <Dialog.Description>Changes are saved when you press Save.</Dialog.Description>
          <Dialog.Close asChild>
            <GlassButton>Close</GlassButton>
          </Dialog.Close>
        </Dialog.Content>
      </Dialog.Portal>
    </Dialog.Root>
  );
}
```

Two further Base UI features have no Radix equivalent. `render` also accepts a function `(props, state) => element`, so you can read state (the docs show `state.checked` on `Switch.Thumb`) and decide what to render. And `className` and `style` accept functions of the same state, for example `className={(state) => (state.checked ? "checked" : "unchecked")}` ([Base UI styling handbook](https://base-ui.com/react/handbook/styling)). Radix exposes state through data attributes only.

### Why SheenUI chose Base UI

SheenUI (ours) depends on `@base-ui/react` 1.9.0, and the reasons are visible in `theme/src/components`:

- The `render` prop is how every trigger takes a glass button: `DialogTrigger` and `DialogClose` are re-exports of `BaseDialog.Trigger` and `BaseDialog.Close`, and the docs show `<DialogTrigger render={<Button>Edit profile</Button>} />`. See the [Dialog page](https://lokendra-builds.github.io/sheenui/components/dialog) and the [Button page](https://lokendra-builds.github.io/sheenui/components/button).
- Dialog, Tabs, Field and Menu parts map directly onto Base UI parts. `dialog.tsx` wraps `BaseDialog.Popup`, `Title` and `Description`; `tabs.tsx` wraps `BaseTabs.Root`, `List`, `Tab`, `Indicator` and `Panel`; `@base-ui/react/field` is used by the input, textarea, number field and radio group; `@base-ui/react/menu` by the menu, menubar, breadcrumb and data table.
- The Tabs indicator uses Base UI's CSS variables. `TabsList` renders `BaseTabs.Indicator` with `h-(--active-tab-height) w-(--active-tab-width) translate-x-(--active-tab-left)`, so the sliding glass pill is pure CSS with no JavaScript animation. Base UI documents `--active-tab-top`, `--active-tab-right`, `--active-tab-bottom`, `--active-tab-left`, `--active-tab-width` and `--active-tab-height` on `Tabs.Indicator` ([Base UI Tabs](https://base-ui.com/react/components/tabs)). Radix Tabs has no indicator part. See the [Tabs page](https://lokendra-builds.github.io/sheenui/components/tabs).
- Dialog animations are CSS keyed on `data-starting-style` and `data-ending-style`, which Base UI sets on the popup itself. Animating the glass popup directly (never a wrapper) is what keeps the blur from flickering.

### Migration notes

Concrete differences, each checked against the two docs sites on 8 Nov 2026.

Package imports:

- `import { Dialog } from "radix-ui"` (or `"@radix-ui/react-dialog"`) becomes `import { Dialog } from "@base-ui/react/dialog"`. Each Base UI component has its own subpath.

Composition:

- `<Dialog.Trigger asChild><MyButton /></Dialog.Trigger>` becomes `<Dialog.Trigger render={<MyButton />}>label</Dialog.Trigger>`. Children move onto the trigger. With React 19 the custom component no longer needs `forwardRef`, but it still has to spread props.

Part names (Dialog):

- Radix `Overlay`, `Content` become Base UI `Backdrop`, `Popup`. Base UI adds an optional `Viewport` ("a positioning container for the dialog popup that can be made scrollable"). `Root`, `Trigger`, `Portal`, `Title`, `Description`, `Close` keep their names.

Part names (Tabs):

- Radix `Trigger`, `Content` become `Tab`, `Panel`; Base UI adds `Indicator`.

Data attributes:

- Radix Dialog Content: `data-state="open" | "closed"`. Base UI Popup: `data-open`, `data-closed`, plus `data-starting-style` and `data-ending-style` for enter and exit animations, and `data-nested`, `data-nested-dialog-open`.
- Radix Tabs Trigger: `data-state="active" | "inactive"`. Base UI Tab: `data-active` (present when active). Both use `data-disabled` and `data-orientation`.
- Tailwind selectors change accordingly: `data-[state=open]:` becomes `data-open:`, `data-[state=active]:` becomes `data-active:`.

Renamed components:

- Hover Card becomes Preview Card; Dropdown Menu becomes Menu; One-Time Password Field becomes OTP Field; Label becomes `Field.Label` inside `Field.Root`.

Animations:

- Radix exit animations key on `data-state="closed"`. Base UI sets `data-starting-style` while the popup animates in and `data-ending-style` while it animates out, so enter and exit transitions are plain CSS on the popup element.

### When not to switch: staying on Radix

- You have no complaint. shadcn/ui says "If your app works, keep shipping", and Radix shipped releases in October 2026.
- You need React 16.8 or 17 support: Radix supports 16.8 and up; Base UI starts at 17.
- You use Aspect Ratio or Password Toggle Field, which Base UI does not ship.
- Your team's Tailwind and tests are full of `data-[state=...]` selectors and you have no budget for the rename; the attribute changes above touch every styled part.
- A third-party library you depend on already pins Radix (for example a glass theme; see our [library comparison](https://lokendra-builds.github.io/sheenui/guides/best-glassmorphism-react-libraries)). Mixing both primitives in one app works but doubles bundle weight for overlapping components.

### Frequently asked questions

#### Is Base UI a Radix UI alternative or a replacement?

An alternative with overlapping authors. The Base UI about page says it comes from "the creators of Radix, Material UI, and Floating UI". Radix is still maintained (releases on 12 Oct 2026) and still a shadcn/ui option.

#### Base UI or Radix UI for a new shadcn/ui project?

shadcn/ui picks Base UI by default since July 2026 and reports a 2 to 1 preference among `shadcn/create` users. Choose Radix explicitly with `-b radix` if you need React 16.8 or 17 or a Radix-only primitive.

#### How hard is it to migrate Radix to Base UI?

Mechanical but wide: change imports, swap `asChild` for `render`, rename Overlay to Backdrop and Content to Popup, and rewrite `data-[state=...]` selectors to `data-open` and `data-active`. Do it one component at a time; both libraries can coexist during the move.

#### Does Base UI need its own styling system?

No. Both ship unstyled. SheenUI styles Base UI with Tailwind CSS v4 utilities and the data attributes above; see the [foundations page](https://lokendra-builds.github.io/sheenui/foundations).

#### liqui.design

Strengths: the closest match to SheenUI's approach. Built on Base UI, it refracts with a canvas-generated displacement map driving an SVG filter, and is clear about browsers: Chromium gets full displacement, Safari "drops `backdrop-filter` entirely when it references an SVG filter", Firefox the same, and the frosted fallback is automatic ([README](https://github.com/leefanv/liqui-design)). #### Glassy UI

Strengths: the clearest accessibility statement among the third-party options: "Reduce Transparency turns the glass solid. Reduce Motion holds it still", with controls on Radix for keyboard support. 38 free web components plus a React Native set, installed through the `@glassyui` shadcn namespace. MIT, pushed 6 Nov 2026, 164 stars ([repo](https://github.com/alexburlis/glassyui)).

Limits: refraction is a Chromium "refracting edge" rather than a full lens, and the optional `LiquidFilters` SVG is something "no Glassy UI component needs". Pro templates are paid ($99 pre-order for the first 100, then $199, per the homepage).

#### rdev/liquid-glass-react

Strengths: the component that made "Liquid Glass in React" popular, with 6,635 stars. A single `LiquidGlass` wrapper with props for `displacementScale`, `blurAmount`, `saturation`, `aberrationIntensity` and `elasticity`; the README states that "Safari and Firefox only partially support the effect (displacement will not be visible)" ([repo](https://github.com/rdev/liquid-glass-react)). MIT.

Limits: one effect, not a component library, with no accessibility notes. npm 1.1.1 was published on 11 Jun 2025; last push 13 Jun 2025. Peer dependency: React 19 or newer.

#### shadcn-glass-ui

Strengths: a drop-in layer over an existing shadcn/ui project with "59 components, 3 themes" (Glass, Light, Aurora), installable from npm or a namespaced registry. npm dependencies are individual `@radix-ui/react-*` packages plus `framer-motion` and `recharts`.

Limits: no documented refraction, browser fallback or accessibility behavior. The license is MIT on npm but Apache-2.0 on GitHub; resolve that before adopting. The repo moved to [artyhoo/shadcn-glass-ui-library](https://github.com/artyhoo/shadcn-glass-ui-library) (38 stars, pushed 14 Sep 2026); the last npm release was 2.11.2 on 25 Dec 2025.

#### glasscn-ui

Strengths: an early glass variant of shadcn/ui as a real npm package with a Tailwind preset, MIT licensed.

Limits: the repository was archived on 2 Sep 2026 and is read-only; the last npm release (0.7.1) is from 19 Oct 2024, and it targets Tailwind v3 (`tailwind.config.ts`, `@tailwind` directives). Not a starting point for new work.

#### crenspire Glass UI

Strengths: the only library here that draws glass with a WebGL shader ("refraction, chromatic dispersion and a light-tracking rim"), with a documented CSS fallback when WebGL is missing or reduced transparency is on. Radix and shadcn/ui underneath, installed via `@glass-ui/*`, pushed 14 Oct 2026, 102 stars ([repo](https://github.com/crenspire/glass-ui)).

Limits: a WebGL canvas per surface has a different performance profile from CSS glass; measure it (see [backdrop-filter performance](https://lokendra-builds.github.io/sheenui/guides/backdrop-filter-performance)). The README says MIT but GitHub detects no license file. No Safari notes.

#### Ein UI

Strengths: a clean frosted-glass set on Radix, shadcn/ui and Tailwind v4, MIT, with a public shadcn registry. Pushed 18 Oct 2026, 157 stars at its new home [einui/einui](https://github.com/einui/einui).

Limits: frosted glass, not refraction; the README states no component count (third-party listings say 44, not verified) and no browser or preference handling.

#### The 21st.dev glass collection

Strengths: volume. The glassmorphism tag lists "135 components available", each by an individual author, useful for one-off hero sections.

Limits: a marketplace, not a maintained library. No shared primitive layer; accessibility and licenses vary per component (not verified). The free Hobby tier allows "2 free copies / day"; unlimited installs start at Builder ($6/month billed yearly) per the [pricing page](https://21st.dev/pricing).

### Which one to pick, by use case

- A full app with Liquid Glass and documented fallbacks: SheenUI, which installs with a shadcn command or by copying the source (no npm package yet); liqui.design for the same Base UI foundation with a smaller surface.
- A shadcn/ui project to restyle without changing primitives: Glassy UI (Radix, strong preference handling) or crenspire Glass UI (Radix, WebGL look).
- One hero element with a real lens: liquid-glass-react, if the 2025 release dates are acceptable.
- Mobile too: Glassy UI, the only one with a React Native set.
- A single landing block: 21st.dev, with per-component license checks.

### Limitations of this comparison, and when glass is the wrong choice

Counts are self-reported and sometimes inconsistent across a project's own pages (we quoted both where they differ). Stars measure attention, not quality. Push dates say a repository is alive, not that the glass is correct. We ran no benchmarks on the other libraries, so no cell claims frame rates.

Glass is the wrong choice for dense data tools, text-heavy pages and anything that must meet contrast targets with user content behind the surface. Every library here depends on `backdrop-filter`, and every blurred surface costs GPU time, so long lists of glass cards hurt on low-end phones. If your users often enable reduced transparency or forced colors, pick a library that documents a solid fallback or skip glass. Read [accessible glassmorphism](https://lokendra-builds.github.io/sheenui/guides/accessible-glassmorphism) first.

### Frequently asked questions

#### What is the best liquid glass React library?

For true refraction with documented fallbacks: SheenUI (ours, Base UI, not yet published), liqui.design (Base UI, 21 components) and crenspire Glass UI (Radix, WebGL). liquid-glass-react is the best single-effect wrapper but has not shipped since June 2025.

#### Does Liquid Glass refraction work in Safari?

Not with the SVG-filter technique. liqui.design documents that Safari drops `backdrop-filter` when it references an SVG filter; liquid-glass-react documents that displacement is not visible in Safari or Firefox. SheenUI falls back to frosted glass there. Only a WebGL approach (crenspire) can refract in Safari.

#### Which glassmorphism libraries use Base UI instead of Radix?

SheenUI and liqui.design. Glassy UI, shadcn-glass-ui, glasscn-ui, crenspire Glass UI and Ein UI are on Radix. See our [Base UI vs Radix guide](https://lokendra-builds.github.io/sheenui/guides/base-ui-vs-radix).

#### Are these libraries free?

Every verified license is MIT (shadcn-glass-ui shows MIT on npm and Apache-2.0 on GitHub). Glassy UI sells templates separately; 21st.dev limits free copies to two per day.

## Glassmorphism UI Prompt for Claude, Cursor & v0

URL: https://lokendra-builds.github.io/sheenui/guides/glassmorphism-ui-prompt
Sidebar name: Glassmorphism UI prompts

A glassmorphism UI prompt for Claude, Cursor and v0: copy-paste prompts, a rules file and a review checklist for accessible glass and Liquid Glass UI.

By Lokendra Singh Rathore. Published November 8, 2026, updated November 14, 2026.

Breadcrumb: [Home](https://lokendra-builds.github.io/sheenui/) > [Guides](https://lokendra-builds.github.io/sheenui/guides/) > Glassmorphism UI Prompts for AI Coding Agents

A good glassmorphism UI prompt does two things: it tells the agent what to build, and it forbids the shortcuts that make AI-generated glass look right in a screenshot and fail in use. This guide gives you copy-paste prompts for Claude, Cursor and v0, a rules file you can commit, a Liquid Glass variant and a checklist for reviewing what comes back.

Basis: the rules come from how we review glass UI in this repository, not from a test of any model; they name React 19.2+ and Tailwind CSS v4, the versions SheenUI requires. First published 8 Nov 2026, last revised 14 Nov 2026.

We make SheenUI, a glass component library. We did not benchmark any model, so nothing here claims that a prompt produces a certain score. The prompts encode rules we apply when reviewing glass UI, and the checklist shows how to verify the result instead of trusting it.

### Why AI-generated glass usually fails

These are failure modes to check for, not statistics. Each one follows from how the CSS works:

- **Contrast is never measured.** A model can pick a tint that looks fine over the sample background and fails over the brightest part of the real one. Contrast on glass has to be sampled from rendered pixels (see [the accessibility guide](https://lokendra-builds.github.io/sheenui/guides/accessible-glassmorphism)).
- **Too much blur, applied everywhere.** Blur is a render pass per surface. Stacking many blurred cards, or blurring inside a blurred parent, costs frames and adds nothing ([performance guide](https://lokendra-builds.github.io/sheenui/guides/backdrop-filter-performance)).
- **A wrapper with `opacity` or `filter`.** An ancestor with `opacity` below 1, a `filter` or a `mask` becomes a backdrop root, and the glass inside blurs nothing behind the page. A fade-in animation on a wrapper does this silently.
- **No fallbacks.** Reduced transparency, more contrast and forced colors need solid surfaces. Prompts that do not ask for them do not get them.
- **Invented CSS each time.** Without a spec, every component gets slightly different blur, tint and borders, and focus handling and keyboard behavior are rewritten from scratch.
- **Animating the wrong things.** `transition: all` and animated blur radius instead of transform and opacity.

### The prompt

Paste this into a chat tool, or use it as the task text in an agent. It works without any library: it states the recipe and the constraints. Replace the bracketed parts.

```text
Build [a pricing section / a settings dialog / a dashboard header] in React 19.2+ + TypeScript + Tailwind CSS v4.

Glass recipe (use exactly this, do not invent variants):
- Surface: background white/55 (light) or a dark smoked tint at 50% (dark), backdrop-filter: blur(20px) saturate(160%), 1px light border, inset top highlight.
- Three levels: level 1 = tint + border only (no blur), level 2 = cards (blur 20px), level 3 = dialogs and bars (blur 32px, most opaque).
- Always include the -webkit-backdrop-filter line.

Hard rules:
1. Text must reach 4.5:1 contrast (3:1 for large text) over the WORST part of the background, not the average. Control borders and focus rings must reach 3:1. Say how you checked.
2. Never put opacity, filter, mask or mix-blend-mode on a wrapper of glass. Animate the glass element itself.
3. No blur inside blur. At most 8 blurred surfaces visible at once.
4. Fallbacks, all of them: prefers-reduced-transparency: reduce, [data-transparency="reduced"], prefers-contrast: more and forced-colors: active must give a solid surface with a real border (CanvasText / Canvas in forced colors; no box-shadow-only edges).
5. Motion: only transform and opacity. Spring for entrances (about 0.2-0.5 s), shorter ease-in for exits, no overshoot on exit. Respect prefers-reduced-motion and replace movement with a short fade.
6. Semantics: real <button>, <a>, <dialog>-pattern components with focus trap and Escape; visible focus outline (outline, not box-shadow); touch targets at least 44px on touch screens.
7. Do not use glass for body text blocks, tables or forms with many fields. Use solid surfaces there.

Output: one file per component, no unused code, and a short list of how each rule was met.
```

Two details make it stronger. Name the real background (a gradient, an image, the color of the section above), because the model cannot reason about contrast without it. And ask for the verification, not just the code: "say how you checked" makes the agent state its assumptions, which you can then test.

### With SheenUI

If you use a component library, tell the agent to use it and not rewrite the glass. SheenUI is a copy-the-source library: its `@sheenui/theme` package is not on npm yet, so you add components with the shadcn CLI or copy the folders you need into your app (the README, the [install guide](https://lokendra-builds.github.io/sheenui/guides/install-frameworks), the [installation page](https://lokendra-builds.github.io/sheenui/docs/installation) and each docs page list them; tell the agent about the [Tailwind CSS v4 setup](https://lokendra-builds.github.io/sheenui/docs/tailwind-v4) too, since the glass tokens depend on it). The agent can then read real source, and that is where it helps: every exported component and hook carries a doc comment with its props, a compiling `@example`, and keyboard and accessibility notes, so an agent that opens `glass-card.tsx` learns the API from the file.             </DialogHeader>
```tsx
            <DialogFooter>
              <DialogClose render={<Button variant="ghost" />}>Cancel</DialogClose>
              <Button>Confirm</Button>
            </DialogFooter>
          </DialogContent>
        </Dialog>
      </GlassCardContent>
    </GlassCard>
  );
}
```

See the [Glass card](https://lokendra-builds.github.io/sheenui/components/glass-card), [Dialog](https://lokendra-builds.github.io/sheenui/components/dialog) and [Button](https://lokendra-builds.github.io/sheenui/components/button) pages for the props.

#### A rules file the agent always reads

Put the stable rules in the file your tool loads on every task. Claude Code reads `CLAUDE.md` ([memory docs](https://code.claude.com/docs/en/memory)); Cursor reads `AGENTS.md` and `.cursor/rules/*.mdc` files with `description`, `globs` and `alwaysApply` frontmatter ([Cursor docs](https://cursor.com/docs/context/rules)). A short version for SheenUI:

```markdown
## UI rules (glass)

- Build UI from the glass components in `src/sheen` (barrel: `src/sheen/index.ts`). Read the component's source and its doc comment before using it. Do not write new glass CSS.
- Surfaces: `GlassCard level={1|2|3}`; dialogs are `Dialog`, never custom modals.
- At most 8 blurred surfaces in view; no glass nested inside glass blur; never `opacity`/`filter`/`mask` on a wrapper of glass.
- Liquid Glass (`LiquidGlass`): one hero element per view, never body text.
- Every glass surface must still work with reduced transparency, more contrast and forced colors. Do not remove these fallbacks.
- Motion: use `motion/react` with the presets and tokens in `src/sheen/motion`; only transform and opacity; respect reduced motion.
- Before finishing, list how contrast, keyboard and reduced-transparency behavior were checked.
```

For Cursor, the same text goes in `.cursor/rules/glass.mdc` below a frontmatter block such as `description: "Rules for glass UI"` and `alwaysApply: true`.

#### The shadcn MCP server, the registry and llms.txt

The shadcn MCP server lets an assistant browse and install from registries listed in `components.json`; setup for Claude Code is `pnpm dlx shadcn@latest mcp init --client claude`, and Cursor, VS Code and Codex are supported ([shadcn MCP docs](https://ui.shadcn.com/docs/mcp)). Third-party registries are added by `@namespace` in `components.json`.

SheenUI's registry is built: 183 items (the shared theme, every component and chart, and the blocks) plus 5 install bundles, served at `https://lokendra-builds.github.io/sheenui/r/<name>.json` once the docs site is deployed. The shadcn CLI installs from those URLs (tested with shadcn 4.23.0 on Next.js and Vite, see the [install guide](https://lokendra-builds.github.io/sheenui/guides/install-frameworks)). We did not test the MCP server against it, and the registry is not listed under a `@namespace` yet, so with MCP you would give the agent the full URL. We have not published an agent skill either, so there is no `npx skills add` command to give you.

What does exist is a machine-readable index. The demo build writes `llms.txt` (an index of a few dozen KB, one line per page) and `llms-full.txt` (more than a megabyte, with each page's intro, files to copy, props and an example). Once the site is deployed they sit at the site root. The full file is too large for many contexts: give the agent `llms.txt` and let it fetch the pages it needs, or paste only the relevant sections.

### A Liquid Glass prompt

Liquid Glass needs different constraints, because its refraction only works in Chromium and costs more per area:

```text
Add Apple-style Liquid Glass to [one hero control] in React 19.2+ + Tailwind CSS v4.

Rules:
- Exactly one hero element per view (a pill button, a nav pill or a floating control). Never body text, never a card full of copy.
- Refraction is an SVG feDisplacementMap referenced from backdrop-filter and works only in Chromium. Detect the engine (do not use @supports: Safari and Firefox accept the declaration and draw nothing) and give every other browser frosted glass: backdrop-filter: blur(14px) saturate(160%).
- Size the displacement map to the element, redraw it on resize at most every 120 ms, never animate the element's size, only its scale.
- Turn refraction off, with a solid surface, for prefers-reduced-transparency, prefers-contrast: more and forced-colors: active.
- At most 3 refracting elements visible at once.
- Keep any text on a tinted ("regular") lens; a clear lens takes only an icon or one bold word.
Explain how the fallback was tested.
```

With SheenUI, the agent should use `LiquidGlass` (see the [Liquid glass page](https://lokendra-builds.github.io/sheenui/effects/liquid-glass) and [the CSS and React guide](https://lokendra-builds.github.io/sheenui/guides/liquid-glass-css-react)), which already does all of the above.

### A review checklist for AI output

Run these against whatever the agent produced:

1. **Contrast.** Sample the rendered pixels behind text, light and dark, with the script in the accessibility guide. Do not accept "I used white at 70%" as evidence.
2. **Fallbacks.** Emulate `prefers-reduced-transparency`, `prefers-contrast: more` and forced colors, and confirm the surface turns solid. The same guide has a Playwright script.
3. **Wrappers.** Search for `opacity`, `filter`, `mask` and `mix-blend-mode` on ancestors of glass.
4. **Budget.** Count blurred surfaces in view. More than 8, or glass inside glass blur, means rework.
5. **Keyboard.** Tab through everything; open and close each overlay with Escape; confirm a visible focus ring that is not a `box-shadow`.
6. **Motion.** Turn on reduced motion and confirm that movement becomes a fade.
7. **No invented API.** If the agent used a component or prop that does not exist in your copy of the source, it guessed. Type-check.

### Following up when the first result is wrong

Short, specific follow-ups work better than rewriting the prompt. Three that map to the checklist:

- "List every text element and its worst-case contrast over the brightest part of the background. Raise the tint on any under 4.5:1 and show the new numbers."
- "Find any ancestor of a glass element with opacity, filter, mask or mix-blend-mode, and move that property onto the glass element itself."
- "Add the reduced-transparency, more-contrast and forced-colors rules, and show the computed background and backdrop-filter under each."

Asking for the evidence each time keeps the agent honest, and it gives you something to paste into a code review.

### When not to rely on prompts

A prompt reduces repeated mistakes; it does not replace the checks above. Models change, and a prompt that works on one version may not on the next. Do not use glass prompts for data-dense screens: ask for solid surfaces there. And do not let an agent decide your brand colors: give it the tokens.

### Frequently asked questions

#### Does this work in Cursor, Claude Code and v0?

The prompts are plain text, so they work in any chat or agent. For Claude Code and Cursor, move the stable rules into `CLAUDE.md`, `AGENTS.md` or a Cursor rules file so you do not paste them each time. We did not test v0 specifically.

#### Can the agent install SheenUI with the shadcn CLI?

Yes, from the registry URL: `npx shadcn@latest add https://lokendra-builds.github.io/sheenui/r/button.json` (works once the docs site is deployed). Next.js needs one CSS import changed to a relative path; the [install guide](https://lokendra-builds.github.io/sheenui/guides/install-frameworks) has the steps. You can also copy the source.

#### Should I paste llms-full.txt into the prompt?

Usually not: it is more than a megabyte. Use `llms.txt` as an index and paste only the pages for the components you need.

#### What is the minimum I should ask for?

Four lines: use the library's components, measure contrast on the worst background, provide solid fallbacks, and respect reduced motion.
