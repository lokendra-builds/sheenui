### About components

#### Overview

Pick a glassy part and copy it. Every one of the 67 pages below is a glass React component with a live demo, the props, the keyboard model and the exact files to copy, so you can take a single button or a whole form kit without installing a package. The set grows from the same foundation: three glass levels, a handful of [glass design tokens](https://lokendra-builds.github.io/sheenui/foundations), and shared motion presets.

The components are grouped the way you build screens. Components are the everyday parts, such as the [glass button](https://lokendra-builds.github.io/sheenui/components/button), [glassmorphism card](https://lokendra-builds.github.io/sheenui/components/glass-card), [modal dialog](https://lokendra-builds.github.io/sheenui/components/dialog) and [data table](https://lokendra-builds.github.io/sheenui/components/data-table). Forms cover inputs, pickers and uploads, Overlays hold menus, drawers and command palettes, and Navigation and Layout give you the frame around them.

Looking for motion? The [animated React components](https://lokendra-builds.github.io/sheenui/effects/) page lists the effects built with Motion. Need whole screens? See the [React Tailwind blocks](https://lokendra-builds.github.io/sheenui/blocks/) and the [glassmorphism dashboard templates](https://lokendra-builds.github.io/sheenui/dashboards/). Charts live on [their own gallery](https://lokendra-builds.github.io/sheenui/charts/), and the [installation guide](https://lokendra-builds.github.io/sheenui/docs/installation) shows how to add any of these with the shadcn CLI; the [Tailwind CSS v4 setup](https://lokendra-builds.github.io/sheenui/docs/tailwind-v4) covers the two CSS imports.

Everything is free and MIT licensed, built on Base UI and Tailwind CSS v4, and checked in light and dark, in both style presets and with reduced motion on. New to glass UI? Start with the [glassmorphism React tutorial](https://lokendra-builds.github.io/sheenui/guides/glassmorphism-react-tutorial).

#### Frequently asked questions

#### What are glass UI components?

Glass UI components are interface parts such as buttons, cards, dialogs and menus drawn as frosted glass: a translucent tint, a backdrop blur and a lit border over a colorful background. SheenUI adds Liquid Glass refraction on top, and a solid fallback for people who turn transparency off.

#### Which library are the components built on?

Behavior, focus handling and ARIA come from Base UI's headless primitives, the styling is Tailwind CSS v4, and the animation is Motion. You copy the source into your own project.

#### Are the components accessible?

Each page lists its keyboard model and accessibility notes. Every component is tested with axe and a keyboard, and glass turns into solid surfaces with reduced transparency, more contrast or Windows High Contrast.


### All exports on this page

- classNameWith — Base UI's className is a string OR a function of the part's state.
- cn — Merge class names, letting later Tailwind classes override earlier ones.
- useLatest — A ref that always holds the latest value, for stable callbacks that must read current props or state without becoming dependencies.
- useSyncRef — Keeps an existing ref in step with value: the same layout-effect update as useLatest.

### Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| tone | "success" \| "warning" \| "danger" \| "info" | "info" | Sets the colour role and the default icon of the alert. |
| title | ReactNode | optional, no default | A bold first line shown above the message. |
| icon | ReactNode | optional, no default | Replaces the tone's icon; false hides it. |
| action | ReactNode | optional, no default | A button or link at the end, such as "Undo" or "Upgrade". Keep it a real control. |
| dismissible | boolean | false | Show a close button. The alert hides itself when it is pressed. |
| open | boolean | optional, no default | Whether the alert is shown (controlled). Pair with onOpenChange. |
| defaultOpen | boolean | true | Whether the alert starts shown when uncontrolled. |
| onOpenChange | ((open: boolean) => void) | optional, no default | Called with false when the dismiss button is pressed. |
| labels | Partial<AlertLabels> | defaultAlertLabels | Every other string, for translation: labels={{ dismiss: "…" }}; omitted keys keep the English of defaultAlertLabels. Its only key is listed in the key table under the props table. |
| role | "alert" \| "status" \| "none" \| … | alert for warning and danger, otherwise status | Sets the live-region role that announces the alert. |

### Example 1 of 2: Four tones

Each tone has its own icon and tint. The words always say what happened.

### Example 2 of 2: Action and dismiss

Put a real button or link in action. dismissible adds a close button; open and onOpenChange let you control it.

```tsx
import { useState } from "react";
import { Alert } from "@/components/sheenui/alert/alert";
import { Button } from "@/components/sheenui/button/button";
// Package build (after the first npm release, or a packed tarball): import { Alert, Button } from "@sheenui/theme";

export function Example() {
  const [open, setOpen] = useState(true);

  return (
    <div className="flex w-full max-w-xl flex-col gap-3">
      <Alert
        tone="warning"
        title="Your trial ends in 3 days"
        action={<Button size="sm" variant="glass">Upgrade</Button>}
        dismissible
        open={open}
        onOpenChange={setOpen}
      >
        Add a payment method to keep your projects.
      </Alert>
      {!open && (
        <Button size="sm" variant="ghost" className="self-start" onClick={() => setOpen(true)}>
          Show the alert again
        </Button>
      )}
    </div>
  );
}
```

### Accessibility

- Warning and danger use role="alert" (announced at once); info and success use role="status" (announced politely). Pass role="none" for a message that is already on screen at page load: the live demos on this page do, so navigating here does not read out five alerts (the code samples show normal use).
- The tone icon is decorative. The title and message carry the meaning, color is only a hint.
- The dismiss button is named by labels.dismiss, is 44px on touch screens, and has a visible focus ring.
- Text sits on a near-opaque tinted surface, so it keeps 4.5:1 over glass, photos and blobs in light and dark. Forced colors draw a CanvasText border.

### When to use Alert

- Use Alert as an inline message in React for a form-level error above a checkout form, such as a declined card, where the message must stay on screen next to the fields the person has to fix.
- Use it for a plan-limit banner at the top of a settings page, with an action button like Upgrade placed at the end of the row and a close button for people who have seen it.
- Use the success tone for a saved confirmation that should remain readable until the next navigation, instead of vanishing the way a toast does after a few seconds.
- Skip it when the message should disappear by itself after a short moment or must block the page until answered. Use Toast for the first case and Dialog or AlertDialog for the second.
- Pair it with Button for the action slot, Field or Input for the form it explains, and Toast for the lighter follow-up feedback once the problem is fixed.


### Frequently asked questions

#### How do I make a dismissible alert in React with SheenUI?

Set the dismissible prop and the alert shows a close button and hides itself when pressed. For control, pass open and onOpenChange, which receives false on dismiss, or use defaultOpen when uncontrolled. The close button is named by labels.dismiss, so translate that string for other languages.

#### Which ARIA role does the alert component use?

The role depends on the tone. Danger and warning default to role alert, which screen readers announce immediately. Info and success default to role status, announced politely. You can override it, and role none suits a message already on screen at page load so nothing is announced twice.

#### Can I replace the icon or add a button to the alert?

Yes. The icon prop replaces the tone icon with your own node, and icon={false} hides it. The action prop takes a button or link rendered at the end of the alert. Keep it a real control, since the alert itself is not focusable and the action is a normal tab stop.

#### Does the alert still animate when the user prefers reduced motion?

It simplifies. Normally the alert moves 6px into place while fading in and leaves with a shorter fade. When reduced motion is on, through the OS setting or the in-app toggle, it only fades with no vertical movement. The tinted surface is near opaque, so text keeps contrast on photos too.

The three look alike and answer different questions. ButtonGroup joins buttons that each run their own action (Copy, Paste, Cut). Pick by what the control remembers: nothing, a set of pressed buttons, or one value.


### Frequently asked questions

#### How do I group buttons in React with SheenUI?

Wrap Button elements in ButtonGroup. It adds no surface of its own: the buttons keep their variant, hover and press motion, and the group only joins their edges and handles the keys.

#### How does keyboard navigation work?

Tab focuses the group once. The arrow keys move between the buttons, Home and End jump to the ends, and Enter or Space presses the focused one. Disabled buttons are skipped.

#### Can I mix links and buttons?

Yes. Any Button, including one rendered as a link through the render prop, can sit in the group.

#### Is ButtonGroup the same as SegmentedControl?

No. ButtonGroup arranges independent actions. SegmentedControl is a form control that holds one selected value.

#### Why does the group have one tab stop?

The group uses roving focus: Tab lands on one button and the arrow keys move between the rest. A toolbar of ten buttons then costs a keyboard user one Tab press instead of ten, and focus returns to the button that was last used.

#### What do I pass for a vertical group, and does it work right to left?

Pass orientation="vertical". The arrow keys then move with up and down. On a right-to-left page the left and right arrows follow the reading direction.

### Frequently asked questions

#### How does async search work?

Type to filter, Down or Up to move through options, Enter to pick and Escape to close. On a closed single-select list Escape clears the value, controlled by clearOnEscape. In multiple mode Backspace removes the last chip and Left or Right move across the chips.

### Example 2 of 7: Server-side

manual + rowCount: the table only renders. Sorting, search (debounced), filters and paging go to a fake API that answers after 600ms. While it loads, the previous rows stay in place under a veil, so nothing jumps.

```tsx
import { useState } from "react";
import { DataTable } from "@/components/sheenui/data-table/data-table";
import { type DataTableColumn, type DataTableColumnFilters, type DataTableSorting } from "@/components/sheenui/data-table/types";
// Package build (after the first npm release, or a packed tarball): import { DataTable, type DataTableColumn, type DataTableColumnFilters, type DataTableSorting } from "@sheenui/theme";

type Customer = { id: string; name: string; plan: string; mrr: number };

const columns: DataTableColumn<Customer>[] = [
  { id: "name", header: "Customer" },
  { id: "plan", header: "Plan" },
  { id: "mrr", header: "MRR", numeric: true },
];

// Sketch (the hook is yours to write, so this is not runnable as pasted): sends sorting, pagination, search and filters to the server (TanStack Query, SWR or your own).
declare function useUsers(query: {
  sorting: DataTableSorting;
  pagination: { pageIndex: number; pageSize: number };
  search: string;
  filters: DataTableColumnFilters;
}): { data: Customer[]; total: number; isFetching: boolean; error?: Error; refetch: () => void };

export function Example() {
  const [sorting, setSorting] = useState<DataTableSorting>([]);
  const [pagination, setPagination] = useState({ pageIndex: 0, pageSize: 10 });
  const [search, setSearch] = useState("");
  const [filters, setFilters] = useState<DataTableColumnFilters>([]);
  const { data, total, isFetching, error, refetch } = useUsers({ sorting, pagination, search, filters });

  return (
    <DataTable
      caption="Customers (server)"
      manual
      rowCount={total}
      data={data}
      columns={columns}
      loading={isFetching}
      error={error?.message}
      onRetry={refetch}
      sorting={sorting} onSortingChange={setSorting}
      pagination={pagination} onPaginationChange={setPagination}
      globalFilter={search} onGlobalFilterChange={setSearch}
      columnFilters={filters} onColumnFiltersChange={setFilters}
    />
  );
}
```

### Example 6 of 7: Ten thousand rows

With maxHeight set, a page of 50 rows or more renders only the rows in view plus a few more (virtualize defaults to auto; pass virtualize to force it). Scroll to the end: the count below stays small, yet the scrollbar spans all 10,000. Rows outside the window are not in the DOM, so Tab skips them: set virtualize={false} for a table people tab through row by row.

```tsx
import { useEffect, useState } from "react";
import { formatCurrency } from "@/components/sheenui/data-table/cells";
import { DataTable } from "@/components/sheenui/data-table/data-table";
import { type DataTableColumn } from "@/components/sheenui/data-table/types";
// Package build (after the first npm release, or a packed tarball): import { DataTable, formatCurrency, type DataTableColumn } from "@sheenui/theme";

type Order = { id: string; customer: string; status: string; total: number };

const statuses = ["Paid", "Pending", "Shipped", "Refunded"];
const orders: Order[] = Array.from({ length: 10_000 }, (_, i) => ({
  id: `ORD-${String(i + 1).padStart(5, "0")}`,
  customer: `Customer ${String(((i * 37) % 900) + 100)}`,
  status: statuses[i % statuses.length] ?? "Paid",
  total: 20 + ((i * 7919) % 48000) / 100,
}));

const columns: DataTableColumn<Order>[] = [
  { id: "id", header: "Order", minWidth: 120 },
  { id: "customer", header: "Customer", minWidth: 150 },
  { id: "status", header: "Status", minWidth: 110 },
  {
    id: "total",
    header: "Total",
    numeric: true,
    minWidth: 110,
    cell: ({ row }) => formatCurrency(row.total, "USD", "en-US", 2),
  },
];

export function Example() {
  const [wrapper, setWrapper] = useState<HTMLDivElement | null>(null);
  const [inDom, setInDom] = useState<number | null>(null);

  useEffect(() => {
    if (!wrapper) return;
    const count = () => setInDom(wrapper.querySelectorAll("tbody tr[data-row-id]").length);
    count();
    const observer = new MutationObserver(count);
    observer.observe(wrapper, { childList: true, subtree: true });
    return () => observer.disconnect();
  }, [wrapper]);

  return (
    <div ref={setWrapper} className="flex w-full flex-col gap-3">
      <p className="text-sm text-sheen-fg-muted">Rows in the DOM: {inDom} of 10,000</p>
      <DataTable
        caption="Orders"
        data={orders}
        columns={columns}
        maxHeight="22rem"
        virtualize
```

### Frequently asked questions

#### How do I build a React data table with sorting and search?

Pass data, columns and a caption, the three required props. Each column needs only an id and a header; the id is also the accessor key unless you set accessorKey or accessorFn. Search, sorting, faceted filters, paging and CSV export all run client-side by default. It uses TanStack Table v9 headless underneath, so you do not wire that library yourself.

#### How does server-side mode work?

Set manual and pass rowCount, plus controlled state props for sorting, pagination, search and filters. The data prop then holds only the current page. The toolbar Export button appears only when you provide an export handler, because the table cannot export rows it does not have.

#### Is the data table accessible?

It renders a real table with a caption, scoped headers and aria-sort on sorted columns. Sorting, paging, selection and result counts are announced through one polite live region, and checkboxes carry row-specific names. Sortable headers work with Enter or Space, and Shift-click or Shift+Enter adds a sort column.

#### What happens on small screens?

By default the table scrolls sideways, with the first data column pinned unless you turn off stickyFirstColumn. Set mobileLayout to cards and rows become glass cards under 640px. A column can opt out of the card with hideInCards. The scroll region is keyboard reachable.

### When to use Dialog

- Use Dialog as a glass modal for a short form that blocks the page, such as renaming a project or inviting a teammate, where the person finishes or cancels before going back to the page. Use it as an animated modal in React whenever the content needs the person's full attention.
- Use it for a details view opened from a table row or a card, with DialogTitle and DialogDescription naming and describing it for screen readers.
- Use DialogFooter with DialogClose for Cancel and Save actions, and keep the corner close button on with showClose unless the footer already offers a clear exit.
- Skip it when the person must answer a destructive question, where AlertDialog fits better, or when the content is a side panel you want next to the page, where Drawer fits better.
- Pair it with Button through the render prop on DialogTrigger, Input and Field for the form inside, and Toast to confirm the result after the dialog closes.


### Frequently asked questions

#### How do I build a React modal dialog with SheenUI?

Compose Dialog with DialogTrigger and DialogContent, then DialogHeader, DialogTitle, DialogDescription and DialogFooter inside. Dialog holds open, defaultOpen and onOpenChange and renders no element. It wraps Base UI Dialog, so the portal, focus handling and scroll lock are already done.

#### How does the dialog handle keyboard focus?

Enter or Space on the trigger opens it and focus moves to the first control inside. Tab and Shift+Tab stay in the dialog, Escape or a click on the scrim closes it, and focus returns to the trigger. The page behind is inert and its scroll is locked.

#### Do I have to include a title?

Yes, always render one. DialogTitle is an h2 and the dialog's accessible name, with aria-labelledby wired for you; DialogDescription gives aria-describedby. If the design has no visible heading, add className sr-only to the title so it stays available to assistive technology.

#### How do I change the size or hide the close button?

DialogContent is centered, at most 28rem wide and never taller than the viewport; it scrolls inside. Override width with className. Set showClose to false to remove the corner button, and use labels to translate its aria-label, which is Close by default.
