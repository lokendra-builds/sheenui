## Animated Accordion for React with Spring Motion

URL: https://lokendra-builds.github.io/sheenui/layout/accordion
Sidebar name: Accordion

An animated React accordion: height follows a spring on open and a quick ease on close, the chevron turns and content drifts in. Base UI, Tailwind v4.

What it is: An animated React accordion whose sections open on a spring, with every trigger a real button in the tab order. Use it as a React accordion for an FAQ section on a pricing or landing page, where the default glass variant puts all questions in one card and the open item rises as a lighter pane.

### Accordion

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| variant | AccordionVariant | "glass" | Surface style: "glass" is one glass card, "separated" gives every item its own card, "plain" has no surface. |
| className | string | optional, no default | Adds extra classes to the outer element. |
| multiple | boolean | false | Let several items stay open at once. |
| defaultValue | any[] | optional, no default | Values of the items open at first (uncontrolled). |
| value / onValueChange | any[] / (value) => void | optional, no default | Control which items are open. |
| hiddenUntilFound | boolean | false | Closed panels stay in the page so the browser's find-in-page can open them. |
| disabled | boolean | false | Disables every item of the group. |

### AccordionItem

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| className | string | optional, no default | Adds extra classes to the item element. |
| value | any | auto id | Names the item for defaultValue / value. |
| disabled | boolean | false | The trigger stays visible but cannot be toggled. |
| onOpenChange | (open) => void | optional, no default | Called when this item opens or closes. |

### AccordionTrigger

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| icon | ReactNode | optional, no default | Leading icon in a small tile; it picks up the accent while the item is open. Hidden from screen readers. |
| description | ReactNode | optional, no default | Shows a secondary line under the title. |
| indicator | "chevron" \| "plus" | "chevron" | "chevron" turns over; "plus" becomes a minus. |
| headingLevel | HeadingLevelOption | 3 | Heading level of the wrapping header (2 to 6), to fit the page outline, or "none" for a paragraph with no heading role (for an example). |
| className | string | optional, no default | Extra classes for the trigger button. |

### AccordionPanel

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| className | string | optional, no default | Extra classes for the panel (height-animated, clips while it moves). |
| contentClassName | string | optional, no default | Extra classes for the padded content box inside the panel. |
| keepMounted | boolean | false | Keep closed content in the DOM. |

### Example 1 of 3: FAQ

### Example 3 of 3: Plain, controlled, inside a card

variant="plain" has no surface of its own, for settings inside an existing card. value / onValueChange control which sections are open; a disabled item stays visible.

```tsx
import { useState } from "react";
import { Accordion, AccordionItem, AccordionPanel, AccordionTrigger } from "@/components/sheenui/accordion/accordion";
import { Button } from "@/components/sheenui/button/button";
import { GlassCard } from "@/components/sheenui/glass-card/glass-card";
// Package build (after the first npm release, or a packed tarball): import { Accordion, AccordionItem, AccordionPanel, AccordionTrigger, Button, GlassCard } from "@sheenui/theme";
import { CreditCard as CardIcon, User as UserIcon } from "lucide-react";

export function Example() {
  const [open, setOpen] = useState<string[]>(["profile"]);
  // Every item that can open: the disabled one stays closed.
  const all = ["profile", "notifications", "security"];

  return (
    <>
      <Button size="sm" variant="glass" onClick={() => setOpen(all)}>Expand all</Button>
      <Button size="sm" variant="ghost" onClick={() => setOpen([])}>Collapse all</Button>

      <GlassCard className="p-2">
        <Accordion variant="plain" multiple value={open} onValueChange={(value) => setOpen(value as string[])}>
          <AccordionItem value="profile">
            <AccordionTrigger icon={<UserIcon />}>Profile</AccordionTrigger>
            <AccordionPanel>Name, photo and email.</AccordionPanel>
          </AccordionItem>
          <AccordionItem value="notifications">
            <AccordionTrigger>Notifications</AccordionTrigger>
            <AccordionPanel>Choose what we email you about.</AccordionPanel>
          </AccordionItem>
          <AccordionItem value="security">
            <AccordionTrigger>Security</AccordionTrigger>
            <AccordionPanel>Password and two-step sign-in.</AccordionPanel>
          </AccordionItem>
          <AccordionItem value="billing" disabled>
            <AccordionTrigger icon={<CardIcon />} description="Ask an owner to unlock">Billing</AccordionTrigger>
            <AccordionPanel>Plans and invoices.</AccordionPanel>
          </AccordionItem>
        </Accordion>
      </GlassCard>
    </>
  );
}
```

### Keyboard

| Keys | Action |
| --- | --- |
| Tab / Shift + Tab | Move between triggers (disabled items are skipped). |
| Enter / Space | Open or close the focused item. |

### Accessibility

- Each trigger is a native button inside a heading (headingLevel sets the level) with aria-expanded and aria-controls.
- Closed panels are hidden from the accessibility tree, so their links are not tabbable; hiddenUntilFound lets find-in-page open matching panels.
- A disabled item is announced as dimmed; the chevron and icon tile are aria-hidden.

### When to use Accordion

- Use it for an FAQ below a pricing table, or a settings screen with long sections, where only the answer you open takes space and every trigger stays a real button in the tab order.
- Use the separated variant with multiple for a settings or filter panel, where each group is its own glass card and several can stay open while someone compares them.
- Use the plain variant inside an existing card, such as a checkout summary or a sidebar, when the accordion should not add a surface of its own.
- Skip it when a section is independent and should not close its neighbors; Collapsible is a single show and hide region, and Tabs is better when users compare parallel views.
- Pair it with Badge in a trigger description, Field and Input for settings groups inside panels, and the Kbd component to show shortcuts in help content.


### Frequently asked questions

#### How do I build an accordion?

Wrap AccordionItem elements in Accordion, each with an AccordionTrigger and an AccordionPanel. The panel height eases open in 220 ms and closes in a quicker 150 ms, and the chevron turns with it. The component is built on Base UI and the file starts with "use client".

#### How do I let several sections stay open?

Set multiple on Accordion. Control which items are open with value and onValueChange, which take arrays of item values, or seed them with defaultValue. Give items stable value props instead of the auto id, so the state survives reordering. A disabled item stays visible but cannot be toggled.

#### Does it work with the keyboard and Ctrl+F?

Each trigger is a native button inside a heading, with aria-expanded, and closed panels are removed from the page. Set hiddenUntilFound so the browser's find-in-page can open a matching panel, and use headingLevel, 3 by default, to fit your page outline.

#### Can I add icons, descriptions or a plus indicator?

AccordionTrigger takes icon for a leading tile that picks up the accent while open, description for a muted second line, and indicator set to chevron or plus, where the plus folds into a minus. Use contentClassName on AccordionPanel to adjust padding of the content box.

## React Aspect Ratio Box for Images & Video

### Example 1 of 2: Screenshots, a video poster and a profile card

ratio is width divided by height. Images fill the box (size-full object-cover); overlays are positioned inside it. Every tile keeps its ratio at any width, so nothing jumps while images load.

| Keys | Action |
| --- | --- |
| Tab | Not focusable: it is a plain container. Anything focusable inside it keeps its own tab stop. |

### Accessibility

- No role of its own. Give the media inside it text: alt on an image, a title or caption on a video or map.
- It reserves space, which prevents layout shift (CLS) while content loads.
- Pass render to use another element, such as a figure. className and ref go on the box.

### When to use the aspect ratio

- Use AspectRatio for a 16:9 video poster, a square product photo or a map tile in a card grid, so every cell keeps its shape and nothing moves while the images load.
- Pass ratio as width divided by height: 16 / 9 for video, 4 / 3 for photos, 1 for avatars and product tiles. The box keeps that ratio at any width.
- Fill the box with size-full object-cover on the image, and give the box rounded corners: it clips its children.
- Skip it for content whose height should follow its text. A card with copy should size itself, not hold a ratio.
- Pair it with Skeleton as the loading state, with Carousel slides that must share one height, and with figure and figcaption through the render prop.


### Frequently asked questions

#### How do I keep an image from shifting the layout while it loads?

Wrap it in AspectRatio with the image's width-to-height ratio. The box takes its height from the ratio right away, so nothing below it moves when the image arrives.

#### How do I use another element, such as a figure?

Pass render with the element you want, for example render={<figure />}. The ratio, className and ref still go on that element.

#### Does AspectRatio add any accessibility semantics?

No. It is a plain container with no role. Give the media inside it text: alt on an image, a title on a video or map.

#### What is the default ratio?

1, a square. Pass 16 / 9, 4 / 3 or any number you need.

### Breadcrumb

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| items | BreadcrumbItem[] | required | The trail, root first. The last item is the current page. |
| separator | ReactNode | "chevron" | Between items: the presets "chevron", "slash" or "dot", or any node (rendered decoratively). |
| collapse | "auto" \| "never" | "auto" | "auto" folds middle items into a menu when the trail does not fit; "never" wraps instead. |
| maxItems | number | no limit | Always collapse when there are more items than this. |
| itemsBefore | number | 1 | Items always shown before the "…" menu. |
| itemsAfter | number | 1 | Items kept after the "…" when maxItems collapses (width-driven collapse keeps at least 1). |
| renderLink | ((item: BreadcrumbItem) => ReactElement) | optional, no default | Render every link as your router's link: (item) => <Link to={item.href!} />. |
| variant | "glass" \| "plain" | "plain" | Picks a "plain" text trail or a "glass" pill. |
| size | "sm" \| "md" | "md" | Sets the text and row size. |
| labels | Partial<BreadcrumbLabels> | defaultBreadcrumbLabels | Any UI string (i18n): nav and more. Give each breadcrumb on a page its own nav. Every other string, for translation: labels={{ nav: "…" }}; omitted keys keep the English of defaultBreadcrumbLabels. All 2 keys of BreadcrumbLabels are listed in the key table under the props table. |
| className | string | optional, no default | Adds extra classes to the <nav>. |

### BreadcrumbItem

| Prop | Type | Default | Description |
| --- | --- | --- | --- |

### Example 3 of 3: Router links and translations

renderLink renders every link through your router, including the links inside the collapse menu. Every string the component adds is a prop.

### When to use Breadcrumb

- Use it as a collapsible breadcrumb on a documentation or e-commerce page that sits several levels deep, such as Home, Products, Shoes, Running, so people can jump back to any ancestor without using the browser's Back button.
- Use maxItems with itemsBefore and itemsAfter for deeply nested file or category trees, where you always want the root and the current page visible and the middle folded into a menu.
- The collapse is measured before paint, so it suits responsive layouts where the same trail must fit a phone header and a wide desktop header without a flash of overflow.
- Skip it for linear multi-step flows such as checkout; Stepper shows progress and state there, and breadcrumbs describe site hierarchy rather than the order of tasks.
- Pair it with Navbar or Vertical nav for primary navigation, with Menu behavior already built in for the folded items, and with a page heading and Button actions below the trail.


### Frequently asked questions

#### How do I build a react breadcrumb with SheenUI?

Pass an items array, root first, to Breadcrumb. Each item has a label and an optional href, and the last item is treated as the current page with aria-current="page" and no link. Choose separator chevron, slash or dot, or supply your own node.

#### What happens when the trail is too long for the screen?

With collapse set to auto, the default, the middle items fold into a menu button, and they come back when the row widens. The hidden pages are listed as real links, and arrow keys, typeahead and Escape work in it. Set collapse to never to let the trail wrap instead.

#### How do I use my router's Link and translate the labels?

Pass renderLink, for example (item) => <Link to={item.href!} />, and it is used for every link, including those in the collapse menu. A single item can override it with render. The labels prop holds the accessible names, nav and more(count), so you can translate them.

#### Can I show an icon-only item such as a home icon?

Yes. Give an item in the items array an icon and set iconOnly, and only the icon is drawn while the label stays available to screen readers. When the label is not a plain string, add textValue so typeahead in the collapse menu has text to match.

### Example 2 of 2: Controlled and remembered

Pass layout and onLayoutChange to own the sizes, for example to save them in localStorage and restore them on the next visit. The sizes are percentages that add up to 100.

```tsx

const KEY = "my-app:layout";

export function Example() {
  const [layout, setLayout] = useState<number[]>(() => {
    try {
      const saved = localStorage.getItem(KEY);
      return saved ? (JSON.parse(saved) as number[]) : [30, 70];
    } catch {
      return [30, 70];
    }
  });

  useEffect(() => {
    try {
      localStorage.setItem(KEY, JSON.stringify(layout));
    } catch {
      /* private mode: the layout just resets next visit */
    }
  }, [layout]);

  return (
    <ResizablePanelGroup layout={layout} onLayoutChange={setLayout} className="h-48 rounded-sheen-lg border border-sheen-border">
      <ResizablePanel minSize={15} maxSize={60}>
        <p className="p-4 text-sm">Sidebar: {Math.round(layout[0] ?? 0)}%</p>
      </ResizablePanel>
      <ResizableHandle withGrip />
      <ResizablePanel>
        <p className="p-4 text-sm">Content: {Math.round(layout[1] ?? 0)}%</p>
```

| ← / → | Move the focused handle (↑ / ↓ in a vertical group) by keyboardStep percent. |
| Shift + arrow | Move it five times as far. |
| Home / End | Send the handle to the limit of its range. |
| Step buttons | Two buttons on the handle make the panel before it larger or smaller with a single press (the non-drag alternative); always visible on touch screens, shown on keyboard focus elsewhere. |
| Double click / double tap | Puts the divider back where it started. |

### Accessibility

- Each handle is a role="separator" (the ARIA window splitter pattern) with aria-orientation, aria-valuenow (percent of the panel before it), aria-valuemin, aria-valuemax and aria-controls, named by labels.resize.
- Every drag has a keyboard equivalent; the grab area is 44px on touch screens and works with mouse, touch and pen.
- Panels never shrink below minSize or grow past maxSize, so content is not lost. In right-to-left pages the arrow keys and the drag follow the reading direction.
- Resizing follows the pointer directly; there is no animation, so reduced motion changes nothing.

### All exports on this page

- ResizableHandle — The draggable divider between two panels of a ResizablePanelGroup.
- ResizablePanel — One panel of a ResizablePanelGroup.
- ResizablePanelGroup — Panels with draggable, keyboard-resizable handles between them: a file tree next to an editor, a list next to a detail pane, a console under a canvas.
- defaultResizableLabels — The English ResizableLabels used when labels is omitted; a partial labels prop is merged over it.


### When to use the resizable panels

- Use Resizable for an IDE-style workspace, an email client or a log viewer, where people drag a handle (or press the arrow keys) to choose how much room each area gets.
- Put ResizablePanel children in a ResizablePanelGroup with a ResizableHandle between each pair. Set minSize and maxSize so a panel never collapses past usefulness.
- Own the sizes with layout and onLayoutChange when you want to save them in localStorage or a user setting and restore them later.
- Skip it for a fixed two-column layout. CSS grid is lighter when nobody needs to resize.
- Pair it with ScrollArea inside each panel, with a vertical group nested in a horizontal one for editor layouts, and with Drawer for the phone version.


### Frequently asked questions

#### How do I build a resizable split pane in React?

Render ResizablePanelGroup with a ResizableHandle between each pair of ResizablePanels. Panels register themselves, so they may sit inside your own components. Sizes are percentages that add up to 100; defaultLayout sets the start and onLayoutChange reports every move.

#### Can the handles be moved with the keyboard or without dragging?

Yes. Each handle is a role=separator: focus it and use the arrow keys (Shift for bigger steps) and Home or End to jump to the limit of its range. Two step buttons on the handle make the panel before it larger or smaller with a single pointer press (the non-drag alternative), and a double click or double tap puts the divider back where it started.

#### How do I save the layout?

Pass layout and onLayoutChange, store the array in localStorage in the handler, and read it back as the initial state. The page's second example shows it.

#### Does it work in right-to-left pages?

Yes. The arrow keys and the drag follow the reading direction.

### Accessibility

- Scrolling stays native (wheel, touch, keys, find-in-page); the viewport gets a name from label and role="region".
- Scrollbars appear on hover, while scrolling and while the viewport has keyboard focus; the focus ring is drawn inside the edge.
- The edge fades are decorative. Use fade="shadow" when glass cards sit inside, so their blur is not masked.

### When to use the scroll area

- Use it as a React scroll area for a fixed-height list inside a card, such as a notification list or a long set of options, where you want slim glass scrollbars instead of the browser's chunky default. It draws a glass scrollbar in CSS that matches the theme, instead of the browser default.
- Use orientation="horizontal" for a row of cards or chips that scrolls sideways, with fade="shadow" so the glass cards inside keep their backdrop blur.
- Use orientation="both" for a wide table in a fixed box with scrollbars="always", when users must see at a glance that the content continues in both directions.
- Skip it when the whole page scrolls; let the browser handle it. For a long list of thousands of rows, the windowed Chat list, which renders only the visible rows, or a paginated Data table is a better fit than scrolling a plain container.
- Pair it with GlassCard as the container, Separator between sections of the scrolled content, and Skeleton to hold the layout while the content loads.


### Frequently asked questions

#### How do I add a custom scrollbar in React without breaking native scrolling?

Wrap the content in ScrollArea and give the root a height for vertical scrolling or a width for horizontal. Scrolling stays native, so wheel, touch, keyboard and find-in-page all work. Only the scrollbars are drawn by the component, and they show on hover, while scrolling and on focus.

#### How does the keyboard reach a scroll area?

The viewport becomes focusable only while it can actually scroll, so Tab reaches it. Then the arrow keys, Page Up, Page Down, Home, End and Space scroll natively. Pass label to name the region for screen readers; the viewport gets role="region" and a focus ring inside its edge.

#### What are the edge fades, and when should I turn them off?

The fade prop shows there is more to see: mask, the default, fades the content at the edges only where it can scroll, shadow draws scroll shadows, and none removes it. Use shadow when glass cards sit inside, because a mask would stop their blur. fadeSize defaults to 32px.

#### How do I scroll to an item programmatically?

Pass a ref to viewportRef, which points at the scrolling element, and call scrollTo or scrollIntoView on it or on a child. Use viewportClassName and contentClassName to style the scroller and its content wrapper, and set the root's border radius so the keyboard focus ring matches.

### Frequently asked questions

#### How do I add a react separator with text in the middle?

Pass label to Separator, for example "or". Choose where it sits with labelAlign, start, center or end, and its look with labelVariant, text or pill. The label also names the separator for screen readers, and labelClassName styles it. A line segment runs on each side of the label, and with labelAlign start or end the segment before or after it shrinks to a short lead-in.

#### Is a separator announced by screen readers?

By default it has role="separator" with the matching orientation, and a labeled one keeps its text readable. If the line is purely visual, set decorative and it is hidden from assistive technology. It is not focusable, so Tab skips it either way.

#### What line styles are available?

The variant prop takes line, a plain hairline, fade, which fades toward the ends, or dashed. Orientation is horizontal or vertical. Line and dashed are drawn with borders, and the fade gradient falls back to a real border in forced colors, so the line survives Windows High Contrast mode, which would otherwise drop backgrounds.

#### Why is my vertical separator not showing?

A vertical separator stretches to the height of its row with self-stretch, which only works inside a flex or grid container. On its own it falls back to a minimum height of 16px, or 4rem with a label. Put it in a flex row that has a height, such as h-6 items-center, and it fills that height.

### When to use Stepper

- Use it as the progress steps of a multi-step form, such as a checkout with Cart, Shipping, Payment and Review, where completed steps can be revisited and a failed payment step can flag itself with an error state.
- Use orientation="vertical" with per-step content for an onboarding or setup wizard, where the current step reveals its own form and optional steps are labeled as such.
- Use it for a long application form on phones, where the automatic compact view shows Step 2 of 4 with a segmented bar instead of cramped titles.
- Skip it when the user can move between views freely with no order; Tabs is the right pattern for parallel views, and Breadcrumb shows where a page sits in the site hierarchy.
- Pair it with Button for Back and Next, Field and Input for each step's form, and Progress when you also want a continuous completion value.


### Frequently asked questions

#### How do I build a react stepper for a multi-step form?

Pass steps, an array of objects with title and optional description, status, optional, icon, disabled and content, plus current, the zero-based index of the current step. Setting current to steps.length marks everything complete. Keep current in your own state and advance it from your Next button.

#### How do I let users go back to earlier steps?

Pass onStepClick, which turns steps into buttons. By default clickable is completed, so only finished steps respond; set it to all to allow jumping anywhere. Clickable steps are real buttons and normal tab stops, and Enter or Space goes to the focused step. The current step is a button too but does nothing when pressed, and non-clickable steps are not focusable.

#### How is the stepper announced to screen readers?

It renders an ordered list inside a nav, the current step has aria-current="step", and each state, complete, current, upcoming or error, is also spoken. Give several steppers on one page their own nav label through the labels prop, which also translates every string.

#### When does it switch to the compact view?

With collapse set to auto, the horizontal stepper collapses to Step 2 of 4 with a segmented bar when each step has less than minStepWidth, 136px by default. Use always or never to force it. The vertical orientation does not collapse; it lists steps in a column.

### Keyboard

| Keys | Action |
| --- | --- |
| Tab / Shift + Tab | Enter or leave the toolbar once (one tab stop). |
| Arrow Left / Arrow Right (Up / Down when vertical) | Move between controls. |
| Home / End | Jump to the first / last control (also from a disabled control; in a text field the keys move the caret). |
| Enter / Space | Press a button or toggle. |

### Accessibility

- role="toolbar" with roving focus (Base UI): name it with aria-label and set orientation to match.
- Toggles use aria-pressed; a toolbar toggle group is role="group" and needs its own aria-label.
- tooltip and shortcut add a tooltip and aria-keyshortcuts; an icon-only button needs a tooltip or aria-label.

### When to use Toolbar

- Use it as an editor toolbar for a rich-text editor's formatting row, where Tab enters once and arrow keys move between Bold, Italic, alignment and menu buttons instead of tabbing through twenty controls. It is an accessible toolbar with roving tabindex: Tab enters it once and the arrow keys move between the controls.
- Use variant="floating" for a selection toolbar over text or a canvas, a glass pill that appears next to the thing being edited.
- Use orientation="vertical" for a tool palette in a design or whiteboard app, where Up and Down move between tools and tooltips open to the side.
- Skip it for a handful of unrelated buttons in a page header; plain Buttons are simpler there, and Menubar fits an application's File and Edit menus with dropdowns.
- Pair it with Menu through ToolbarButton's render prop, Tooltip text already built in through the tooltip prop, and Kbd to show a shortcut such as mod+b.


### Frequently asked questions

#### How do I build a react toolbar with arrow key navigation?

Wrap controls in Toolbar and use ToolbarButton, ToolbarToggle, ToolbarLink and ToolbarInput. The toolbar is a single tab stop: arrow keys move focus, Home and End jump to the ends, and loopFocus, on by default, wraps from last to first. Give it an aria-label.

#### How do toggle groups differ for single and multiple choice?

ToolbarToggleGroup is single choice by default, with one accent pill gliding between options; add required to keep one pressed, as with alignment. With multiple, toggles are independent, such as bold, italic and underline, and each blooms its own tint. value takes an array of strings.

#### How do icon-only buttons get an accessible name and a shortcut?

Set tooltip on ToolbarButton or ToolbarToggle. It shows the tooltip and, for an icon-only control, becomes the accessible name. Add shortcut, such as "mod+b", to show it in the tooltip and expose it as aria-keyshortcuts. A disabled control stays focusable so it can be discovered.

#### What happens on narrow screens?

The default overflow="wrap" flows controls onto more rows. Set overflow="scroll" to keep one row that scrolls sideways inside the toolbar, styled through contentClassName. The scrolling row fades at the edges that hide more controls and scrolls a focused control into view, and controls grow to at least 44px on touch screens regardless of size.
