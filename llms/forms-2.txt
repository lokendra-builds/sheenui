## React Tags Input: Chips with Paste & Keyboard

URL: https://lokendra-builds.github.io/sheenui/forms/tags-input
Sidebar name: Tags input

A glass React tags input: Enter or comma makes a chip, paste a list to add many, walk chips with arrow keys and remove with Backspace. Tailwind v4, MIT.

What it is: A glass React tags input that turns typed text into chips, adds a pasted list at once and lets you walk and remove chips from the keyboard.

### Example 1 of 3: Basic

Enter or comma adds; Backspace at the start selects the last tag, a second Backspace removes it. Try pasting “glass, motion; a11y”.

```tsx
import { TagsInput } from "@/components/sheenui/tags-input/tags-input";
// Package build (after the first npm release, or a packed tarball): import { TagsInput } from "@sheenui/theme";

export function Example() {
  return (
    <TagsInput
      label="Topics"
      defaultValue={["design", "motion"]}
      placeholder="Add a topic…"
      description="Press Enter or comma to add."
    />
  );
}
```

### Example 3 of 3: Validation

Your own rule plus built-ins: each address must be valid and unique, lower-cased on the way in. Paste a whole list: the bad ones are reported, the rest are added.

```tsx
import { TagsInput } from "@/components/sheenui/tags-input/tags-input";
// Package build (after the first npm release, or a packed tarball): import { TagsInput } from "@sheenui/theme";

const EMAIL = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

export function Example() {
  return (
    <TagsInput
      label="Invite by email"
      placeholder="name@example.com"
      delimiters={[",", " ", ";"]}
      transform={(t) => t.trim().toLowerCase()}
      validate={(t) => (EMAIL.test(t) ? null : `“${t}” isn’t an email address.`)}
      max={10}
      name="invites"
    />
  );
}
```

### Keyboard

| Keys | Action |
| --- | --- |
| Enter / , | Add what you typed (or the highlighted suggestion). |
| Backspace | At the start of the field, select the last tag; press again to remove it. |
| Arrow Left / Arrow Right | From the start of the field, walk the tags (flipped in right-to-left pages). |
| Backspace / Delete on a tag | Remove it; focus moves to the neighboring tag. |
| Any letter on a tag | Jump back to the field and type. |
| Paste | "a, b; c" (or one per line) adds several tags. |

### Accessibility

- The field is a labeled input with a hidden keyboard hint; each tag has a name and a remove button ("Remove React").
- Added, removed and rejected tags (duplicate, too long, over max) are announced politely, and the error is linked to the field.
- During IME composition Enter confirms the text and never adds a tag.

### All exports on this page

- TagsInput — Tags input: type and press Enter (or a comma) to turn text into a chip.
- defaultTagsInputLabels — Default English strings of TagsInputLabels; spread it and override single keys to reword.


### When to use the tags input

- Use it as a tag input component for a blog editor's keywords field where people type a word and press Enter or a comma to turn it into a chip, with max capping how many are allowed. Use it as a multi-value input in Tailwind projects when people add several short values, such as topics, and each becomes a removable tag.
- Use it for an email recipients or invite field where pasting a list such as a, b; c or one per line adds several tags at once through pasteSplit.
- Use it for labels on a task or file, where the optional suggestions prop opens a glass list under the field so people reuse existing tags instead of inventing near duplicates.
- Skip it when users must pick only from a fixed, known list; Combobox with multiple selection validates against it, and plain Input fits one free value such as a title.
- Pair it with its own label and error props for the name and message, Badge for how the saved tags display elsewhere, and Button to submit the list that name posts as hidden inputs.


### Frequently asked questions

#### How do I make a React tags input with Enter and comma?

Enter and the comma key turn typed text into a tag by default, or add the highlighted suggestion. The delimiters prop changes what splits text, transform cleans a tag before it is added, and addOnBlur adds whatever is typed when the field loses focus.

#### Which keyboard shortcuts remove or move between tags?

Backspace at the start of the field selects the last tag, and pressing it again removes it. Left and Right from the start walk the tags, flipped in right-to-left. Backspace or Delete on a tag removes it, and typing any letter on a tag jumps back to the field.

#### How are tags exposed to assistive technology?

The tags form a real list with role="list" and a named remove button on each chip. The field is described by a hint, the counter and any error, and additions, removals and errors are announced politely. Chips and buttons are 44px targets on touch screens.

#### How do I submit the tags with a form or validate them?

The name prop renders one hidden input per tag. Use value with onValueChange for controlled use, or defaultValue. The error prop overrides the built-in messages with your own, and labels translates every string, including announcements. Reduced motion makes chips fade rather than move.

```tsx
    <form
      className="flex w-full max-w-md flex-col items-end gap-3"
      onSubmit={(e) => {
        e.preventDefault();

        label="Post"
        value={post}

            </Button>
          </>
        }
      />

      </Button>
    </form>
  );
}
```

### When to use Textarea

- Use it as an auto-resize textarea for a comment box or a chat reply composer that should grow as people type, between minRows and maxRows, and then scroll instead of pushing the page down.
- Use it for a profile bio with a 280 character limit, where the counter ring turns amber near the limit and red at it, and screen readers hear the count with the field.

### Frequently asked questions

#### How does the auto resize textarea in React avoid page jumps?

It measures height on an off-screen twin of the content, so the visible field never reflows while you type. It grows between minRows and maxRows and then scrolls. Set autoResize={false} for a fixed height with a native resize handle.

#### What happens when someone reaches the character limit?

With limit="block", the default, typing stops at maxLength and the counter gives a small shake; reduced motion drops the shake. With limit="warn", people can keep typing and the field is marked invalid until they trim it. showCount overrides when the counter appears.

#### Is the character counter announced to screen readers?

The count is linked to the field through aria-describedby, so it is read with the textarea. A polite announcement also fires at 20 and 10 characters left and at the limit, not on every keystroke. The labels prop translates those counter strings.

#### Which props go to the native element?

Every prop other than the component's own, such as value, onChange, placeholder and name, goes to the native textarea. className styles the outer wrapper and textareaClassName styles the textarea itself. On touch screens the text is 16px so iOS does not zoom in.

### Example 1 of 2: Standalone toggles

children can be a function of the pressed state, to swap an outline icon for a filled one. The label stays the same: screen readers say “pressed” or “not pressed”, so a label that also changed would contradict it.

```tsx
import { useState } from "react";
import { Toggle } from "@/components/sheenui/toggle/toggle";
// Package build (after the first npm release, or a packed tarball): import { Toggle } from "@sheenui/theme";
import { Bell as BellIcon, BellOff as BellOffIcon, Pin as PinIcon, Star as StarIcon } from "lucide-react";

export function Example() {
  const [muted, setMuted] = useState(false);

  return (
    <>
      <Toggle iconOnly aria-label="Favorite">
        {({ pressed }) => <StarIcon fill={pressed ? "currentColor" : "none"} />}
      </Toggle>

      <Toggle defaultPressed>
        {({ pressed }) => (
          <>
            <PinIcon fill={pressed ? "currentColor" : "none"} />
            Pin
          </>
        )}
      </Toggle>

      <Toggle iconOnly variant="ghost" pressed={muted} onPressedChange={setMuted} aria-label="Mute notifications">
        {muted ? <BellOffIcon /> : <BellIcon />}
      </Toggle>

      <Toggle disabled>Disabled</Toggle>
    </>
  );
}
```

### Example 2 of 2: Formatting toolbar

Two named groups: B / I / U / S are independent (multiple); alignment is one at a time. The arrow keys move inside a group and Tab moves to the next one. For a single tab stop across several groups, put them in a Toolbar.

```tsx

import { Toggle, ToggleGroup, ToggleGroupSeparator } from "@/components/sheenui/toggle/toggle";
// Package build (after the first npm release, or a packed tarball): import { Toggle, ToggleGroup, ToggleGroupSeparator } from "@sheenui/theme";
import { AlignCenter as AlignCenterIcon, AlignLeft as AlignLeftIcon, AlignRight as AlignRightIcon, Bold as BoldIcon, Italic as ItalicIcon, Strikethrough as StrikeIcon, Underline as UnderlineIcon } from "lucide-react";

export function Example() {
  const [format, setFormat] = useState(["bold"]);
```

### Keyboard

| Keys | Action |
| --- | --- |
| Tab / Shift + Tab | Toggle: move focus to or from it. ToggleGroup: enter or leave the group once. |
| Enter / Space | Press or release the focused toggle. |
| Arrow keys | ToggleGroup: move between toggles. |

### Accessibility

- A native button with aria-pressed; give an icon-only toggle an aria-label.
- A group has role="group"; name it with aria-label. Pressed state is shown by fill and weight, not only by color.
- The touch hit area is 44 px; under reduced motion the state changes without a scale.

### When to use Toggle

- Use it as a toggle button for Bold or Italic in a text editor toolbar, with variant="ghost" so there is no surface until pressed and a ToggleGroup holding several together.
- Use it for a stand-alone Mute, Pin or Favorite button that keeps its pressed state, with iconOnly for a square button and children as a function to swap an outline icon for a filled one.
- Use a ToggleGroup with the multiple prop for independent options such as text formatting, or without it for a single choice like text alignment where pressing the active one clears it.
- Skip it when the control is a setting that applies at once, which is what Switch is for, or a form value that submits with the form, where Checkbox is the right element.
- Pair it with Toolbar for grouped editor actions, Tooltip to name icon-only buttons, and Kbd or KbdShortcut to show the key that triggers the same action elsewhere.


### Frequently asked questions

#### How do I build a React toggle button with a pressed state?

Use Toggle uncontrolled with defaultPressed, or controlled with pressed and onPressedChange. It renders a native button with aria-pressed. Children can be a function receiving the pressed state, so you can return a filled icon when pressed and an outline icon otherwise.

#### Does an icon-only Toggle need an accessible name?

Yes. iconOnly makes a square button for a lone icon, and it then needs an aria-label, such as Favorite, because there is no text to read. In forced colors a pressed toggle is filled with Highlight, so the state never depends on the tint alone.

#### How does ToggleGroup handle keyboard focus and values?

Tab enters the group once, the arrow keys move between toggles, and Enter or Space presses. Give each Toggle a value; the group holds an array of strings through value and onValueChange, or defaultValue. It has role="group", so name it with aria-label.

#### What is the difference between the glass and ghost variants?

The glass variant is one frosted glass-1 surface, meant for stand-alone toggles. Ghost has no surface until pressed, and suits toolbars and groups. Inside a ToggleGroup the toggles are ghost, so the group is a single backdrop surface. Reduced motion fades the tint without scaling.
